# 认证与授权 JWT

> 学完本节，你能回答：JWT 的三段各解决什么问题？为什么服务端要用签名而非加密来验证身份？刷新令牌如何与短有效期访问令牌配合？RBAC 的“校验点”应该放在哪一层？

## 从会话到令牌：为什么需要无状态

传统的服务端会话（session）把用户状态存在内存或 Redis，浏览器只持有一个 `session_id`。这在单机时代足够，但遇到多实例、跨域与移动端时会暴露三点痛点：服务端要有状态、跨服务要共享存储、每次请求都要查库。

JWT（JSON Web Token）的思路是把“已验证的身份断言”直接签发给客户端，服务端只做验签，不存会话。代价是令牌一旦签发就难以单条撤回，过期与轮转必须前置设计。MeetingToText 若要对外提供 `POST /api/tasks` 与 `GET /api/tasks/{id}`，用 JWT 即可让网关与业务服务各自验签，无需共享会话存储。

类比：session 像“寄存手牌”，每次取物都要回柜台查询；JWT 像“盖章门票”，检票员只验章，不查存根。

## JWT 的三段结构

JWT 形如 `header.payload.signature`，三段均为 Base64URL 编码的 JSON（头部与载荷）与签名：

- `header`：声明类型与签名算法，如 `{"alg":"HS256","typ":"JWT"}`。
- `payload`：载荷，承载断言（`sub` 用户、`exp` 过期、`iat` 签发、`roles` 角色等）。注意：载荷只是编码，不是加密，任何拿到令牌的人都能解码看到内容。
- `signature`：对 `base64url(header) + "." + base64url(payload)` 用密钥做 HMAC-SHA256（或 RS256 非对称），保证“内容未被篡改且由持有密钥的服务端签发”。

验证流程：按同样算法重算签名并做常时间比较；校验 `exp` / `nbf` / `iss` 等声明；通过后再做授权判断。

> **安全前提**：HS256 的密钥必须足够长且仅存于服务端（环境变量或密钥管理服务），绝不随代码提交或返回给前端。RS256 则把私钥留服务端、公钥分发给验签方，适合多服务验签的场景。

## 自签与验签：只用标准库

下面用 `hashlib` / `hmac` / `base64` / `json` 手工实现 JWT 的创建与校验，不依赖 PyJWT，便于看清每一步的字节流。

文件 `book/part4_现代工程进阶与交付/chapter10_健壮性与安全底线/demo_jwt_hs256.py`：

```{code-cell} ipython3
# 文件 book/part4_现代工程进阶与交付/chapter10_健壮性与安全底线/demo_jwt_hs256.py
import base64, json, hmac, hashlib, time

def b64url_encode(data: bytes) -> str:
    return base64.urlsafe_b64encode(data).decode().rstrip("=")

def b64url_decode(s: str) -> bytes:
    pad = "=" * (-len(s) % 4)
    return base64.urlsafe_b64decode(s + pad)

SECRET = b"dev-secret-change-in-prod-32bytes!!"

def jwt_encode(payload: dict, secret: bytes = SECRET) -> str:
    header = {"alg": "HS256", "typ": "JWT"}
    h_b64 = b64url_encode(json.dumps(header, separators=(",", ":"), ensure_ascii=False).encode())
    p_b64 = b64url_encode(json.dumps(payload, separators=(",", ":"), ensure_ascii=False).encode())
    signing_input = f"{h_b64}.{p_b64}".encode()
    sig = hmac.new(secret, signing_input, hashlib.sha256).digest()
    s_b64 = b64url_encode(sig)
    return f"{h_b64}.{p_b64}.{s_b64}"

def jwt_decode(token: str, secret: bytes = SECRET) -> dict:
    parts = token.split(".")
    if len(parts) != 3:
        raise ValueError("token 结构错误：需为 header.payload.signature")
    h_b64, p_b64, s_b64 = parts
    signing_input = f"{h_b64}.{p_b64}".encode()
    expected = hmac.new(secret, signing_input, hashlib.sha256).digest()
    actual = b64url_decode(s_b64)
    if not hmac.compare_digest(expected, actual):
        raise ValueError("签名校验失败：token 可能被篡改或密钥不匹配")
    payload = json.loads(b64url_decode(p_b64))
    # 过期校验（exp 为 Unix 秒）
    exp = payload.get("exp")
    if exp is not None and time.time() > exp:
        raise ValueError("token 已过期")
    return payload

# 签发：模拟 MeetingToText 登录后签发访问令牌
now = int(time.time())
payload = {"sub": "user42", "roles": ["user"], "iat": now, "exp": now + 3600, "iss": "m2t"}
token = jwt_encode(payload)
print("token:", token[:48] + "...")
# 验证：网关或业务服务验签
decoded = jwt_decode(token)
print("decoded sub:", decoded["sub"], "roles:", decoded["roles"])
# 篡改演示：改一个字符应触发签名失败
tampered = token[:-3] + "abc"
try:
    jwt_decode(tampered)
except ValueError as e:
    print("tamper detected:", e)
assert decoded["sub"] == "user42"
# 预期输出:
# token: eyJ...（三段 Base64URL，以两个点分隔）
# decoded sub: user42 roles: ['user']
# tamper detected: 签名校验失败：token 可能被篡改或密钥不匹配
```

> **跨平台提示**：`exp` / `iat` 统一用 UTC 的 Unix 秒（`time.time()`），避免本地时区差异导致“在 Windows 上刚好过期、在 Linux 上还没过期”的不一致。有效期校验应在服务端用 `time.time()` 做，不信任客户端时钟。

## 刷新令牌与 RBAC：让令牌既短命又可用

单一长有效期令牌一旦泄露，攻击窗口就很长。业界常用双令牌：

- **访问令牌（access token）**：短有效期（如 15 分钟），随每个请求携带，服务端只验签与过期。
- **刷新令牌（refresh token）**：长有效期（如 7 天），仅用于换取新的访问令牌，存储更谨慎（HttpOnly + Secure + SameSite 的 Cookie 或独立存储），可做轮转与撤回表。

流程：登录 → 返回 `access + refresh` → 访问令牌过期时，前端用 `refresh` 调 `/auth/refresh` 换新令牌 → 服务端校验 `refresh` 的签名与是否在撤回表，签发新 `access` 并可选轮转 `refresh`（旧的作废）。

RBAC（基于角色的访问控制）则在验签之后做：从 `payload.roles` 取角色，按路由要求的最小角色集合做包含判断。校验点应放在“业务边界”——FastAPI 的依赖（`Depends`）或网关中间件，而不是散落在每个 handler 内部。

文件 `book/part4_现代工程进阶与交付/chapter10_健壮性与安全底线/demo_jwt_refresh_rbac.py`：

```{code-cell} ipython3
# 文件 book/part4_现代工程进阶与交付/chapter10_健壮性与安全底线/demo_jwt_refresh_rbac.py
import time, json, hashlib, hmac, base64, secrets

# 复用上一节的 b64url 与 jwt 函数（自包含复制，避免跨 cell 隐式依赖）
import base64 as _b64, json as _json, hmac as _hmac, hashlib as _hashlib
def _b64e(b: bytes) -> str:
    return _b64.urlsafe_b64encode(b).decode().rstrip("=")
def _b64d(s: str) -> bytes:
    return _b64.urlsafe_b64decode(s + "=" * (-len(s) % 4))
SECRET2 = b"dev-secret-change-in-prod-32bytes!!"
def _encode(payload: dict) -> str:
    h = _b64e(_json.dumps({"alg":"HS256","typ":"JWT"}, separators=(",",":"), ensure_ascii=False).encode())
    p = _b64e(_json.dumps(payload, separators=(",",":"), ensure_ascii=False).encode())
    sig = _hmac.new(SECRET2, f"{h}.{p}".encode(), _hashlib.sha256).digest()
    return f"{h}.{p}.{_b64e(sig)}"
def _decode(token: str) -> dict:
    h,p,s = token.split(".")
    exp_sig = _hmac.new(SECRET2, f"{h}.{p}".encode(), _hashlib.sha256).digest()
    if not _hmac.compare_digest(exp_sig, _b64d(s)):
        raise ValueError("签名校验失败")
    obj = _json.loads(_b64d(p))
    if obj.get("exp") and time.time() > obj["exp"]:
        raise ValueError("token 已过期")
    return obj

# --- 刷新令牌轮转（简化版：内存集合模拟存储）---
revoked_refresh: set[str] = set()

def issue_pair(user_id: str, roles: list[str]) -> dict:
    now = int(time.time())
    access = _encode({"sub": user_id, "roles": roles, "iat": now, "exp": now + 900, "typ": "access", "iss": "m2t"})
    refresh = _encode({"sub": user_id, "roles": roles, "iat": now, "exp": now + 7*24*3600, "typ": "refresh", "jti": secrets.token_hex(8), "iss": "m2t"})
    return {"access": access, "refresh": refresh}

def refresh_access(refresh_token: str) -> str:
    data = _decode(refresh_token)
    if data.get("typ") != "refresh":
        raise ValueError("非刷新令牌")
    jti = data.get("jti", "")
    if jti in revoked_refresh:
        raise ValueError("刷新令牌已撤回")
    # 轮转：旧 refresh 作废
    revoked_refresh.add(jti)
    now = int(time.time())
    return _encode({"sub": data["sub"], "roles": data["roles"], "iat": now, "exp": now + 900, "typ": "access", "iss": "m2t"})

def require_roles(token: str, required: set[str]) -> bool:
    data = _decode(token)
    got = set(data.get("roles", []))
    return required.issubset(got)

# 演示：签发 -> 校验 RBAC -> 刷新轮转 -> 旧 refresh 不可复用
pair = issue_pair("user42", ["user", "editor"])
print("access ok (editor):", require_roles(pair["access"], {"editor"}))
print("access ok (admin):", require_roles(pair["access"], {"admin"}))
new_access = refresh_access(pair["refresh"])
print("refreshed:", _decode(new_access)["sub"] == "user42")
try:
    refresh_access(pair["refresh"])
except ValueError as e:
    print("replay blocked:", e)
assert require_roles(pair["access"], {"user"}) is True
assert require_roles(pair["access"], {"admin"}) is False
# 预期输出:
# access ok (editor): True
# access ok (admin): False
# refreshed: True
# replay blocked: 刷新令牌已撤回
```

> **工程启示**：JWT 的优势是“无状态验签”，代价是“撤回困难”。生产中常用短 `access` + 可撤回 `refresh` + 关键操作二次校验来平衡；权限判断用声明式的 RBAC 中间件收敛，避免在业务代码中散落 `if role ==`。
