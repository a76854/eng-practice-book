# FastAPI 路由设计

> 学完本节，你能回答：路径参数、查询参数与请求体参数在 HTTP 语义上有何分工？为什么 FastAPI 能用类型标注自动完成校验并生成 OpenAPI？MeetingToText 的 `POST /api/upload` 与 `GET /tasks/{id}` 背后，Pydantic 与依赖注入做了什么？

## 三类参数的语义分工

把 HTTP 请求比作快递单：路径（Path）是“收件地址”（定位资源）、查询参数（Query）是“备注选项”（筛选、分页、排序）、请求体（Body）是“包裹内容”（创建或更新的载荷）。混用会导致契约模糊：把分页塞进 Body 无法被缓存与收藏，把资源 ID 放进 Query 则失去可寻址性。

- **路径参数**：资源的身份标识。`GET /tasks/{task_id}` 中的 `task_id` 是资源的锚点，必填、唯一、出现在 URL 层级中。适合 `GET / PUT / DELETE` 的目标定位。
- **查询参数**：资源的修饰与集合操作。`GET /tasks?status=pending&limit=20&offset=0` 中的 `status / limit / offset` 是对集合的过滤与分页，可选、有默认值、可组合，天然适合被浏览器与 CDN 缓存。
- **请求体参数**：资源的载荷。`POST /tasks` 的 `{task_id, filename}` 或 `POST /api/upload` 的 `multipart/form-data` 是待创建资源的完整描述，适合 `POST / PUT / PATCH`。

FastAPI 的设计哲学是**用 Python 类型标注声明契约，让框架在边界自动校验**：路径与查询参数由函数签名推导，请求体由 `BaseModel` 推导，校验失败自动以 `422` 暴露，无需手写 `if`。

## Pydantic 校验：把“口头约定”变成“书面合同”

`Field` 与类型标注共同构成声明式校验：`min_length / max_length / ge / le / pattern / description` 等约束在**进入业务层之前**即被检查，错误以结构化的 `422` 响应返回，包含字段路径与错误原因。这与 [第3章的分层思想](../chapter03_后端开发到底是什么/3.5_分层架构落地.md) 一致：Controller 层做“形状校验”，Service 层做“业务规则校验”，二者分层可测。

依赖注入（`Depends`）则让**可复用的校验与上下文**（如分页参数对象、鉴权、任务存在性检查）从路由函数中抽离，保持路由“薄而可测”。

> **跨平台提示**：路由设计本身与平台无关；若示例涉及文件上传的本地落盘，统一用 `pathlib.Path` 处理分隔符（`/` 在 macOS / Linux，`\` 在 Windows，由 `Path` 自动适配）。

## 可运行示例：路径/查询/请求体校验与依赖注入

文件 `book/part2_后端开发全景与核心基石/chapter04_HTTP与RESTful架构/demo_routing.py`（演示三类参数校验与 `Depends`，`TestClient` 本地验证，无网络）：

```{code-cell} ipython3
# 文件 book/part2_后端开发全景与核心基石/chapter04_HTTP与RESTful架构/demo_routing.py
import tempfile, pathlib
from typing import Annotated

from fastapi import FastAPI, Depends, Path, Query, HTTPException, status
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field
from m2t.store import TaskStore

tmpdir = tempfile.TemporaryDirectory()
db_path = pathlib.Path(tmpdir.name) / "routing.db"
store = TaskStore(db_path)

# --- 契约：请求体模型（Pydantic 校验） ---
class TaskCreateIn(BaseModel):
    task_id: str = Field(min_length=1, max_length=64, description="任务 ID，1–64 字符")
    filename: str = Field(min_length=1, description="文件名")
    priority: int = Field(default=0, ge=0, le=10, description="优先级 0–10，默认 0")

class TaskOut(BaseModel):
    id: str
    filename: str
    status: str
    priority: int = 0

# --- 依赖：分页参数（可复用、可测试） ---
class PaginationParams(BaseModel):
    limit: int = Field(default=20, ge=1, le=100)
    offset: int = Field(default=0, ge=0)

def pagination(
    limit: Annotated[int, Query(ge=1, le=100, description="每页数量 1–100")] = 20,
    offset: Annotated[int, Query(ge=0, description="偏移量 >=0")] = 0,
) -> PaginationParams:
    return PaginationParams(limit=limit, offset=offset)

# --- 依赖：任务存在性检查（演示依赖注入的“守门”作用） ---
def require_task_exists(task_id: Annotated[str, Path(min_length=1, description="任务 ID")]) -> dict:
    row = store.get(task_id)
    if row is None:
        raise HTTPException(status_code=404, detail=f"task {task_id} not found")
    return row

app = FastAPI(title="Routing Demo")

@app.post("/tasks", response_model=TaskOut, status_code=status.HTTP_201_CREATED)
def create_task(payload: TaskCreateIn):
    if store.get(payload.task_id) is not None:
        raise HTTPException(status_code=409, detail="already exists")
    store.create(payload.task_id, payload.filename)
    row = store.get(payload.task_id)
    assert row is not None
    # 教学简化：priority 仅在响应中回显，未持久化到 TaskStore
    return TaskOut(id=row["id"], filename=row["filename"], status=row["status"], priority=payload.priority)

@app.get("/tasks/{task_id}", response_model=TaskOut)
def get_task(task: Annotated[dict, Depends(require_task_exists)]):
    # 通过 Depends 注入已校验的任务行，路由函数无需再查库与判空
    return TaskOut(id=task["id"], filename=task["filename"], status=task["status"])

@app.get("/tasks", response_model=list[TaskOut])
def list_tasks(p: Annotated[PaginationParams, Depends(pagination)], status_filter: Annotated[str | None, Query(description="按状态过滤")] = None):
    # 查询参数：分页 + 可选过滤（演示 Query 的“修饰”语义）
    rows = store.list_tasks(limit=100)
    if status_filter is not None:
        rows = [r for r in rows if r["status"] == status_filter]
    # 手动分页（教学简化，生产中应在 SQL 层分页）
    sliced = rows[p.offset : p.offset + p.limit]
    return [TaskOut(id=r["id"], filename=r["filename"], status=r["status"]) for r in sliced]

@app.get("/search")
def search(q: Annotated[str, Query(min_length=1, description="关键词")], limit: Annotated[int, Query(ge=1, le=50)] = 10):
    # 查询参数的校验：空关键词直接 422，无需进入业务逻辑
    all_rows = store.list_tasks(limit=100)
    matched = [r for r in all_rows if q in r["filename"]]
    return {"query": q, "count": len(matched[:limit]), "items": matched[:limit]}

# --- 本地验证：用 TestClient 演示三类参数的校验与注入 ---
client = TestClient(app)

# 1) 请求体校验：正常创建
r1 = client.post("/tasks", json={"task_id": "r1", "filename": "meeting.wav", "priority": 5})
print("create r1:", r1.status_code, r1.json())
assert r1.status_code == 201
assert r1.json()["priority"] == 5

# 2) 请求体校验失败 → 422（priority 超限，未进入业务层）
r2 = client.post("/tasks", json={"task_id": "r2", "filename": "x.wav", "priority": 99})
print("priority overflow:", r2.status_code, r2.json()["detail"][0]["type"])
assert r2.status_code == 422

# 3) 请求体校验失败 → 422（空 task_id）
r3 = client.post("/tasks", json={"task_id": "", "filename": "x.wav"})
print("empty task_id:", r3.status_code)
assert r3.status_code == 422

# 4) 路径参数 + Depends：存在 → 200；不存在 → 404
r4 = client.get("/tasks/r1")
print("get r1:", r4.json())
assert r4.status_code == 200
r5 = client.get("/tasks/missing_xyz")
print("get missing:", r5.status_code, r5.json()["detail"])
assert r5.status_code == 404

# 5) 查询参数：分页（limit/offset）
# 先创建若干任务
for i in range(5):
    client.post("/tasks", json={"task_id": f"batch{i}", "filename": f"file{i}.wav"})
r6 = client.get("/tasks?limit=2&offset=1")
print("list paginated:", len(r6.json()), r6.json()[0]["id"])
assert len(r6.json()) == 2
# 6) 查询参数校验：limit 超限 → 422
r7 = client.get("/tasks?limit=999")
print("limit overflow:", r7.status_code)
assert r7.status_code == 422

# 7) 查询参数：搜索（q 为必填，空则 422）
r8 = client.get("/search?q=file&limit=2")
print("search file:", r8.json()["count"], r8.json()["query"])
assert r8.json()["query"] == "file"
r9 = client.get("/search?q=")
print("empty q:", r9.status_code)
assert r9.status_code == 422

# 8) 业务层冲突：重复创建 → 409（Pydantic 校验通过后，业务规则校验）
r10 = client.post("/tasks", json={"task_id": "r1", "filename": "dup.wav"})
print("duplicate r1:", r10.status_code)
assert r10.status_code == 409

tmpdir.cleanup()
print("路由校验通过：路径/查询/请求体 + Depends 各司其职")
# 预期输出:
# create r1: 201 {'id': 'r1', ...}
# priority overflow: 422 ...
# empty task_id: 422
# get r1: {'id': 'r1', ...}
# get missing: 404 ...
# list paginated: 2 ...
# limit overflow: 422
# search file: 2 file
# empty q: 422
# duplicate r1: 409
# 路由校验通过：路径/查询/请求体 + Depends 各司其职
```
