# 与外部世界的集成

> **本章学习目标**
> - 能够说清文件为什么不进数据库不落磁盘，并用 bucket 加 key、预签名 URL 与前端直传实现文件的存取链路
> - 能够用旁路缓存给高频读加速，并说清穿透击穿雪崩三个局面的成因与解法
> - 能够用生产者加 Broker 加消费者解释长时任务的异步化，并用幂等键与发件箱算清重复与丢失两笔账
> - 能够用真实接口完成大模型的普通调用与流式调用，并说清 key 放服务端、结构化输出与成本账
> - 能够用函数调用让模型获取它不知道的信息，并说清工具参数为什么也要校验

> **为什么需要掌握本章**
> 后端的很多能力来自外部：文件要存到对象存储，热数据要放进缓存，慢活要交给队列，摘要要请大模型完成。外部能力是杠杆，也带来体积、延迟、重复、账单这些新风险。本章以文档查询应用为贯穿例子，原文存对象存储，热搜结果进 Redis，解析建索引走 Kafka，摘要调大模型，四节把四种外部能力一次配齐。

> **预计理论学时**：3学时

本章四节沿着一次文档上传的旅程展开：文件落到对象存储，热搜结果被 Redis 记住，解析建索引在 Kafka 里排队，摘要由大模型生成。动手练习交给实验指导书。章内结构如下：

- [对象存储](object_storage.md)：文件放哪，bucket 与 key、前端直传、预签名 URL 与断点续传
- [缓存与 Redis](redis_cache.md)：查得快，旁路缓存、穿透击穿雪崩、会话限流锁的归属
- [消息队列与 Kafka](kafka_queue.md)：做得慢，生产消费三件、幂等去重、发件箱与定时
- [大模型调用方法](llm_calling.md)：答得聪明，普通调用、流式响应、结构化输出、函数调用与两笔账
