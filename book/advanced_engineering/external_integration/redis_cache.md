# 缓存与 Redis

学完本节，你能回答：

- 数据库扛不住什么样的读，什么样的结果值得缓存
- 旁路缓存下，读与写的顺序为什么不能反
- 缓存穿透、击穿、雪崩各是什么局面，分别怎么解
- 会话、限流、分布式锁，为什么也落在 Redis 身上

> 常用的电话号码贴在冰箱上，翻电话本太慢。缓存就是冰箱贴，常用的抄一份放手边，过期撕掉重抄。冰箱贴再方便，也替代不了电话本，丢了还能重抄是缓存的前提。

上一节解决了文件放哪，本节解决查得快。本节是第二个帮手，管热数据放手边。数据库保正确，Redis 保快。学完本节，什么样的结果值得缓存、缓存什么时候算过期，都有章法。注意本节只讲缓存这一件事，会话、限流、锁只给归属，不展开。

## 什么值得缓存

数据库扛不住的是高频重复读。文档搜索里，同一个关键词一分钟被搜上百次，每次都走 SQL 解析、走索引、回表，慢且浪费。搜索结果读多写少，丢了能重查，有时效要求，这些性质决定了它值得缓存。

判断值不值得缓存，看三条。读远多于写，缓存才有命中率。丢了能重建，缓存才敢设过期。允许短暂不一致，缓存才有存在空间。三条全中，放手边。三条中一条都不中，老实走数据库。

## 旁路缓存

应用侧缓存最常用的姿势叫旁路，DB 永远是真相，缓存只是手边的抄件。读时先看手边，没有再查 DB，查到回填一份：

```python
# 读：先看缓存，没有再查库，查到回填并设过期（展示代码）
cached = redis.get(f"search:{q}")
if cached is None:
    results = db.search(q)
    redis.setex(f"search:{q}", 300, json.dumps(results))
    return results
return json.loads(cached)
```

写时顺序不能反，先写 DB，再删缓存。先删缓存后写 DB，中间来一个读请求，会把旧数据回填，脏数据就此住下。先写 DB 后删缓存，脏数据的窗口只剩删缓存失败那一种，用重试兜住即可。

## 缓存三坑

缓存上线后，三个经典局面迟早会碰到，各有解法：

| 局面 | 长什么样 | 怎么解 |
| --- | --- | --- |
| 穿透 | 查不存在的东西，每次都打穿缓存直达 DB，恶意构造直接打垮 DB | 空结果也缓存一份，过期设短；或在入口校验参数合法性 |
| 击穿 | 某个热点 key 恰好过期，瞬间上百个请求同时回源，DB 被冲垮 | 热点 key 永不过期加后台刷新，或加互斥锁只放一个请求回源 |
| 雪崩 | 大批 key 同时过期，或 Redis 宕机，所有请求一起压向 DB | 过期时间加随机抖动；Redis 高可用部署；DB 侧保留限流兜底 |

三坑的共同点是请求绕过缓存直达 DB，解法的共同点是别让"同时回源"发生。文档搜索里，空关键词的结果缓存一份短过期的空列表，就是防穿透的日常操作。

## 过期时间

过期时间不能拍脑袋，按数据变得多快定：

| 数据 | 过期 | 理由 |
| --- | --- | --- |
| 搜索结果 | 5 分钟 | 别处新增文档，晚上架几分钟没人投诉 |
| 会话 | 30 分钟 | 人走茶凉，过期即登出 |
| 字典配置 | 1 天 | 几乎不变，变了等一天也能接受 |

同一批 key 别设同一个过期，雪崩就是这么来的。过期时间加随机抖动，300 秒上下浮动几十秒，回源就被打散了。拿不准时先设短，缓存短了只是多查几次库，设长了可是脏数据住下。

## 内存满了怎么办

Redis 存在内存里，内存会满。满了不处理，写操作全报错。办法是设上限加淘汰策略：

| 策略 | 含义 | 适用 |
| --- | --- | --- |
| noeviction | 满了直接报错 | 数据一条不能丢，且有人值班 |
| allkeys-lru | 全体里踢最久没用的 | 缓存场景默认选这个 |
| volatile-ttl | 有过期的里踢快到期的 | 冷热分明，且都设了过期 |

上限看机器内存留余量，重要数据除了设过期，还要接受"可能被淘汰"这件事，真金白银的数据回 DB 重建。缓存满了不是事故，没有上限才是。

## 会话、限流与锁

Redis 身上还挂着三件和缓存无关的活，知道归属即可。会话放 Redis，登录态跨多机共享，重启应用不掉线。计数器做限流，同一 key 一分钟加几次超了就拒，简单有效。分布式锁，多机抢同一资源时先拿锁再办事。每一件都值得单开一节，本书点到为止，用到时知道该找谁。

## 本节小结

- 高频重复读走数据库又慢又浪费，读多写少、可重建、允许短暂不一致的结果值得放手边。
- 读先看缓存再查库并回填，写先写库再删缓存，顺序反了会住下脏数据。
- 穿透击穿雪崩都是别让请求同时打到 DB，过期按变化定，同一批加随机抖动防雪崩。
- 内存设上限，满了按策略淘汰，重要数据接受可淘汰，真东西回 DB 重建。
- 会话、限流、分布式锁也归 Redis 管，本书只给归属，用到时再深挖。
