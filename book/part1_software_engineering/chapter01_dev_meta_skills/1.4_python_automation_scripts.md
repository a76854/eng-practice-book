# Python 自动化脚本

> 工程中的重复劳动是“人肉 CI”——易错、难复现、无法审计。Python 脚本的价值在于把“操作”变成“代码”，把“口头约定”变成“可执行契约”。

## 何时用 Python 代替 Shell

- **可移植**：Shell 脚本在不同环境（本机、CI、服务器）间常有细微差异，Python 的 `pathlib` / `shutil` / `subprocess` 行为一致、更易复现。
- **错误处理**：Shell 的 `set -e` 粒度粗，Python 的异常与类型系统能精确区分“文件不存在”与“命令失败”。
- **可测试**：函数可被 `pytest` 直接调用，而 Shell 函数难以单元测试。

经验法则：**超过 10 行或需要分支、循环、参数校验的自动化，一律用 Python**。

## 三件套：`subprocess`、`shutil`、`argparse` / `click`

| 模块 | 职责 | 典型用法 |
|---|---|---|
| `subprocess` | 进程调用 | `run(["git", "status"], capture_output=True)`；避免 `shell=True` |
| `shutil` | 文件系统高级操作 | `copytree`、`rmtree`、`which`、`disk_usage` |
| `argparse` / `click` | 命令行封装 | 参数解析、校验、帮助信息生成；`argparse` 零依赖，`click` 更适合复杂 CLI |

通用示例：一个典型的 `cli.py` 会用 `argparse` 封装 `serve` / `process` 等子命令，并支持 `APP_*` 环境变量覆盖；`Makefile` 仅作为薄封装，实际逻辑由 Python 脚本完成，以保持“可移植的自动化”。

```bash
# 查看通用 CLI 帮助（以教学仓示例为准）
python -m mymodule.cli --help
python -m mymodule.cli serve --help

# 常用调用形态
python -m mymodule.cli serve --port 8000 --reload
```

## `subprocess` 的正确姿势

```bash
# 错误：依赖 shell 解析，易受注入与平台差异影响
python -c "import subprocess; subprocess.run('echo hello | grep h', shell=True)"

# 正确：参数列表 + 管道显式构造
python -c "import subprocess, sys; subprocess.run([sys.executable, '-c', 'print(1)'])"
```

要点：

- 永远优先 `run([...], capture_output=True, text=True, check=True)`。
- 需要管道时用 `Popen` 显式连接 `stdout` → `stdin`，而非 `shell=True` 中的 `|`。
- 超时用 `timeout` 参数，避免子进程挂死。

## `shutil`：可移植的文件操作

`shutil` 屏蔽了 `cp` / `rm -rf` 的平台差异：

```bash
# Shell 写法
cp -r data/uploads data/backup

# Python 写法（更易校验与回滚）
python -c "import shutil; shutil.copytree('data/uploads', 'data/backup')"
```

## `argparse` vs `click`

- `argparse`：标准库、无依赖、适合单文件脚本与课程项目。
- `click`：装饰器语法、自动生成帮助、支持子命令嵌套，适合多子命令的复杂 CLI（但需额外依赖）。

本章示例统一用 `argparse` 以保持零依赖；学有余力可对照 [click 文档](https://click.palletsprojects.com/) 将示例改写为装饰器风格。

## 可运行示例：自动化脚本

示例（文件整理 + 子进程校验）：

```{code-cell} ipython3
import pathlib, shutil, subprocess, sys, tempfile, argparse

def organize_uploads(src: pathlib.Path, dst: pathlib.Path) -> dict:
    """通用上传归档示例：按扩展名分桶，并校验结果。"""
    dst.mkdir(parents=True, exist_ok=True)
    # 1) 用 shutil 完成文件操作（可移植）
    buckets = {}
    for p in src.iterdir():
        if p.is_file():
            ext = p.suffix.lower().lstrip(".") or "noext"
            bucket = dst / ext
            bucket.mkdir(exist_ok=True)
            shutil.copy2(p, bucket / p.name)
            buckets[ext] = buckets.get(ext, 0) + 1
    # 2) 用 subprocess 校验（复刻 CLI 中的健康检查）
    # 用 Python 子进程列目录，避免依赖 ls/dir
    result = subprocess.run(
        [sys.executable, "-c", f"import pathlib; print(list(pathlib.Path(r'{dst}').rglob('*')))" ],
        capture_output=True, text=True, check=True
    )
    print("buckets:", buckets)
    print("subprocess check ok:", "wav" in result.stdout)
    return buckets

with tempfile.TemporaryDirectory() as td:
    src = pathlib.Path(td) / "uploads"
    dst = pathlib.Path(td) / "archive"
    src.mkdir()
    for name in ["a.wav", "b.mp3", "c.wav", "notes.txt"]:
        (src / name).write_text("dummy")
    buckets = organize_uploads(src, dst)
    assert buckets == {"wav": 2, "mp3": 1, "txt": 1}
    assert (dst / "wav" / "a.wav").exists()
# 预期输出:
# buckets: {'wav': 2, 'mp3': 1, 'txt': 1}
# subprocess check ok: True
```

示例（`argparse` 命令行封装）：

```{code-cell} ipython3
import argparse, pathlib, tempfile, sys

def build_parser() -> argparse.ArgumentParser:
    p = argparse.ArgumentParser(description="通用归档 CLI（演示）")
    p.add_argument("--src", required=True, help="源目录")
    p.add_argument("--dst", required=True, help="目标目录")
    p.add_argument("--dry-run", action="store_true", help="仅打印将执行的操作，不实际复制")
    p.add_argument("--ext", default="wav", help="仅处理指定扩展名（默认 wav）")
    return p

# 模拟命令行调用：python demo_cli_argparse.py --src ./uploads --dst ./archive --ext wav --dry-run
parser = build_parser()
args = parser.parse_args(["--src", "data/uploads", "--dst", "data/archive", "--ext", "wav", "--dry-run"])
print("src:", args.src)
print("dst:", args.dst)
print("ext:", args.ext)
print("dry_run:", args.dry_run)
# 参数校验：路径分隔符由 pathlib 统一处理
src_path = pathlib.Path(args.src)
dst_path = pathlib.Path(args.dst)
print("src Path:", src_path)
print("dst Path:", dst_path)
assert args.ext == "wav"
assert args.dry_run is True

# 演示 dry-run 分支：不碰文件系统，仅打印
if args.dry_run:
    print(f"[dry-run] would copy *.{args.ext} from {src_path} to {dst_path}")
# 预期输出:
# src: data/uploads
# dst: data/archive
# ext: wav
# dry_run: True
# src Path: data/uploads
# dst Path: data/archive
# [dry-run] would copy *.wav from data/uploads to data/archive
```

示例（用教学包 `m2t` 演示“脚本 + 业务”结合的通用模式）：

```{code-cell} ipython3
import tempfile, pathlib
from m2t.export import export

# 模拟 CLI 的导出子命令：给定任务，导出 txt / srt / md
task = {
    "id": "demo123",
    "filename": "weekly.wav",
    "result": {
        "duration": 62,
        "segments": [
            {"speaker": "说话人1", "text": "大家好，今天讨论版本计划", "start": 0.5, "end": 3.2},
            {"speaker": "说话人2", "text": "我建议先上转写功能", "start": 3.5, "end": 6.0},
        ],
    },
    "minutes": "## 决策\n- 优先实现转写",
}

for fmt in ["txt", "srt", "md"]:
    out = export(task, fmt)
    # 仅打印首行，验证分发正确
    first_line = out.splitlines()[0] if out else ""
    print(f"{fmt}: {first_line[:40]}")
    assert len(out) > 0
# 预期输出示例:
# txt: [说话人1] 大家好，今天讨论版本计划
# srt: 1
# md: # 会议转录 — weekly.wav
```

> **工程建议**：把脚本的“参数解析”与“业务逻辑”分离为两个函数（`build_parser` 与 `organize_uploads`），前者负责校验与帮助信息，后者可被 `pytest` 直接测试。更多测试策略见 [第2章 2.3 测试的工程思维](../chapter02_code_quality/2.3_testing_engineering_mindset.md)。

> **教学项目 — MeetingToText**：在 MeetingToText 中，`cli.py` 用 `argparse` 封装 `serve` / `transcribe` 等子命令并支持 `MTT_*` 环境变量覆盖，`Makefile` 仅做薄封装，实际逻辑由 Python 与 `uvicorn` 承担。`m2t.export` 的多格式导出（`txt` / `srt` / `md`）则展示了“参数解析与纯函数业务分离”后，脚本与库代码如何各自可测试。
