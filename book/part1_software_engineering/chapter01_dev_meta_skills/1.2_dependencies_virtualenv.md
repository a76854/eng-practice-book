# 依赖与虚拟环境

> 如果把项目比作一间厨房，依赖就是食材清单，虚拟环境就是独立的灶台——没有灶台隔离，再好的菜谱也会因“共用调料”而串味。

## 为什么需要隔离

Python 的导入机制本质是**在 `sys.path` 上按序搜索**。若所有项目共用同一个全局解释器：

- A 项目需要 `numpy==1.26`，B 项目需要 `numpy==2.0`，全局只能装一个版本，必有一方失败。
- `pip install` 时可能因权限或系统包冲突把系统 Python 弄脏，回退困难。
- “在我机器上能跑”往往是因为全局环境恰好有某依赖，而 CI 或同事机器没有。

虚拟环境要解决的正是**依赖的确定性与隔离性**：每个项目拥有独立的解释器、独立的 `site-packages`、独立的 `PATH`。

## 三种主流方案：venv / conda / uv

| 方案 | 定位 | 优势 | 代价与适用场景 |
|---|---|---|---|
| `venv`（标准库） | 轻量隔离 | 零额外安装、与 `pip` 原生配合、心智负担最小 | 不管理 Python 版本本身；适合已装好 Python 的课程与大多数后端项目 |
| `conda` / `mamba` | 环境 + 非 Python 依赖 | 能管理 Python 版本与系统库（如 `ffmpeg`、`cuda`） | 体积大、解决器慢；适合数据科学、音视频等含原生依赖的项目 |
| `uv` | 极速工具链 | Rust 编写，解析与安装比 `pip` 快 10–100 倍；兼容 `venv` 与 `pyproject.toml` | 新工具链，需团队统一；适合追求 CI 速度与统一锁文件的团队 |

> **中立性说明**：没有银弹。教学仓 `eng-practice-book` 默认使用 `venv`（`.venv` 目录）以保持“标准库即可复现”；MeetingToText 的音视频依赖在文档中提供 `conda` 作为可选方案；`uv` 可作为 `pip` 的透明替代（`uv pip install -e .`）。

选型决策可简化为：

- 只需 Python 包隔离 → `venv` + `pip`（或 `uv pip` 加速）。
- 需要管理 Python 版本或原生库 → `conda`。
- 追求速度与锁文件一致性 → `uv` + `uv.lock`。

## 虚拟环境隔离的本质

创建虚拟环境时，Python 做了三件关键事：

1. **复制或链接解释器**：在 `.venv/bin/python` 放置一个指向原解释器的副本或符号链接。
2. **独立的 `site-packages`**：`.venv/lib/python3.12/site-packages` 成为该环境独有的第三方包目录。
3. **改写 `sys.prefix` 与 `PATH`**：激活后 `sys.prefix` 指向虚拟环境根，`PATH` 首位加入 `.venv/bin`，使得 `python` 与 `pip` 优先解析到环境内。

未激活时，`sys.prefix` 与 `sys.base_prefix` 相等；激活后二者分离——这正是判断“是否在虚拟环境中”的可靠信号。

```bash
# 创建与激活
python -m venv .venv
source .venv/bin/activate

# 验证：查看解释器路径
which python

# 退出虚拟环境
deactivate
```

## 可运行示例：用 Python 揭示隔离原理

文件 `book/part1_software_engineering/chapter01_dev_meta_skills/demo_venv_isolation.py`：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter01_dev_meta_skills/demo_venv_isolation.py
import sys, pathlib, sysconfig

print("sys.prefix:", sys.prefix)
print("sys.base_prefix:", sys.base_prefix)
print("in venv:", sys.prefix != sys.base_prefix)
print("site-packages:", sysconfig.get_paths()["purelib"])
# 列出当前环境可导入的顶层包数量（仅作隔离体感，不依赖具体包）
import pkgutil
top_level = [m.name for m in pkgutil.iter_modules()]
print("top-level modules count:", len(top_level))
# 预期输出示例（路径因机器而异，但逻辑一致）:
# sys.prefix: /home/.../eng-practice-book/.venv
# sys.base_prefix: /opt/miniconda3 或 /usr
# in venv: True
# site-packages: .../.venv/lib/python3.12/site-packages
# top-level modules count: 200+
```

> **如何解读输出**：若 `in venv` 为 `True`，说明当前解释器已隔离；`purelib` 路径应指向 `.venv` 内部。若为 `False`，请检查是否按上表正确激活（常见错误：在 VS Code 中终端与编辑器使用了不同解释器）。

文件 `book/part1_software_engineering/chapter01_dev_meta_skills/demo_pip_freeze.py`（依赖可复现性：从 `pyproject.toml` 推导安装清单）：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter01_dev_meta_skills/demo_pip_freeze.py
import pathlib, importlib.metadata

# 读取已安装的 m2t 版本，模拟 pip freeze 的可复现思想
dist = importlib.metadata.version("m2t")
print("installed m2t version:", dist)

# 模拟生成最小可复现依赖（真实项目应提交 requirements.lock 或 uv.lock）
deps = ["numpy>=1.26", "soundfile>=0.12"]
for d in deps:
    # importlib.metadata 可查询已安装版本的精确号
    pkg = d.split(">=")[0].split("==")[0]
    try:
        v = importlib.metadata.version(pkg)
        print(f"{pkg}=={v}  # 来自 {d}")
    except importlib.metadata.PackageNotFoundError:
        print(f"{pkg} 未安装（在 CI 中会按 {d} 安装）")
# 预期输出:
# installed m2t version: 0.1.0
# numpy==1.x.x  # 来自 numpy>=1.26
# soundfile==0.12.x  # 来自 soundfile>=0.12
```

> **可复现性建议**：课程项目至少做到 `pip freeze > requirements.lock` 并提交锁文件；团队项目推荐 `uv` 的 `uv.lock` 或 `pip-tools` 的 `requirements.txt --generate-hashes`，确保“同一提交、同一依赖图”。更多自动化校验见 [1.4 Python 自动化脚本](1.4_python_automation_scripts.md)。

文件 `book/part1_software_engineering/chapter01_dev_meta_skills/demo_m2t_store_isolation.py`（用教学包演示“环境隔离不影响业务逻辑可测试性”）：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter01_dev_meta_skills/demo_m2t_store_isolation.py
import tempfile, pathlib
from m2t.store import TaskStore

with tempfile.TemporaryDirectory() as td:
    db = pathlib.Path(td) / "demo.db"
    store = TaskStore(db)
    store.create("demo1", "meeting.wav")
    row = store.get("demo1")
    print("row:", row["filename"], row["status"])
    store.update("demo1", status="done", full_text="hello world")
    print("after:", store.get("demo1")["status"])
    assert store.get("demo1")["full_text"] == "hello world"
# 预期输出:
# row: meeting.wav pending
# after: done
```
