# Pytest 进阶

> 如果说 [2.3 测试的工程思维](2.3_testing_engineering_mindset.md) 解决了“测什么、怎么组织断言”，本节解决“如何让测试在真实工程中跑得快、跑得稳、易维护”。

## Fixture：把 Arrange 从用例中抽离

`pytest` 的 `fixture` 是“可复用的 Arrange”。相比在每个用例中手写 `tempfile` + `TaskStore`，`fixture` 让准备逻辑集中、可组合、可按作用域复用：

- **作用域（scope）**：`function`（默认，每用例新建）、`module`（每文件复用一次）、`session`（全程复用一次）。选择依据是“资源成本 × 隔离需求”。
- **工厂 fixture**：`fixture` 返回工厂函数，适配“每用例不同参数”的场景。
- **自动清理**：`yield` 之后的 `teardown`（如删除临时数据库）由 `pytest` 保证执行。

```bash
# 运行 pytest
.venv/bin/pytest -q
.venv/bin/pytest -q --fixtures  # 查看可用 fixture
```

> **环境约定**：本书面向 Linux，`fixture` 中涉及文件与路径的，一律用 `tmp_path`（`pytest` 内置）或 `tempfile.TemporaryDirectory()` + `pathlib.Path`，避免平台相关硬编码。

## Mocking：隔离外部依赖

MeetingToText 的外部依赖（ASR 模型、LLM 网络、文件系统、时间）在测试中是不稳定因素。`unittest.mock` 提供两类替身：

- **Fake / Stub**：用极简实现替代真实依赖（如 `fake_model.generate` 返回固定 `result`）。
- **Mock / Spy**：记录调用并可断言（如 `MagicMock` 记录 `called`、`call_count`、`assert_called_with`）。

隔离的边界应选在**“不稳定或昂贵”的调用点**，而非所有函数。典型应用：

| 依赖 | 隔离方式 | 示例 |
|---|---|---|
| `funasr.AutoModel.generate` | 传入 `fake_model` 或 `patch` | `transcribe(audio, model=fake)` |
| `openai.OpenAI.chat.completions.create` | `patch` + `MagicMock` | `LLMClient` 的 `client` 属性 |
| 文件读取 `sf.read` | `patch("m2t.audio.sf.read")` | 返回合成 `np.ndarray` |
| 时间 `datetime.now` | `patch` 固定返回值 | 断言 `created_at` 可预期 |

> **中立性说明**：Mock 是手段，不是目的。过度 mock 会让测试与实现紧耦合，失去回归价值。优先测试可观测行为（返回值、状态、抛错），而非内部调用次数；仅在“不 mock 就无法 hermetic 运行”时引入替身。

## 可运行示例：Fixture 作用域与 Mock

示例（用 Python 复刻 `fixture` 的作用域思想，无需 `pytest` 进程）：

```{code-cell} ipython3
import tempfile, pathlib
from m2t.store import TaskStore

# 复刻 pytest fixture 的核心思想：可复用的 Arrange 工厂
def make_store_factory(tmp_dir: pathlib.Path):
    """返回一个工厂，每次调用新建独立 TaskStore（模拟 function scope）。"""
    counter = 0
    def factory(suffix: str = "") -> TaskStore:
        nonlocal counter
        counter += 1
        db = tmp_dir / f"scope_{counter}{suffix}.db"
        return TaskStore(db)
    return factory

with tempfile.TemporaryDirectory() as td:
    root = pathlib.Path(td)

    # function scope：每用例独立数据库
    factory = make_store_factory(root)
    s1 = factory()
    s1.create("a1", "a.wav")
    s2 = factory()
    s2.create("b1", "b.wav")
    # s1 与 s2 隔离，互不影响
    assert s1.get("a1") is not None
    assert s1.get("b1") is None
    assert s2.get("b1") is not None
    print("function scope: 每调用一次工厂 -> 独立 DB，隔离通过")

    # session scope：全程复用同一数据库（适合只读或昂贵资源的演示）
    session_store = TaskStore(root / "session.db")
    session_store.create("s1", "session.wav")
    # 多个“用例”共享同一 store 实例
    assert session_store.get("s1")["filename"] == "session.wav"
    session_store.create("s2", "session2.wav")
    assert len(session_store.list_tasks()) == 2
    print("session scope: 单例复用，状态累积通过")
# 预期输出:
# function scope: 每调用一次工厂 -> 独立 DB，隔离通过
# session scope: 单例复用，状态累积通过
```

示例（`unittest.mock` 隔离 ASR 与 LLM）：

```{code-cell} ipython3
from unittest.mock import MagicMock, patch, call
from m2t.asr import transcribe, normalize_result
from m2t.llm import LLMClient, map_llm_error

# 1) Mock ASR：用 fake_model 替代真实 FunASR，避免 torch/funasr 依赖
class FakeModel:
    def generate(self, input, cache, language, use_itn):
        # 返回 sentence_info 形状，由 normalize_result 归一
        return [{"sentence_info": [
            {"text": "模拟转写", "start": 0, "end": 1000, "spk": 0}
        ]}]

segs = transcribe("fake.wav", model=FakeModel())
print("mock ASR segs:", segs)
assert segs[0]["text"] == "模拟转写"
assert segs[0]["speaker"] == "说话人1"
print("Mock ASR 通过：无需真实模型即可验证归一逻辑")

# 2) Mock LLM：用 patch.object 隔离 OpenAI 客户端，验证消息构造
mock_client = MagicMock()
fake_resp = MagicMock()
fake_resp.choices = [MagicMock(message=MagicMock(content="会议纪要：3 点"))]
mock_client.chat.completions.create.return_value = fake_resp

# 通过 patch.object 直接替换 LLMClient.client 属性，避免依赖 openai 导入路径
with patch.object(LLMClient, "client", mock_client):
    c = LLMClient(base_url="https://fake", api_key="sk-test", model="fake-model")
    out = c.generate(system_prompt="你是纪要助手", user_message="转写文本...")
    print("mock LLM out:", out)
    assert out == "会议纪要：3 点"
    mock_client.chat.completions.create.assert_called_once()
    args, kwargs = mock_client.chat.completions.create.call_args
    assert kwargs["model"] == "fake-model"
    assert kwargs["messages"][0]["role"] == "system"
    print("Mock LLM 通过：消息形状可断言，无需网络")

# 3) 错误映射：map_llm_error 绝不透传原始异常文本
try:
    from openai import RateLimitError
    # 构造一个限流异常（需 response/request 桩）
    fake_exc = RateLimitError("too many", response=MagicMock(), body=None)
    msg = map_llm_error(fake_exc)
    print("mapped RateLimit:", msg)
    assert "频繁" in msg or "稍后" in msg
    assert "too many" not in msg  # 脱敏：不含原始文本
    print("错误映射脱敏通过")
except ImportError:
    # 未安装 openai 时走兜底分支
    msg = map_llm_error(RuntimeError("fake"))
    print("mapped fallback:", msg)
    assert "LLM" in msg
# 预期输出:
# mock ASR segs: [{'speaker': '说话人1', 'text': '模拟转写', 'start': 0.0, 'end': 1.0}]
# Mock ASR 通过：无需真实模型即可验证归一逻辑
# mock LLM out: 会议纪要：3 点
# Mock LLM 通过：消息形状可断言，无需网络
# mapped RateLimit: LLM 服务请求过于频繁，请稍后重试
# 错误映射脱敏通过
```

示例（Mock 文件系统与边界）：

```{code-cell} ipython3
import tempfile, pathlib
import numpy as np
from unittest.mock import patch
from m2t.audio import load_audio, resample_audio

# 1) 用真实临时 wav 验证 load_audio 的单声道归一（hermetic，无需 mock）
import soundfile as sf
with tempfile.TemporaryDirectory() as td:
    wav = pathlib.Path(td) / "stereo.wav"
    # 构造立体声：两通道不同幅度，验证读取后被均值为单声道
    stereo = np.array([[0.5, -0.5], [0.3, -0.3], [0.0, 0.0]], dtype=np.float32)
    sf.write(str(wav), stereo, 16000)
    samples, sr = load_audio(wav)
    print("loaded shape:", samples.shape, "sr:", sr, "dtype:", samples.dtype)
    assert samples.ndim == 1
    assert samples.dtype == np.float32
    print("load_audio 单声道归一通过")

# 2) Mock soundfile：验证上游解码失败时的防御（此处模拟 sf.read 返回立体声）
with patch("m2t.audio.sf.read") as mock_read:
    mock_read.return_value = (np.array([[1.0, 0.0], [0.5, 0.5]], dtype=np.float32), 16000)
    samples, sr = load_audio("any_path.wav")
    print("mocked sf.read -> shape:", samples.shape)
    assert samples.ndim == 1  # 仍被压为单声道
    mock_read.assert_called_once()
    print("Mock 文件系统通过：无需真实文件即可验证归一分支")

# 3) Mock librosa 缺失：验证 resample_audio 的降级路径
with patch.dict("sys.modules", {"librosa": None}):
    # 重新加载模块以触发 ImportError 分支（简化：直接调用时 except ImportError）
    # 此处直接验证回退逻辑：orig_sr != target_sr 但无 librosa 时原样返回
    samples = np.array([0.1, 0.2, 0.3], dtype=np.float32)
    out = resample_audio(samples, 48000, 16000)
    # 若 librosa 实际已安装，上例会走真实重采样；此分支在 CI 中按“无 librosa”回退验证
    print("resample fallback shape:", out.shape)
    print("Mock 降级路径演示完成")
# 预期输出:
# loaded shape: (3,) sr: 16000 dtype: float32
# load_audio 单声道归一通过
# mocked sf.read -> shape: (2,)
# Mock 文件系统通过：无需真实文件即可验证归一分支
# resample fallback shape: (3,)
# Mock 降级路径演示完成
```

> **工程启示**：`fixture` 让 Arrange 可复用与可清理，`mock` 让不稳定依赖可替身化。二者共同降低“写测试的成本”与“跑测试的波动”，使 [2.3 测试的工程思维](2.3_testing_engineering_mindset.md) 的用例能在 CI 中稳定回归。下一节 [2.5 测试覆盖率与质量门禁](2.5_test_coverage_quality_gate.md) 将讨论“如何度量测试的充分性，并用门禁守住底线”。
