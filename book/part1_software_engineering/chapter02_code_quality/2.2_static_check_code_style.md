# 静态检查与代码风格

> 如果把类型检查比作“审合同”，静态检查就是“审排版与错别字”——合同对了，排版仍需统一，否则协作会在“空格、引号、导入顺序”这类噪声中反复内耗。

## 从三件套到一站式：Flake8 / Black / Ruff

传统 Python 工程常需三件套：

- **Flake8**：发现未使用变量、未定义名称、圈复杂度等“逻辑异味”。
- **Black**：以确定性规则格式化代码，终结“引号该用单还是双”的争论。
- **isort**：统一 `import` 排序，避免导入顺序的无意义 diff。

痛点在于**规则分散、配置多处、速度各异**。MeetingToText 教学仓与真实项目仓统一采用 **Ruff**：

- **一站式**：同一工具覆盖 `E` / `F` / `W`（pycodestyle/pyflakes）、`I`（isort）、`B`（flake8-bugbear）、`UP`（pyupgrade）、`SIM`（simplify）等规则。
- **极速**：Rust 实现，比 Flake8 快 10–100 倍，适合在提交前与 CI 中高频运行。
- **可自动修复**：大量规则支持 `--fix`，把“发现问题”与“修复问题”闭环。

> **中立性说明**：Flake8/Black 仍是成熟方案，存量项目无需为迁移而迁移。新项目或教学项目选用 Ruff 的收益在于“单一配置、统一入口、更快反馈”；若团队已深度绑定 Black，也可让 Ruff 的 `format` 与 Black 保持兼容（`ruff format` 即 Black 兼容实现）。

## 工程化配置：`pyproject.toml` 即单一事实源

教学仓 `pyproject.toml` 的相关段落：

```toml
[tool.ruff]
target-version = "py312"
line-length = 100

[tool.ruff.lint]
select = ["E", "F", "W", "I", "B", "UP", "SIM"]

[tool.ruff.format]
# ruff format 兼容 Black 风格，无需额外配置即可与 Black 一致
```

解读：

- `target-version = "py312"`：让 Ruff 知道可用 3.12 语法（如 `str | None`），避免误报。
- `line-length = 100`：全仓统一行宽，`ruff check` 与 `ruff format` 共用，避免“检查与格式化打架”。
- `select`：按需开启规则集。`E/W` 关注风格、`F` 关注未定义/未使用、`I` 统一导入排序、`B` 捕获常见 bug 模式、`UP` 提示可用新语法、`SIM` 简化可读性。

```bash
# 检查
.venv/bin/ruff check m2t/
# 自动修复可修复项
.venv/bin/ruff check --fix m2t/
# 格式化
.venv/bin/ruff format m2t/

# 亦可用 python -m 入口
.venv/bin/python -m ruff check m2t/
```

> **环境约定**：本书面向 Linux，路径与激活命令同第 1 章约定（Linux）；`ruff` 的行为与平台无关，输出仅与 `pyproject.toml` 有关，保证 CI 与本地一致。

## 规则与自动修复的思路

Ruff 的每条规则都有**编码、说明与是否可自动修复**。工程化落地的关键不是“开启所有规则”，而是“选一套能讲清原因的规则，并让修复自动化”：

- **发现**：`ruff check` 产出带编码的诊断（如 `F401` 未使用导入、`I001` 导入未排序、`UP007` 可用 `X | Y` 替代 `Union`）。
- **修复**：`--fix` 对安全修复自动改写；`--unsafe-fixes` 则需人工复核。
- **格式化**：`ruff format` 独立于 `check`，负责引号、分号、换行等排版，不与检查规则冲突。

团队应把 `ruff check` 与 `ruff format --check`（只检查不改写）放入 CI，作为质量门禁的一部分（见 [2.5 测试覆盖率与质量门禁](2.5_test_coverage_quality_gate.md)）。

## 可运行示例：规则检出与自动修复

文件 `book/part1_software_engineering/chapter02_code_quality/demo_ruff_rules.py`：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter02_code_quality/demo_ruff_rules.py
import subprocess, sys, tempfile, pathlib, textwrap

# 构造一份故意包含风格与逻辑异味的代码
bad_code = textwrap.dedent("""
import os, sys  # E401 多导入同行；可能触发 I001 导入排序
import pathlib
x = 1
y = 2  # F841 未使用变量（若未使用 y）
def foo():
    a = 1
    return a
# UP006: List[int] 可改 list[int]（py312）；SIM102 可合并嵌套 if（视代码而定）
""")

def run_ruff(code: str, fix: bool = False) -> tuple[int, str, str]:
    """用 ruff 检查给定代码，返回 (exit, stdout, fixed_code)。"""
    with tempfile.TemporaryDirectory() as td:
        p = pathlib.Path(td) / "sample.py"
        p.write_text(code, encoding="utf-8")
        # 优先用 python -m ruff，保证找到 .venv 中的 ruff
        cmd = [sys.executable, "-m", "ruff", "check", str(p)]
        if fix:
            cmd.append("--fix")
        # 若 mypy/ruff 的 pyproject 配置影响结果，显式隔离：仅用默认规则演示
        # 此处不传 --select，复用 pyproject.toml 的 select，保证与仓内一致
        result = subprocess.run(cmd, capture_output=True, text=True)
        fixed = p.read_text(encoding="utf-8") if fix else code
        out = (result.stdout + result.stderr).strip()
        return result.returncode, out[:2000], fixed

status, out, _ = run_ruff(bad_code, fix=False)
print("ruff check exit:", status)
print(out if out else "(no output)")
print("---")
# 演示自动修复
status2, out2, fixed = run_ruff(bad_code, fix=True)
print("after --fix exit:", status2)
print(out2[:800] if out2 else "(no output after fix)")
# 展示修复前后的 diff 体感（截取前 300 字符）
print("fixed preview:")
print(fixed[:400])
# 预期输出:
# ruff check exit: 1  包含 F401/I001 等诊断
# after --fix exit: 0 或仍有需人工修复项
# fixed preview: 已自动移除未使用导入或重排 imports
```

文件 `book/part1_software_engineering/chapter02_code_quality/demo_ruff_format.py`（格式化的一致性）：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter02_code_quality/demo_ruff_format.py
import subprocess, sys, tempfile, pathlib, textwrap

unformatted = textwrap.dedent("""
def export(task,fmt):
    if fmt=="txt": return task["text"]
    return ""
""")

with tempfile.TemporaryDirectory() as td:
    p = pathlib.Path(td) / "fmt.py"
    p.write_text(unformatted, encoding="utf-8")
    # 检查格式化差异（--check --diff 不改写文件）
    chk = subprocess.run(
        [sys.executable, "-m", "ruff", "format", "--check", "--diff", str(p)],
        capture_output=True, text=True,
    )
    print("format --check diff exit:", chk.returncode)
    print((chk.stdout + chk.stderr)[:1500])

    # 真正格式化
    fmt = subprocess.run(
        [sys.executable, "-m", "ruff", "format", str(p)],
        capture_output=True, text=True,
    )
    print("format exit:", fmt.returncode)
    print("after format:")
    print(p.read_text(encoding="utf-8"))
    assert "def export(task, fmt):" in p.read_text(encoding="utf-8") or "def export" in p.read_text(encoding="utf-8")
# 预期输出:
# format --check diff exit: 1  提示需要格式化
# format exit: 0
# after format: 已按 line-length=100、Black 兼容风格重排
```

文件 `book/part1_software_engineering/chapter02_code_quality/demo_m2t_style.py`（用 `m2t` 真实代码验证仓内风格已收敛）：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter02_code_quality/demo_m2t_style.py
import subprocess, sys, pathlib

# 对 m2t 包做一次只读检查，验证教学仓已通过自身门禁
targets = ["m2t/__init__.py", "m2t/export.py", "m2t/store.py"]
for t in targets:
    p = pathlib.Path(t)
    if not p.exists():
        print(f"skip {t}: not found")
        continue
    result = subprocess.run(
        [sys.executable, "-m", "ruff", "check", str(p)],
        capture_output=True, text=True,
    )
    print(f"{t}: exit={result.returncode}", "(ok)" if result.returncode == 0 else result.stdout[:500])
    # 预期：已收敛的文件应为 exit 0；若有告警，说明需在提交前 --fix
# 预期输出:
# m2t/__init__.py: exit=0 (ok)
# m2t/export.py: exit=0 (ok)
# m2t/store.py: exit=0 (ok)
```

> **工程启示**：风格不是审美之争，而是“协作成本”的度量。Ruff 把风格与低级缺陷收敛到一条命令，让 `git diff` 只承载业务变更，而非引号与空格的噪声。配合 `mypy`（见 [2.1 类型系统与防御性编程](2.1_type_system_defensive_programming.md)）与测试（见 [2.3 测试的工程思维](2.3_testing_engineering_mindset.md)），三者在提交前形成第一道自动化护城河。
