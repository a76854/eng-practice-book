# 类型系统与防御性编程

> 如果把动态类型比作“口头约定”，类型标注就是“书面合同”——口头约定灵活但易生歧义，书面合同让协作双方在动手前就对齐了形状与边界。

## 为什么需要类型

Python 的灵活以“运行时才暴露形状错误”为代价。真实坑点往往不在算法，而在边界形状：某个函数预期收到 `list` 却收到了 `None`，某个查询返回 `None` 却被直接取下标，某个导出函数的参数既可能是 `dict` 也可能是对象。类型标注的价值在于**把这些形状从“运行时才发现”提前到“编辑期就检查”**。

类型系统不保证逻辑正确，但能把一大类“传错形状、用错空值、拼错字段”在提交前拦住。

## 类型标注最小子集

不必一次学全类型系统，掌握最小可用子集就能让大部分协作错误提前暴露：

- **函数签名**：`def load(name: str, n: int) -> str:` 锁住输入与输出形状。
- **可选值**：`str | None`（Python 3.10+）表示“可能为空”，逼迫调用方显式处理 `None` 分支。
- **泛型容器**：`list[dict[str, Any]]` 精确描述“列表里装的是字典，字典的值暂不约束”。
- **字面量约束**：`Literal["txt", "srt", "md"]` 让非法取值在检查期就不可表示。

签名本身就是文档与契约，配合 `get_type_hints` 可以在运行时直接看到形状被如何锁住。

```{code-cell} ipython3
from __future__ import annotations
from typing import Any, Literal, get_type_hints

# 1) 基础签名：锁住输入输出
def load(name: str, n: int) -> str:
    if not name.strip():
        raise ValueError("name 不能为空")
    if n <= 0:
        raise ValueError("n 必须为正整数")
    return f"{name}:{n}"

# 2) 可选值：str | None 逼迫调用方处理空值
def find_title(meta: dict[str, str]) -> str | None:
    v = meta.get("title")
    return v if v and v.strip() else None

# 3) 泛型容器：列表里装字典
def summarize(rows: list[dict[str, Any]]) -> list[str]:
    out: list[str] = []
    for r in rows:
        out.append(str(r.get("text", "")))
    return out

# 4) 字面量约束：只允许三种取值
def export(text: str, fmt: Literal["txt", "srt", "md"] = "txt") -> str:
    if fmt not in ("txt", "srt", "md"):
        raise ValueError(f"不支持的格式: {fmt}")
    return f"[{fmt}] {text}"

# 形状被签名锁住：直接打印即可验证
print("load hints:", get_type_hints(load))
print("find_title hints:", get_type_hints(find_title))
print("summarize hints:", get_type_hints(summarize))
print("export hints:", get_type_hints(export))

# 可运行断言
assert load("task", 2) == "task:2"
assert find_title({"title": "hello"}) == "hello"
assert find_title({}) is None
assert summarize([{"text": "a"}, {"text": "b"}]) == ["a", "b"]
assert export("hi", "md") == "[md] hi"

# 预期输出：
# load hints: {'name': <class 'str'>, 'n': <class 'int'>, 'return': <class 'str'>}
# find_title hints: {'meta': dict[str, str], 'return': str | None}
# summarize hints: {'rows': list[dict[str, typing.Any]], 'return': list[str]}
# export hints: {'text': <class 'str'>, 'fmt': typing.Literal['txt', 'srt', 'md'], 'return': <class 'str'>}
```

> **要点**：类型标注不改变运行时行为，但让“传错形状”在编辑器与检查工具中立刻显形。团队约定“新文件必须有签名标注”，收益远大于成本。

## `@dataclass` 固定数据形状

当数据从“随意字典”升级为“固定结构”，`dataclass` 是最轻量的形状固化工具。它把字段名、类型、默认值写在类定义里，非法字段在创建对象时立即暴露，替代了“字典里拼对字段名、运行时才发现拼错”的脆弱模式。

```{code-cell} ipython3
from dataclasses import dataclass, field, asdict
from typing import Literal

@dataclass
class Task:
    id: str
    filename: str
    status: Literal["pending", "running", "done", "failed"] = "pending"
    segments: list[str] = field(default_factory=list)

# 正常创建：形状清晰，默认值生效
t1 = Task(id="t-001", filename="report.txt")
print(t1)
print(asdict(t1))
assert t1.status == "pending"
assert t1.segments == []

# 追加片段：default_factory 保证每个实例独立列表
t1.segments.append("hello")
t2 = Task(id="t-002", filename="notes.txt", status="running", segments=["intro"])
print("t1 segments:", t1.segments)
print("t2 segments:", t2.segments)
assert t2.segments == ["intro"]
assert t1.segments == ["hello"]  # 与 t2 互不影响

# 非法字段：创建时即抛 TypeError，提早暴露拼写错误
try:
    Task(id="t-003", filename="a.txt", unknown_field="oops")  # type: ignore[call-arg]
except TypeError as e:
    print("caught unexpected field:", e)

# 类型错配：dataclass 本身不在运行时强校验类型（由静态检查负责），
# 但把形状写在定义处后，mypy 会在提交前拦截 Task(id=123, ...) 这类错误。
# 运行时可通过简单断言兜底演示：
try:
    bad = Task(id=123, filename="a.txt")  # type: ignore[arg-type]
    if not isinstance(bad.id, str):
        raise TypeError(f"id 期望 str，实际为 {type(bad.id).__name__}")
except TypeError as e:
    print("caught type mismatch:", e)

# Literal 约束：非法 status 同样应在静态检查期被拦截，运行时可断言
assert Task(id="t-004", filename="b.txt", status="done").status == "done"

# 预期输出：
# Task(id='t-001', filename='report.txt', status='pending', segments=[])
# {'id': 't-001', 'filename': 'report.txt', 'status': 'pending', 'segments': []}
# t1 segments: ['hello']
# t2 segments: ['intro']
# caught unexpected field: Task.__init__() got an unexpected keyword argument 'unknown_field'
# caught type mismatch: id 期望 str，实际为 int
```

> **工程启示**：`dataclass` 让“有哪些字段、字段是什么类型、默认值是什么”从隐式约定变为显式定义。字典适合临时拼接，`dataclass` 适合在模块边界与存储层之间传递的结构化数据。配合下一节的 `pydantic`，可在入口处进一步做运行时校验。

## `pydantic.BaseModel` 运行时校验

`dataclass` 固化了形状，但默认不做运行时值校验。`pydantic.BaseModel` 在此之上补上了**边界运行时校验**：空字符串、类型错误、越界值会在对象创建时被 `ValidationError` 拦截，并通过 `e.errors()` 给出结构化、可直接返回给调用方的错误详情。这是防御性编程在边界的落地形态。

```{code-cell} ipython3
from pydantic import BaseModel, Field, ValidationError
from typing import Literal

class CreateTaskIn(BaseModel):
    filename: str = Field(min_length=1, max_length=128, description="文件名不能为空且不超过 128 字符")
    fmt: Literal["txt", "srt", "md"] = "txt"
    priority: int = Field(default=1, ge=1, le=5, description="优先级 1-5")

# 合法输入：直接通过
ok = CreateTaskIn(filename="report.txt", fmt="md", priority=3)
print("ok:", ok.model_dump())
assert ok.filename == "report.txt"
assert ok.priority == 3

# 空字符串：被 min_length 拦截
try:
    CreateTaskIn(filename="", fmt="txt")
except ValidationError as e:
    print("empty filename errors:", e.errors())
    assert any(err["loc"] == ("filename",) for err in e.errors())

# 类型错误：priority 期望 int，传入字符串被拦截
try:
    CreateTaskIn(filename="a.txt", priority="high")  # type: ignore[arg-type]
except ValidationError as e:
    print("type error:", e.errors())
    assert any(err["loc"] == ("priority",) for err in e.errors())

# 越界：priority 超出 [1,5] 被拦截
try:
    CreateTaskIn(filename="a.txt", priority=10)
except ValidationError as e:
    print("range error:", e.errors())
    assert any(err["type"] == "less_than_equal" for err in e.errors())

# 非法字面量：fmt 不在允许集合内
try:
    CreateTaskIn(filename="a.txt", fmt="pdf")  # type: ignore[arg-type]
except ValidationError as e:
    print("literal error:", e.errors())
    assert any(err["loc"] == ("fmt",) for err in e.errors())

# 预期输出（节选）：
# ok: {'filename': 'report.txt', 'fmt': 'md', 'priority': 3}
# empty filename errors: [{'type': 'string_too_short', 'loc': ('filename',), ...}]
# type error: [{'type': 'int_parsing', 'loc': ('priority',), ...}]
# range error: [{'type': 'less_than_equal', 'loc': ('priority',), ...}]
# literal error: [{'type': 'literal_error', 'loc': ('fmt',), ...}]
```

## 防御性编程：边界校验、Fail Fast、尽早失败

类型解决“形状对不对”，防御性编程解决“值合不合法、失败早不早”：

1. **在边界校验**：对外输入（HTTP 请求体、CLI 参数、文件路径）在入口处一次性用 `BaseModel` 校验，失败即抛 `ValidationError`，不让脏数据流入深层。
2. **尽早失败（Fail Fast）**：校验失败立即返回结构化错误（`e.errors()`），而非让 `None` 或空字符串渗透到后续逻辑才触发难以定位的异常。
3. **不可表示优于运行时检查**：用 `Literal` 约束枚举值、用 `Field(ge=..., le=..., min_length=...)` 约束范围与长度，比“字符串随意传、运行时再判断”更早暴露错误。
4. **收窄而非放行**：`str | None` 逼迫调用方写 `if v is None` 分支，`dataclass` 固定字段避免 `dict.get` 的拼写容错，二者配合把“容错式编程”收敛为“契约式编程”。

上一节的 `CreateTaskIn` 正是这一思想的落地：所有非法输入在构造模型的瞬间被拦截，错误信息精确到字段与类型，调用方无需深入业务逻辑即可修正。

## 静态检查与风格：一句话带过

类型写好了，需要工具来执行契约：`mypy` 会做静态类型检查，发现签名不一致与空值误用，命令为 `.venv/bin/mypy file.py`；`ruff` 管风格与 lint，统一格式并捕获低级缺陷，命令为 `.venv/bin/ruff check .`。二者配合，把“靠人眼”的检查变为“提交前自动拦截”。更完整的规则与工作流见 [2.2 静态检查与代码风格](2.2_static_check_code_style.md)。

> **工程启示**：类型标注锁形状、`dataclass` 固化结构、`pydantic` 在边界拦截脏输入，三者递进形成“编辑期检查 → 结构显式化 → 运行时校验”的完整护城河。防御性编程不是到处写 `if`，而是让非法状态不可表示、让失败尽早且清晰。
