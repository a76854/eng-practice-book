# 测试的工程思维

> 如果把类型与静态检查比作“出厂质检”，测试就是“试驾”——不发动起来，很多边界与协作问题永远藏在静态视角之外。

## 为什么需要测试思维，而非“写几个断言”

MeetingToText 的流水线“上传 → 转写 → 纪要 → 导出 → 存储”中，单点正确不等于链路可靠：

- `normalize_result` 对空结果返回 `[]`，调用方若假设“必有 1 段”就会在空音频时崩溃。
- `export(task, "srt")` 对无段任务返回空字符串，`export(task, "unknown")` 应抛 `ValueError`，二者是**不同语义**，需分别验证。
- `TaskStore` 在并发写入时依赖 `WAL` 与 `busy_timeout`，单次 `create` 成功不代表并发下不丢数据。

测试的工程价值在于**把“隐式假设”显式化为可回归的契约**：未来重构、升级依赖、调整 SQL 时，契约仍在，信心就在。

## 测试金字塔：分层与取舍

```
      /__ E2E __\      少数、慢、覆盖链路（如 FastAPI /upload -> 导出）
    /_ Integration _\  适量、较慢、覆盖协作（如 store + export 组合）
  /____ Unit ____\     大量、快、覆盖纯函数（如 export、normalize_result）
```

- **单元测试**：验证纯函数与边界（`m2t.export`、`m2t.asr.normalize_result`），无 I/O、无网络，毫秒级。
- **集成测试**：验证模块协作（如 `TaskStore` 写入后 `export` 能否消费），需临时文件/数据库，但仍可在本机 hermetic 运行。
- **端到端**：验证 HTTP 链路，需启动 FastAPI 与真实或替身服务，成本最高，按需保留。

> **中立性说明**：金字塔是经验模型，不是教条。MeetingToText 的音视频与 LLM 依赖适合用替身（mock/fake）下沉到单元/集成层，把昂贵的 E2E 留给关键链路。

## AAA 模式：Arrange / Act / Assert

每个测试用例都应清晰分为三段：

1. **Arrange**：准备输入与替身（构造 `task` dict、临时数据库、`fake_model`）。
2. **Act**：执行被测行为（调用 `export(task, "txt")`、`store.create(...)`）。
3. **Assert**：断言可观测结果（返回值、状态、抛错类型）。

AAA 让测试具有**可读性与可定位性**：失败时能立刻判断是“准备错了、执行错了、还是预期错了”。

## 边界条件：从“正常路径”到“异常形状”

边界不是“额外工作”，而是“用户真实输入”：

- **空输入**：`[]`、`{}`、`""`、`None`。
- **单元素与多元素**：1 段、2 段、100 段（如 `srt` 编号是否连续）。
- **非法输入**：未知格式 `"unknown"`、路径穿越 `"../evil"`、负数时间戳。
- **类型边界**：`int` vs `float`、`str | Path`、`dict` vs 对象。

> **环境约定**：本书面向 Linux，涉及临时文件与路径的测试，用 `tempfile.TemporaryDirectory()` 与 `pathlib.Path`，避免硬编码 `/tmp` 或 `\`，保证在 Linux 环境一致。

## 可运行示例：pytest 断言与边界用例

文件 `book/part1_software_engineering/chapter02_code_quality/demo_pytest_aaa.py`（AAA 与边界，`m2t.export`）：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter02_code_quality/demo_pytest_aaa.py
from m2t.export import export

# AAA 示例 1：正常路径 — txt 导出带说话人
# Arrange
task = {
    "filename": "meeting.wav",
    "result": {
        "segments": [
            {"speaker": "说话人1", "text": "大家好", "start": 0, "end": 1.2},
            {"speaker": "", "text": "今天讨论进度", "start": 1.2, "end": 3.0},
        ]
    },
}
# Act
out = export(task, "txt")
# Assert
print(out)
assert "[说话人1] 大家好" in out
assert "今天讨论进度" in out
print("AAA 正常路径通过")
# 预期输出:
# [说话人1] 大家好
# 今天讨论进度
# AAA 正常路径通过

# 边界：空段
empty_task = {"filename": "empty.wav", "result": {"segments": []}, "full_text": "无段但有全文"}
assert export(empty_task, "txt") == "无段但有全文"
print("边界 空段 -> 回退 full_text 通过")

# 边界：srt 对空段返回空字符串
assert export(empty_task, "srt") == ""
print("边界 srt 空段 -> 空字符串通过")

# 异常路径：未知格式应抛 ValueError
try:
    export(task, "unknown")
    assert False, "应抛 ValueError"
except ValueError as e:
    print("异常路径 未知格式 -> ValueError:", e)
    assert "不支持" in str(e)
# 预期输出:
# 边界 空段 -> 回退 full_text 通过
# 边界 srt 空段 -> 空字符串通过
# 异常路径 未知格式 -> ValueError: 不支持的导出格式: unknown，...

# 边界：时间戳为负数的防御（srt 应归零而非崩溃）
neg_task = {
    "filename": "neg.wav",
    "result": {"segments": [{"speaker": "", "text": "hello", "start": -5, "end": -1}]},
}
srt = export(neg_task, "srt")
print(srt.splitlines()[:3])
assert "00:00:00,000" in srt  # _format_timestamp_srt 对负数归零
print("边界 负时间戳 -> 归零通过")
# 预期输出:
# ['1', '00:00:00,000 --> 00:00:00,000', 'hello']
# 边界 负时间戳 -> 归零通过
```

文件 `book/part1_software_engineering/chapter02_code_quality/demo_pytest_boundaries.py`（`normalize_result` 的形状边界）：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter02_code_quality/demo_pytest_boundaries.py
from m2t.asr import normalize_result

# 边界 1：空结果
assert normalize_result([]) == []
assert normalize_result([{}]) == []
print("边界 空结果通过")

# 边界 2：sentence_info 形状（含说话人与毫秒时间）
result_si = [{
    "sentence_info": [
        {"text": "你好", "start": 0, "end": 1200, "spk": 0},
        {"text": "再见", "start": 1200, "end": 2500, "spk": 1},
        {"text": "  ", "start": 2500, "end": 3000, "spk": 0},  # 空白应被过滤
    ]
}]
segs = normalize_result(result_si)
print(segs)
assert segs[0]["speaker"] == "说话人1"  # 0 基转 1 基
assert segs[1]["speaker"] == "说话人2"
assert len(segs) == 2  # 空白段被过滤
print("边界 sentence_info 通过")

# 边界 3：raw_text + timestamp 回退
result_raw = [{"text": "hello", "timestamp": [[0, 1000]]}]
segs2 = normalize_result(result_raw)
print(segs2)
assert segs2[0]["text"] == "hello"
assert segs2[0]["start"] == 0.0
assert segs2[0]["end"] == 1.0  # 毫秒转秒
print("边界 raw_text+timestamp 通过")

# 边界 4：脏数据（非 dict 的 sentence_info 项应被跳过）
dirty = [{"sentence_info": ["not a dict", {"text": "ok", "start": 0, "end": 500}]}]
segs3 = normalize_result(dirty)
assert len(segs3) == 1 and segs3[0]["text"] == "ok"
print("边界 脏数据防御通过")
# 预期输出:
# 边界 空结果通过
# 边界 sentence_info 通过
# 边界 raw_text+timestamp 通过
# 边界 脏数据防御通过
```

文件 `book/part1_software_engineering/chapter02_code_quality/demo_store_integration.py`（集成：store 写入后可被 export 消费）：

```{code-cell} ipython3
# 文件 book/part1_software_engineering/chapter02_code_quality/demo_store_integration.py
import tempfile, pathlib
from m2t.store import TaskStore
from m2t.export import export

with tempfile.TemporaryDirectory() as td:
    db = pathlib.Path(td) / "integration.db"
    store = TaskStore(db)

    # Arrange: 写入任务
    store.create("int1", "demo.wav", full_text="集成测试：存储与导出协作")
    row = store.get("int1")
    assert row is not None
    print("store row:", row["filename"], row["status"])

    # Act: 构造可被 export 消费的 task 视图
    task = {
        "id": row["id"],
        "filename": row["filename"],
        "result": {
            "segments": [{"speaker": "说话人1", "text": row["full_text"], "start": 0, "end": 2}],
            "duration": 2,
        },
        "minutes": "要点：金字塔分层让协作可回归",
    }
    md = export(task, "md")
    # Assert
    assert "demo.wav" in md
    assert "集成测试" in md
    print(md.splitlines()[0])
    print("集成 store -> export 通过")
# 预期输出:
# store row: demo.wav pending
# # 会议转录 — demo.wav
# 集成 store -> export 通过
```

> **工程启示**：测试不是“为覆盖率而写的断言”，而是“对协作契约的显式表达”。从纯函数单元测试起步，沿金字塔向上按需补充集成与 E2E，并在 [2.4 Pytest 进阶](2.4_pytest_advanced.md) 中用 `fixture` 与 `mock` 降低不稳定依赖的成本。
