# 第一篇 软件工程筑基

本篇是全书的工程底座，回答一个基础问题，怎样让代码从“在你机器上能跑”变为“在任何机器上可复现，在任何协作中可维护”。两章内容不涉及具体业务，却会直接影响后续所有业务代码的交付质量。

许多同学在入门阶段习惯单文件编程，依赖全局安装，协作靠压缩包传递，版本靠文件后缀区分。这种方式在课程作业中尚可应付，一旦进入团队项目或长期维护，就会暴露出环境不一致、合并困难、回归频发等问题。本篇把这些隐性成本显式化，并给出可落地的工程化方案。从项目结构与虚拟环境，到 Shell 与自动化脚本，再到 Git 与代码质量保障，每一步都强调“用工具把约束自动化”，让规范不需要靠人为记忆来维持。

学完本篇，你将拥有一套可直接用于课程大作业与实习项目的工程脚手架，能够独立完成环境搭建、依赖管理、脚本自动化、分支协作与质量门禁的完整闭环。

本篇包含以下两章：

- [第1章 开发者的元技能](chapter01_dev_meta_skills/index.md)，从 `src` 布局与 `pyproject.toml` 到 `venv` 与 `uv` 的选型，从 Shell 的文件、进程与管道到 Python 自动化脚本与 Git 对象模型，把环境、脚本与协作三件套一次讲透。本章以通用项目为例，演示项目仅在每节末尾以案例形式出现，适合作为独立的工程入门
- [第2章 构筑代码质量的护城河](chapter02_code_quality/index.md)，用类型系统、Ruff 静态检查、pytest 测试金字塔与覆盖率门禁，把“能跑”提升为“可信”，让错误尽早暴露，让协作有底线可守

建议按顺序阅读，并在阅读过程中同步完成实验一与实验二，让工程规范在动手中有落脚点。
