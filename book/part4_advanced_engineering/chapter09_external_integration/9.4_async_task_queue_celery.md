# 异步任务队列 Celery

> 当一个请求要做 30 秒的转写 + 10 秒的摘要生成时，让 HTTP 线程“等着”是最贵的错误——把长时工作丢进队列，让请求快速返回、让工作可重试、可观测，才是工程解。

## 为什么 HTTP 不适合直接做长时任务

- **超时**：网关、浏览器、移动端对单次请求的超时多在 30–60 秒，超过即被切断。
- **重试放大**：用户看到超时会重试，若服务端已在处理，重试即“同一任务执行多次”。
- **资源占用**：FastAPI/Uvicorn 的工作线程被长时任务占满，短请求也被拖慢（见 [第6章 并发模型与性能工程](../../part2_backend_development/chapter06_concurrency_perf/index.md) 的事件循环陷阱）。

**解法**：HTTP 只做“入队 + 返回任务 ID”，真实工作由队列的 worker 异步执行，前端用轮询或 SSE/WebSocket 观察进度。

## Celery / RQ 的三件套心智

无论是 Celery、RQ 还是自研队列，抽象都是同一套：

- **Broker**：任务的“邮箱”（Redis、RabbitMQ），负责入队与分发。
- **Worker**：后台进程，循环 `pop -> 执行 -> 更新结果`。
- **Result Backend**：任务结果与状态的存储（Redis、数据库、或 `m2t.store.TaskStore` 的 SQLite）。

```
[HTTP] --enqueue--> [Broker] --pop--> [Worker] --update--> [Result Backend]
  |                                                        |
  +-- 返回 task_id --> [前端轮询/SSE] <--- 查询状态/结果 ---+
```

**附加能力**：重试（指数退避）、幂等（同一音频多次提交只算一次）、定时（`eta`/`countdown`）、优先级与路由（转写队列 vs 摘要队列分离）。

> **中立性说明**：Celery 功能全但运维重（需 broker + result + worker 监控）；RQ 轻量但仅支持 Redis；若并发不高，用数据库轮询或 `asyncio.Queue` 的内存队列亦可起步。选型应基于团队运维能力与峰值，而非“必须用 Celery”。

## 可观测与失败域

- 每个任务应有 `id / status / progress / error` 四字段，状态机至少为 `pending -> running -> done/failed`。
- 失败时保留脱敏错误（见 [9.1 第三方服务集成模式](9.1_third_party_service_integration.md) 的 `map_llm_error`），成功时写回 `result`。
- 走 `m2t.store.TaskStore` 的 SQLite + WAL 即是最小的 result backend，无需额外中间件即可演示“入队即返回、后台可重试”的闭环。

```bash
# 本节不依赖 celery/redis，仅用标准库演示队列抽象
# 若需真实 Celery，请在隔离环境中 pip install celery redis
```

## 可运行示例：最小队列抽象（不 import celery）

文件 `book/part4_advanced_engineering/chapter09_external_integration/demo_task_queue.py`（简化 broker/worker，无外部依赖）：

```{code-cell} ipython3
# 文件 book/part4_advanced_engineering/chapter09_external_integration/demo_task_queue.py
import queue, threading, time, uuid
from dataclasses import dataclass, field

@dataclass
class Task:
    id: str
    kind: str  # "transcribe" | "summarize"
    payload: dict
    status: str = "pending"
    result: str = ""
    error: str = ""

class SimpleBroker:
    """内存 Broker：用 queue.Queue 模拟入队/出队，无需 Redis。"""
    def __init__(self):
        self.q: queue.Queue[Task] = queue.Queue()
    def enqueue(self, task: Task) -> None:
        self.q.put(task)
    def dequeue(self, timeout: float = 0.2) -> Task | None:
        try:
            return self.q.get(timeout=timeout)
        except queue.Empty:
            return None

class SimpleWorker(threading.Thread):
    """后台 Worker：循环取任务并执行，支持优雅停止。"""
    def __init__(self, broker: SimpleBroker, store: dict[str, Task]):
        super().__init__(daemon=True)
        self.broker = broker
        self.store = store
        self._stop_event = threading.Event()

    def run(self):
        while not self._stop_event.is_set():
            task = self.broker.dequeue()
            if task is None:
                continue
            task.status = "running"
            try:
                # 模拟两种外部调用：ASR 与 LLM，均为本地计算，无网络
                if task.kind == "transcribe":
                    time.sleep(0.05)
                    audio = task.payload.get("audio", "")
                    task.result = f"transcript of {audio}: 与外部世界的集成"
                elif task.kind == "summarize":
                    time.sleep(0.05)
                    text = task.payload.get("text", "")
                    task.result = f"summary: {text[:12]}..."
                else:
                    task.result = "unknown kind"
                task.status = "done"
            except Exception as e:
                # 脱敏：不把原始异常透传给前端
                from m2t.llm import map_llm_error
                task.error = map_llm_error(e)
                task.status = "failed"
            finally:
                self.store[task.id] = task

    def stop(self):
        self._stop_event.set()

# 演示：HTTP 入队 -> 立即返回 id -> 后台执行 -> 轮询结果
broker = SimpleBroker()
store: dict[str, Task] = {}
worker = SimpleWorker(broker, store)
worker.start()

def submit(kind: str, payload: dict) -> str:
    tid = uuid.uuid4().hex[:8]
    t = Task(id=tid, kind=kind, payload=payload)
    store[tid] = t
    broker.enqueue(t)
    return tid

tid1 = submit("transcribe", {"audio": "meeting.wav"})
tid2 = submit("summarize", {"text": "与外部世界的集成是必修课"})
print("enqueued:", tid1, tid2)
print("immediate status:", store[tid1].status)

# 轮询等待（真实项目中由前端或 SSE 驱动）
deadline = time.time() + 2.0
while time.time() < deadline:
    if store[tid1].status == "done" and store[tid2].status == "done":
        break
    time.sleep(0.05)

print("final:", store[tid1].status, store[tid1].result)
print("final:", store[tid2].status, store[tid2].result)
assert store[tid1].status == "done"
assert "transcript" in store[tid1].result
assert store[tid2].status == "done"

worker.stop()
worker.join(timeout=1.0)
print("队列校验通过：入队即返回、后台可执行、结果可查询")
# 预期输出:
# enqueued: <8hex> <8hex>
# immediate status: pending 或 running
# final: done transcript of meeting.wav: 与外部世界的集成
# final: done summary: 与外部世界的集成...
# 队列校验通过：入队即返回、后台可执行、结果可查询
```

```{code-cell} ipython3
# 文件 book/part4_advanced_engineering/chapter09_external_integration/demo_queue_retry.py
import queue, time

class IdempotentStore:
    """用内存去重表演示幂等：同一 audio 只入队一次。"""
    def __init__(self):
        self.seen: set[str] = set()
        self.q: queue.Queue[str] = queue.Queue()

    def submit_once(self, audio: str) -> bool:
        if audio in self.seen:
            return False
        self.seen.add(audio)
        self.q.put(audio)
        return True

def run_with_retry(fn, max_retries: int = 2):
    last = None
    for attempt in range(max_retries + 1):
        try:
            return fn(attempt)
        except Exception as e:
            last = e
            if attempt == max_retries:
                break
            # 指数退避（本地不真实 sleep，仅演示计算）
            _backoff = 0.05 * (2 ** attempt)
    from m2t.llm import map_llm_error
    return f"failed: {map_llm_error(last)}"

# 幂等演示
store = IdempotentStore()
print("first submit:", store.submit_once("meeting.wav"))
print("dup submit:", store.submit_once("meeting.wav"))
assert store.q.qsize() == 1

# 重试演示：前 2 次瞬态失败，第 3 次成功
def flaky(attempt: int):
    if attempt < 2:
        raise RuntimeError(f"transient {attempt}")
    return "ok after retry"

print(run_with_retry(flaky, max_retries=2))
assert run_with_retry(flaky, max_retries=2) == "ok after retry"

# 超过重试仍失败 -> 脱敏
def always_fail(_):
    raise RuntimeError("sk-secret leak attempt https://api.example.com")

msg = run_with_retry(always_fail, max_retries=1)
print(msg)
assert "sk-secret" not in msg
print("重试与幂等校验通过：幂等防重、重试有界、失败脱敏")
# 预期输出:
# first submit: True
# dup submit: False
# ok after retry
# LLM 调用失败，请检查服务可用性或联系管理员
# 重试与幂等校验通过：幂等防重、重试有界、失败脱敏
```

> **工程启示**：把“HTTP 快速返回 + 队列后台执行 + 结果可查询”三件套做扎实后，ASR 与 LLM 的时延与不可靠性就被隔离在 worker 中，HTTP 层只需做好入队幂等与状态查询。MeetingToText 的 `backend/app/routers` 与 `m2t.store` 即是该分层的生产映射。
