# 大模型接口设计

> 大模型接口的核心矛盾是“自由文本的创造力”与“系统集成的确定性”之间的张力——结构化输出解决“如何可编程地用”，流式响应解决“如何快地用”。

## 为何要结构化输出

直接让 LLM 输出自然段，适合人读，不适合机器读。MeetingToText 的“会议纪要”若是自由文本，下游难以做字段校验、入库与模板渲染。**结构化输出**用 JSON Schema 约束模型只吐合法 JSON：

- **JSON Mode**：声明 `response_format={"type": "json_object"}`，模型尽量吐 JSON。
- **JSON Schema / Structured Output**：进一步给出字段、类型、枚举与必填，让“缺字段、类型错、枚举外”在服务端即被拒。
- **校验前置**：收到后先 `json.loads`，再用 Pydantic/JSON Schema 校验，失败则视为“生成失败”走重试或降级。

> **选型权衡**：结构化越强，可靠性越高，但创造力与容错越低。对会议纪要这类“半结构化”输出，常采用“结构化外壳 + 自由文本内核”（如 `{"title": str, "summary": str, "action_items": [{"owner": str, "task": str}]}`）。

## 为何要流式响应

一次 LLM 调用可能 5–20 秒才完成，若等全量返回再渲染，用户体感是“卡住”。**流式（SSE, Server-Sent Events）**让模型边生成边吐增量，前端用 `EventSource` 或 `fetch + ReadableStream` 逐块渲染，首字时延从秒级降至百毫秒级。

SSE 的 wire 格式极简：

```
data: {"delta": "与"}
data: {"delta": "外部"}
data: [DONE]
```

每行以 `data:` 开头，空行分隔事件。关键是**增量解析**——不能等 ` [DONE]` 才 `json.loads`，而要逐 delta 拼出完整 JSON，并在中途处理截断。

## 错误与限流

结构化与流式同样受限流与超时影响。常见策略：

- 流式中途断连视为可重试，但需带上已收到的 `request_id` 做幂等续传，或直接重建新请求。
- 结构化校验失败不应无限重试——2 次重试后即降级为“自由文本 + 后处理抽取”。

## 可运行示例：流式 SSE 仿真与结构化解析（无网络）

文件 `book/part4_advanced_engineering/chapter09_external_integration/demo_llm_stream.py`（仿真 SSE 生成器与增量解析）：

```{code-cell} ipython3
# 文件 book/part4_advanced_engineering/chapter09_external_integration/demo_llm_stream.py
import json, time

def fake_sse_stream(full_text: str, chunk_size: int = 2, delay: float = 0.0):
    """仿真 LLM 的 SSE 流：按 chunk_size 切分，逐块 yield SSE 行，无网络。"""
    for i in range(0, len(full_text), chunk_size):
        delta = full_text[i:i+chunk_size]
        payload = json.dumps({"delta": delta}, ensure_ascii=False)
        yield f"data: {payload}\n\n"
        if delay:
            time.sleep(delay)
    yield "data: [DONE]\n\n"

def parse_sse(lines):
    """增量解析 SSE：拼出完整文本，忽略 [DONE]，容错空行。"""
    buf = []
    for line in lines:
        line = line.strip()
        if not line or line == "data: [DONE]":
            continue
        if line.startswith("data:"):
            raw = line[len("data:"):].strip()
            obj = json.loads(raw)
            buf.append(obj.get("delta", ""))
    return "".join(buf)

# 演示：边生成边解析
full = "与外部世界的集成是现代后端的必修课。"
stream = fake_sse_stream(full, chunk_size=3)
chunks = list(stream)
print("sse wire 首行:", chunks[0].strip())
print("sse lines:", len(chunks))
rebuilt = parse_sse(chunks)
print("rebuilt:", rebuilt)
assert rebuilt == full

# 首字时延体感：第一个 delta 到达即应渲染
first_delta = json.loads(chunks[0].strip()[len("data:"):])["delta"]
print("first delta:", first_delta)
assert first_delta == full[:3]
print("流式校验通过：增量可拼回全量")
# 预期输出:
# sse wire 首行: data: {"delta": "与外部"}
# sse lines: 6 或 7（取决于 chunk_size 与全量长度）
# rebuilt: 与外部世界的集成是现代后端的必修课。
# first delta: 与外部
# 流式校验通过：增量可拼回全量
```

文件 `book/part4_advanced_engineering/chapter09_external_integration/demo_llm_structured.py`（结构化输出的校验与修复）：

```{code-cell} ipython3
# 文件 book/part4_advanced_engineering/chapter09_external_integration/demo_llm_structured.py
import json
from m2t.llm import LLMClient, map_llm_error

# 模拟：LLM 的结构化外壳 + 自由文本内核
def fake_structured_generate(transcript: str) -> str:
    """本地仿真结构化生成：返回 JSON 字符串，无网络。"""
    data = {
        "title": "周会纪要",  # 标题为固定示例，非时间表述
        "summary": transcript[:20] + "… 核心是外部集成。",
        "action_items": [
            {"owner": "Alice", "task": "整理 ASR 接入文档"},
            {"owner": "Bob", "task": "实现 SSE 流式渲染"},
        ],
        "duration_hint": 1200,
    }
    return json.dumps(data, ensure_ascii=False)

def validate_minutes(obj: dict) -> list[str]:
    """校验结构化纪要，返回错误列表（空即通过）。"""
    errs = []
    if not isinstance(obj.get("title"), str) or not obj["title"]:
        errs.append("title 缺失或非字符串")
    if not isinstance(obj.get("summary"), str):
        errs.append("summary 非字符串")
    if not isinstance(obj.get("action_items"), list):
        errs.append("action_items 非列表")
    else:
        for i, it in enumerate(obj["action_items"]):
            if not isinstance(it, dict) or "owner" not in it or "task" not in it:
                errs.append(f"action_items[{i}] 缺字段")
    return errs

# 1) 正常路径：生成 -> 解析 -> 校验
raw = fake_structured_generate("本次会议讨论了与外部世界的集成，涉及 ASR 与 LLM。")
print("raw json:", raw[:60], "...")
obj = json.loads(raw)
errs = validate_minutes(obj)
print("validate:", "通过" if not errs else errs)
assert not errs
print("title:", obj["title"], "| items:", len(obj["action_items"]))

# 2) 异常路径：模型偶发吐出截断 JSON（流式中常见）
truncated = raw[:50]  # 人为截断
try:
    json.loads(truncated)
    print("unexpected: truncated should fail")
except json.JSONDecodeError as e:
    safe = map_llm_error(e)
    print("truncated safe:", safe)
    assert "sk-" not in safe
    # 本地修复策略：丢弃本次增量或等待下一个 delta，而非直接入库
    print("修复策略: 等待更多 delta 再解析，或重试一次生成")

# 3) 展示 LLMClient 的存在即契约：真实调用时只需替换 fake 为 client.generate
client = LLMClient(timeout=60, max_retries=2)
print("client ready:", client.timeout == 60 and client.max_retries == 2)
print("结构化校验通过：先校验再入库，不让脏数据污染下游")
# 预期输出:
# raw json: {"title": "周会纪要", "summary": "本次会议讨论了与外部...
# validate: 通过
# title: 周会纪要 | items: 2
# truncated safe: LLM 调用失败，请检查服务可用性或联系管理员
# 修复策略: 等待更多 delta 再解析，或重试一次生成
# client ready: True
# 结构化校验通过：先校验再入库，不让脏数据污染下游
```

> **工程启示**：把 LLM 当作“不可靠的外部服务”而非“确定性函数”——所有输出先校验、流式先拼后判、失败走脱敏与重试。MeetingToText 的真实链路中，`backend/app/services/llm.py` 的 `generate` 与前端的 `EventSource` 即是该契约的两端。
