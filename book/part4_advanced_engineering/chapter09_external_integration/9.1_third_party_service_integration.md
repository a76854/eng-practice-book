# 第三方服务集成模式

> 集成外部服务的本质不是“调通一次”，而是“在网络不可靠、对方限流、我方重试可能放大故障”的前提下，依然给出可观测、可重试、可降级的确定性行为。

## SDK 还是裸 HTTP 客户端

**直觉类比**：SDK 像“带说明书的专用插头”，已把签名、序列化、分页等细节包好；裸 HTTP（如 `httpx`/`requests`）像“万能插座”，灵活但每根线都要自己接。

| 维度 | SDK（如 `openai`） | 裸 HTTP 客户端 |
| --- | --- | --- |
| 协议细节 | 封装鉴权头、重试、SSE 解析 | 需手写 header、query、body、签名 |
| 升级成本 | 跟随上游版本，需关注 breaking change | 自行控制，但需自测兼容性 |
| 可测试性 | 可注入 fake client（见 `m2t.llm.LLMClient` 的懒创建） | 可用 `httpx.MockTransport` 或录制回放 |
| 适用场景 | 对方提供官方 SDK 且行为稳定 | 私有协议、极简调用、或需统一自家 HTTP 层 |

**选型原则**：有官方维护的 SDK 且需处理流式、分页、错误码映射时优先 SDK；仅一两个端点、需统一观测与超时策略时，用自家薄封装的 HTTP 客户端。

> **工程启示**：无论 SDK 还是 HTTP，都要在“边界处”收敛配置——超时、重试、鉴权、错误脱敏集中在一处模块，而不是散落在每个业务函数中。`m2t/llm.py` 即是该思想的最小落地。

## 超时、重试与幂等

- **超时（timeout）**：区分“连接超时”与“读取超时”。LLM 生成可能 20–60 秒才完成，`m2t.llm.LLMClient` 默认 `timeout=60` 即兼顾首字时延与整体完成。
- **重试（max_retries）**：仅对可重试错误（网络抖动、429 限流、5xx）做指数退避；对 4xx（鉴权、参数错）不应重试。`max_retries=2` 意味着“1 次尝试 + 2 次重试”共 3 次机会。
- **幂等键**：若外部写入（创建任务、扣费）不可自动去重，需由调用方传入 `Idempotency-Key`，服务端用该键做去重表。

```bash
# 依赖说明：本书正文仅依赖 m2t（已含 openai 可选依赖的最小契约）
# 如需真实网络演示，请在隔离环境中执行，切勿在 code-cell 中发起真实请求
.venv/bin/python -c "from m2t.llm import LLMClient; print(LLMClient().timeout)"
```

## 熔断与舱壁

当对方持续失败时，无节制重试会把“我方的线程/连接池”也拖垮。**熔断（circuit breaker）**的三个状态：

1. **关闭**：正常放行，统计失败率。
2. **打开**：失败率超阈值，快速失败一段时间，不再发请求。
3. **半开**：探活少量请求，成功则关闭，失败则重回打开。

**舱壁（bulkhead）**则用隔离的线程池/连接池把“外部调用”与“内部计算”分舱，避免一舱进水全船沉没。

> **中立性说明**：重试与熔断无银弹。重试适合瞬态故障，熔断适合持续故障；二者常组合使用，并配合告警与日志。

## 错误脱敏：绝不透传原文

`m2t.llm.map_llm_error` 的核心契约是**不拼接任何异常原文**——固定中文文案返回给前端，原始堆栈仅由服务端日志记录。这避免了把 `sk-xxx`、`base_url` 或内部堆栈泄漏给用户。

环境差异体现在日志与密钥管理：密钥通过 `export OPENAI_API_KEY=sk-...` 注入；路径统一用 `/` 书写，通过 `pathlib.Path` 处理。

## 可运行示例：用 m2t.llm 演示超时、重试与脱敏

示例：LLM 超时、重试与脱敏：

```{code-cell} ipython3
from m2t.llm import LLMClient, map_llm_error

# 1) 构造客户端：对齐 MeetingToText 的生产默认值
client = LLMClient(
    base_url="https://api.example.com/v1",
    api_key="sk-demo-***",
    model="gpt-4o-mini",
    timeout=60,
    max_retries=2,
)
print("base_url:", client.base_url)
print("model:", client.model)
print("timeout:", client.timeout)
print("max_retries:", client.max_retries)
assert client.timeout == 60
assert client.max_retries == 2

# 2) 脱敏：即使原始异常含敏感信息，也只返回固定文案
sensitive = RuntimeError("request to https://api.example.com failed, key=sk-abc123")
safe = map_llm_error(sensitive)
print("safe:", safe)
assert "sk-abc123" not in safe
assert "https://api.example.com" not in safe

# 3) 鉴权/限流/超时的差异化文案（在未安装 openai 时均回退为通用文案，行为确定）
print("generic mapping ok:", "LLM" in safe or "服务" in safe)
# 预期输出:
# base_url: https://api.example.com/v1
# model: gpt-4o-mini
# timeout: 60
# max_retries: 2
# safe: LLM 调用失败，请检查服务可用性或联系管理员
# generic mapping ok: True
```

示例（重试与熔断的本地仿真，无网络）：

```{code-cell} ipython3
import time
from m2t.llm import LLMClient, map_llm_error

class FakeTransientError(RuntimeError):
    pass

class FakeLLMClient(LLMClient):
    """用内存计数模拟瞬态失败：前 N 次抛错，之后成功。"""
    def __init__(self, fail_times: int = 2, **kw):
        super().__init__(**kw)
        self.fail_times = fail_times
        self.calls = 0

    def generate(self, system_prompt: str, user_message: str, **kw) -> str:
        self.calls += 1
        if self.calls <= self.fail_times:
            raise FakeTransientError(f"transient {self.calls}")
        return f"[{system_prompt[:8]}] {user_message[:12]} => ok (try {self.calls})"

def call_with_retry(client: FakeLLMClient, prompt: str, retries: int = 2) -> str:
    last_exc: Exception | None = None
    for attempt in range(retries + 1):
        try:
            return client.generate("system: 摘要", prompt)
        except Exception as e:
            last_exc = e
            # 指数退避：本地仿真不真实 sleep，仅演示计算
            backoff = 0.1 * (2 ** attempt)
            _ = backoff
            if attempt == retries:
                break
    # 统一脱敏
    assert last_exc is not None
    return map_llm_error(last_exc)

# 演示：2 次瞬态失败 + 第 3 次成功
c1 = FakeLLMClient(fail_times=2, timeout=5, max_retries=2)
ok = call_with_retry(c1, "本次会议讨论了外部集成", retries=2)
print(ok)
assert "ok (try 3)" in ok
print("calls:", c1.calls)

# 演示：超过重试仍失败 -> 脱敏文案而非原文
c2 = FakeLLMClient(fail_times=5, timeout=5, max_retries=2)
msg = call_with_retry(c2, "会失败的调用", retries=2)
print("fail safe:", msg)
assert "transient" not in msg
print("熔断提示: 若 fail safe 连续出现，调用方应打开熔断并告警，而非继续重试")

# 额外：展示 LLMClient 的 fake 注入点——测试中可绕过真实 openai
fake = FakeLLMClient(fail_times=0)
fake._client = object()  # 注入任意对象，避免懒创建时 import openai
print("fake client injected:", fake._client is not None)
# 预期输出:
# [system: ] 本次会议讨论了外部 => ok (try 3)
# calls: 3
# fail safe: LLM 调用失败，请检查服务可用性或联系管理员
# 熔断提示: 若 fail safe 连续出现，调用方应打开熔断并告警，而非继续重试
# fake client injected: True
```

> **小结**：本节把“如何与第三方服务打交道”收敛为三件套——在边界处统一配置（`LLMClient`）、对可重试错误做有限重试、对不可重试错误快速失败并脱敏；当失败持续时，用熔断保护自身。下一节将该模式落到语音识别这一具体外部能力上。
