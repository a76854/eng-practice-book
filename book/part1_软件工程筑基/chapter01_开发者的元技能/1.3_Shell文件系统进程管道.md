# Shell、文件系统、进程与管道

> Shell 是工程师的“第二编辑器”。理解文件系统、进程与管道，不是为了背命令，而是为了获得一种可组合的文本思维——把复杂任务拆成可串联的小工具。

## 文件系统：一切皆路径

以 MeetingToText 为例，`data/uploads`、`data/temp`、`data/meetingtotext.db` 的分层本身就是领域建模：

```
data/
  uploads/      # 用户上传的原始音频（输入）
  temp/         # 转写过程中的临时切片（中间产物）
  meetingtotext.db  # 任务与设置的持久化（状态）
```

关键直觉：

- **路径是接口**：`Path("data/uploads/a.wav")` 在 Python 与 Shell 中指向同一资源，跨平台差异仅在分隔符（`/` vs `\`）与大小写敏感性（Linux 敏感、macOS 默认不敏感、Windows 不敏感）。
- **文件是字节流**：`cat`、`less`、`head` 只是按不同窗口观察同一字节流，Python 的 `open(..., "rb")` 亦然。

```bash
# 列出目录（macOS / Linux）
ls -lh data/uploads
# Windows 等价
dir data\uploads

# 递归查找音频文件（macOS / Linux）
find data -name "*.wav" | head
# Windows PowerShell 等价
Get-ChildItem -Recurse -Filter *.wav | Select-Object -First 5

# 查看路径分隔符差异（Python 自动处理）
python -c "from pathlib import Path; print(Path('a/b/c'))"
```

## 进程：程序的运行实例

每个 `python -m backend.app.server` 或 `npm run dev` 都是一个进程，拥有独立的 PID、环境变量、打开的文件描述符。理解进程对调试至关重要：

- `ps aux | grep uvicorn`（macOS / Linux）或 `tasklist | findstr uvicorn`（Windows）查看进程是否存在。
- 环境变量是进程的“上下文”：`MTT_DATA_DIR=./data python cli.py` 只影响该次启动的子进程，不会污染全局。
- 退出码是进程的“返回值”：`0` 表示成功，非 `0` 表示失败，`&&` 与 `||` 基于此做流程控制。

```bash
# 启动后端（全平台，MeetingToText 真实命令）
meetingtotext serve --port 8000 --log-level INFO

# 进程管理（macOS / Linux）
ps aux | grep meetingtotext
kill <PID>

# Windows
tasklist | findstr meetingtotext
taskkill /PID <PID> /F
```

## 管道：把大问题切成小工具

管道 `|` 的哲学是：**每个工具只做一件事，把文本流作为统一接口**。

```bash
# 统计项目中 Python 文件行数（macOS / Linux）
find . -name "*.py" | xargs wc -l | sort -n | tail

# Windows PowerShell 等价（对象管道，而非文本管道）
Get-ChildItem -Recurse -Filter *.py | ForEach-Object { (Get-Content $_.FullName).Count } | Sort-Object | Select-Object -Last 5
```

管道的威力在于**可组合性**：`find` 产生路径流 → `xargs` 转为参数 → `wc -l` 统计 → `sort` 排序 → `tail` 取尾部。每个环节都可独立替换与测试。

## 可运行示例：用 Python 复刻管道、glob 与进程思想

以下示例不依赖真实 Shell 进程，全部用 Python 标准库复刻其思想，保证在 MyST 的受限执行环境中可复现。

文件 `book/part1_软件工程筑基/chapter01_开发者的元技能/demo_pipe_glob.py`（glob + 管道式处理）：

```{code-cell} ipython3
# 文件 book/part1_软件工程筑基/chapter01_开发者的元技能/demo_pipe_glob.py
import pathlib, re, itertools, tempfile

# 1) 用 tempfile 构造一个微型“文件系统”，模拟 find + grep 管道
with tempfile.TemporaryDirectory() as td:
    root = pathlib.Path(td)
    # 创建 5 个模拟音频与文本文件
    for name in ["a.wav", "b.mp3", "c.txt", "d.wav", "e.WAV"]:
        (root / name).write_text("dummy")

    # 2) glob 等价于 find . -name "*.wav"（大小写不敏感需额外处理）
    # pathlib 的 glob 在 Linux 上大小写敏感，需手动归一
    all_files = list(root.rglob("*"))
    wav_files = [p for p in all_files if p.suffix.lower() == ".wav"]
    print("found wav (case-insensitive):", sorted(p.name for p in wav_files))

    # 3) 管道式处理：过滤 -> 映射 -> 排序（复刻 Shell 管道）
    # 等价于 find . -name "*.wav" | xargs -I{} basename {} | sort
    pipeline = (
        p.name.lower()
        for p in wav_files
    )
    sorted_names = sorted(pipeline)
    print("pipeline sorted:", sorted_names)

    # 4) 正则过滤，等价于 grep -i "^[ad]"（仅匹配文件名首字母）
    pattern = re.compile(r"^[ad]", re.I)
    matched = [n for n in sorted_names if pattern.search(n)]
    print("grep ^[ad]:", matched)
    assert len(wav_files) == 3
    assert matched == ["a.wav", "d.wav"]
# 预期输出:
# found wav (case-insensitive): ['a.wav', 'd.wav', 'e.WAV']
# pipeline sorted: ['a.wav', 'd.wav', 'e.wav']
# grep ^[ad]: ['a.wav', 'd.wav']
```

文件 `book/part1_软件工程筑基/chapter01_开发者的元技能/demo_process_env.py`（进程环境与退出码思想）：

```{code-cell} ipython3
# 文件 book/part1_软件工程筑基/chapter01_开发者的元技能/demo_process_env.py
import os, subprocess, sys, tempfile, pathlib, json

# 演示 1：子进程继承环境变量（复刻 MTT_DATA_DIR 的用法）
env = os.environ.copy()
env["MTT_DATA_DIR"] = "/tmp/demo_data"
# 用 Python 子进程打印环境变量，不依赖 shell
result = subprocess.run(
    [sys.executable, "-c", "import os; print(os.getenv('MTT_DATA_DIR'))"],
    capture_output=True, text=True, env=env
)
print("child env MTT_DATA_DIR:", result.stdout.strip())
print("exit code:", result.returncode)
assert result.stdout.strip() == "/tmp/demo_data"
assert result.returncode == 0

# 演示 2：用 Python 实现管道（不依赖 shell=True）
# 等价于 echo "hello world" | tr a-z A-Z （此处用 Python 复刻 tr）
p1 = subprocess.Popen([sys.executable, "-c", "print('hello world')"], stdout=subprocess.PIPE, text=True)
p2 = subprocess.Popen([sys.executable, "-c", "import sys; print(sys.stdin.read().strip().upper())"],
                      stdin=p1.stdout, stdout=subprocess.PIPE, text=True)
p1.stdout.close()
out, _ = p2.communicate()
print("pipe result:", out.strip())
assert out.strip() == "HELLO WORLD"
# 预期输出:
# child env MTT_DATA_DIR: /tmp/demo_data
# exit code: 0
# pipe result: HELLO WORLD
```

文件 `book/part1_软件工程筑基/chapter01_开发者的元技能/demo_m2t_audio_pipe.py`（把管道思想用于 MeetingToText 音频流水线）：

```{code-cell} ipython3
# 文件 book/part1_软件工程筑基/chapter01_开发者的元技能/demo_m2t_audio_pipe.py
import tempfile, pathlib, numpy as np
from m2t.audio import resample_audio

# 构造 1 秒 440Hz 正弦波（16kHz 采样），模拟“文件读取 -> 重采样 -> 归一”管道
sr_orig = 48000
sr_target = 16000
t = np.linspace(0, 1, sr_orig, endpoint=False, dtype=np.float32)
samples = (0.5 * np.sin(2 * np.pi * 440 * t)).astype(np.float32)

# 管道式处理：重采样（复刻 Shell 中 sox / ffmpeg 的重采样步骤）
resampled = resample_audio(samples, sr_orig, sr_target)
print(f"orig: {samples.shape[0]} samples @ {sr_orig}Hz")
print(f"resampled: {resampled.shape[0]} samples @ {sr_target}Hz")
# 验证：若安装 librosa 则长度约为原来的 1/3，否则回退为原长
try:
    import librosa  # type: ignore
    has_librosa = True
except ImportError:
    has_librosa = False
if has_librosa:
    assert 15000 < resampled.shape[0] < 17000
else:
    assert resampled.shape[0] == samples.shape[0]
print("resampled dtype:", resampled.dtype)
print("has_librosa:", has_librosa)
# 预期输出:
# orig: 48000 samples @ 48000Hz
# resampled: ~16000 samples @ 16000Hz（或 48000 若无 librosa）
# resampled dtype: float32
# has_librosa: True/False
```

> **可移植性要点**：涉及路径时优先使用 `pathlib.Path`；涉及进程时用 `subprocess.run(..., capture_output=True, text=True)` 而非 `shell=True`；涉及管道时用 Python 生成器表达式复刻“流式”语义。三者都能在 Windows / macOS / Linux 上获得一致行为，详见 [1.4 Python 自动化脚本](1.4_Python自动化脚本.md) 的封装实践。
