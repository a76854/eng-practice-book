# 类型系统与防御性编程

> 如果把动态类型比作“口头约定”，类型标注就是“书面合同”——口头约定灵活但易生歧义，书面合同让协作双方在动手前就对齐了形状与边界。

## 为什么需要类型

Python 的灵活以“运行时才暴露形状错误”为代价。MeetingToText 的真实坑点往往不在算法，而在边界形状：`normalize_result` 收到 `None` 而非 `list`、`TaskStore.get` 返回 `None` 却被直接取下标、`export` 的 `task` 既可能是 `dict` 也可能是对象。类型标注的价值在于**把这些形状从“运行时才发现”提前到“编辑期就检查”**。

类型系统不保证逻辑正确，但能把一大类“传错形状、用错空值、拼错字段”在提交前拦住。

## Python 类型标注：最小可用子集

```python
# 文件 m2t/audio.py 的真实签名（节选）
from pathlib import Path
import numpy as np

def load_audio(path: str | Path) -> tuple[np.ndarray, int]: ...
def resample_audio(samples: np.ndarray, orig_sr: int, target_sr: int) -> np.ndarray: ...

# 文件 m2t/store.py 的真实签名（节选）
class TaskStore:
    def get(self, task_id: str) -> dict[str, str] | None: ...
    def create(self, task_id: str, filename: str, status: str = "pending", full_text: str = "") -> None: ...
```

关键构件（按需选用，不必一次学全）：

- **基本标注**：`str`、`int`、`float`、`bool`、`None`；函数签名标注参数与返回值。
- **联合与可选**：`str | None`（Python 3.10+）等价于 `Optional[str]`，表示“可能为空”。
- **容器泛型**：`list[dict[str, Any]]`、`dict[str, str]` 精确描述集合形状。
- **路径与数组**：`str | Path` 兼容两种调用方，`np.ndarray` 需配合 `numpy` 存根。
- **Any 的克制使用**：`Any` 表示“暂不约束”，应在边界处收窄，而非全程放行。

> **跨平台提示**：`Path` 自动处理 `/` 与 `\` 差异，标注 `str | Path` 时函数内部统一用 `Path(path)` 归一，再做 `str(p)` 传递给底层库。

## `mypy` 严格模式：把约定变成检查

`pyproject.toml` 已声明 `mypy` 配置：

```toml
[tool.mypy]
python_version = "3.12"
warn_unused_ignores = true
ignore_missing_imports = false
strict = false

[[tool.mypy.overrides]]
module = ["funasr.*", "torch.*", "librosa.*", "soundfile.*", "numpy.*", "openai.*"]
ignore_missing_imports = true
```

- `strict = false` 是教学仓的当前默认值，适合渐进引入类型。
- 严格模式（`mypy --strict`）会同时开启 `disallow_untyped_defs`、`warn_return_any`、`no_implicit_optional` 等检查，要求所有函数都有完整标注、无隐式 `Any`。
- 对缺失存根的第三方库（如 `soundfile`、`librosa`）通过 `overrides` 放行，避免误报。

```bash
# 单文件检查（macOS / Linux / Windows 通用，假设已 pip install -e ".[dev]"）
.venv/bin/mypy m2t/audio.py
# 严格模式抽检
.venv/bin/mypy --strict m2t/store.py
# Windows 需用
.venv\Scripts\mypy.exe m2t/store.py
```

> **中立性说明**：有数据说数据，无数据说 trade-off。`mypy` 的严格模式能捕获更多形状错误，但会增加标注成本与初期噪声。团队是否开启 `strict` 取决于“协作规模 × 缺陷成本”与“标注维护成本”的权衡；教学建议从“新文件必须有标注、旧文件渐进补齐”开始。

## 防御性编程：让非法状态不可表示

类型解决“形状对不对”，防御性编程解决“值合不合法、失败早不早”：

1. **在边界校验**：对外输入（CLI 参数、HTTP 请求、文件路径）在入口处一次性校验，失败即抛 `ValueError` / `FileNotFoundError`，不让脏数据流入深层。
2. **尽早失败（Fail Fast）**：`TaskStore.get` 返回 `None` 时，调用方应在取用前 `if row is None: raise`，而非在下游 `row["filename"]` 才触发 `TypeError`。
3. **收窄而非放行**：用 `if isinstance(x, dict)`、`if seg is None` 等收窄分支，避免全程 `Any`。
4. **不可表示优于运行时检查**：用 `Literal["txt", "srt", "md"]` 约束导出格式，用 `dataclass` 固定任务形状，比“字符串随意传、运行时再判断”更早暴露错误。

## 可运行示例：类型标注与防御性校验

文件 `book/part1_软件工程筑基/chapter02_构筑代码质量的护城河/demo_typing_defensive.py`：

```{code-cell} ipython3
# 文件 book/part1_软件工程筑基/chapter02_构筑代码质量的护城河/demo_typing_defensive.py
from __future__ import annotations
from pathlib import Path
from typing import Any, get_type_hints
import tempfile, pathlib
import numpy as np
from m2t.store import TaskStore
from m2t.asr import normalize_result

# 1) 类型标注：让形状在签名中可见
def format_segment(seg: dict[str, Any]) -> str:
    """将归一段格式化为可读字符串，标注输入/输出形状。"""
    speaker: str = str(seg.get("speaker") or "")
    text: str = str(seg.get("text") or "")
    start: float = float(seg.get("start") or 0)
    end: float = float(seg.get("end") or 0)
    if speaker:
        return f"[{speaker} {start:.1f}-{end:.1f}s] {text}"
    return f"[{start:.1f}-{end:.1f}s] {text}"

print("hints:", get_type_hints(format_segment))
seg = {"speaker": "说话人1", "text": "类型让协作更安全", "start": 0.5, "end": 2.0}
print(format_segment(seg))
# 预期输出:
# hints: {'seg': dict[str, Any], 'return': <class 'str'>}
# [说话人1 0.5-2.0s] 类型让协作更安全

# 2) 防御性编程：在边界处校验并尽早失败
def create_task_defensive(store: TaskStore, task_id: str, filename: str) -> dict[str, str]:
    if not task_id or not task_id.strip():
        raise ValueError("task_id 不能为空")
    if not filename or not filename.strip():
        raise ValueError("filename 不能为空")
    # 防御：不允许路径穿越（简化示意）
    if ".." in filename or filename.startswith("/"):
        raise ValueError(f"非法 filename: {filename}")
    store.create(task_id, filename)
    row = store.get(task_id)
    if row is None:  # 防御：显式处理 None 分支
        raise RuntimeError(f"创建后未找到任务: {task_id}")
    return row

with tempfile.TemporaryDirectory() as td:
    db = pathlib.Path(td) / "defensive.db"
    store = TaskStore(db)
    row = create_task_defensive(store, "t1", "meeting.wav")
    print("created:", row["filename"], row["status"])
    # 触发防御分支
    try:
        create_task_defensive(store, "", "a.wav")
    except ValueError as e:
        print("caught expected:", e)
    try:
        create_task_defensive(store, "t2", "../evil.wav")
    except ValueError as e:
        print("caught expected:", e)
    assert row["filename"] == "meeting.wav"
# 预期输出:
# created: meeting.wav pending
# caught expected: task_id 不能为空
# caught expected: 非法 filename: ../evil.wav

# 3) 结合 m2t 真实 API：normalize_result 的空值防御
empty: list[dict[str, Any]] = normalize_result([])
print("empty result:", empty)
assert empty == []
# 传入非预期形状，函数内部通过 isinstance 防御，返回空列表而非抛错
print("defensive normalize on [] ->", empty)
# 预期输出:
# empty result: []
# defensive normalize on [] -> []
```

文件 `book/part1_软件工程筑基/chapter02_构筑代码质量的护城河/demo_mypy_strict.py`（用 `mypy` API 演示严格检查如何捕获形状错误）：

```{code-cell} ipython3
# 文件 book/part1_软件工程筑基/chapter02_构筑代码质量的护城河/demo_mypy_strict.py
import tempfile, pathlib, textwrap, sys

# 构造两份临时源码：一份正确标注，一份故意遗漏标注/传入错误形状
good_code = textwrap.dedent('''
def add(a: int, b: int) -> int:
    return a + b
x: int = add(1, 2)
''')

bad_code = textwrap.dedent('''
def add(a, b):  # 未标注
    return a + b
x: int = add("1", "2")  # 传入错误形状，若有标注应被检出
''')

def run_mypy(code: str, strict: bool = False) -> tuple[int, str]:
    try:
        from mypy import api
    except ImportError:
        return 0, "mypy 未安装，跳过演示（pip install mypy 后可复现）"
    with tempfile.TemporaryDirectory() as td:
        p = pathlib.Path(td) / "sample.py"
        p.write_text(code, encoding="utf-8")
        args = [str(p)]
        if strict:
            args.insert(0, "--strict")
        # 兼容 overrides：忽略缺失导入，仅检查本文件形状
        result = api.run(args)
        # result 为 (stdout, stderr, exit_status)
        stdout, stderr, exit_status = result
        return exit_status, (stdout + stderr).strip()

for label, code in [("good", good_code), ("bad", bad_code)]:
    status, out = run_mypy(code, strict=True)
    print(f"[{label}] exit={status}")
    print(out[:500] if out else "(no mypy errors)")
    print("---")

# 额外演示：m2t 的真实签名在 strict 下的表现（仅作体感，不作失败判定）
status, out = run_mypy("from m2t.store import TaskStore\ns = TaskStore(':memory:')\nprint(s.get('x'))\n", strict=False)
print("m2t store import check exit:", status)
# 预期输出:
# [good] exit=0  (no mypy errors)
# [bad] exit=1  包含 Missing type parameters / incompatible type 等提示
# m2t store import check exit: 0
```

> **工程启示**：类型与防御性编程是“同一枚护城河的两块砖”——类型让非法形状不可表示，防御性校验让非法取值尽早失败。二者配合，才能把 MeetingToText 这类“输入多源、形状多变”的流水线收敛到可预期的契约上。后续 [2.2 静态检查与代码风格](2.2_静态检查与代码风格.md) 将在形状之外，继续用自动化规则统一风格与低级缺陷。
