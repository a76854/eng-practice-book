# 全书写作契约（STYLE.md）

> 本文档是《python编程工程实践》全书写作的唯一权威契约。任何章节作者在开工前只需阅读本文档，无需额外访谈即可按约交付。后续章节迭代以本文为准，本文未规定之处再行补充。

## 1 角色与文风

- 角色定位：资深软件工程教材作者，兼具一线大厂后端工程经验。写作视角是"老师傅带新人"，既懂教材体系，也懂线上真实坑点。
- 语言风格：专业但不晦涩。概念必须讲透、术语必须准确，同时多用生活化类比帮助理解。避免堆砌黑话，必要时先给直觉再给定义。
- 受众假设：面向本科大学生，已有基础编程能力，但对工程化、协作、后端全链路不熟悉。所有关键概念循序渐进，不跳步，不预设"显然"。

## 2 全书结构

- 全书 = 前言 + 正文 13 章 + 实验指导书（6 个实验）+ 附录。
- **无“篇”层级**：章直接挂目录顶层，由 MyST 自动编号为 1~13；节编号为 `章.节`（如 `5.1`），小节为 `章.节.小节`（三级，勿写成四级）。
- 编排逻辑：从开发者元技能、代码质量护城河，贯通后端全景、HTTP 与 RESTful、数据持久化、并发与性能，再到综合实战、前端协作、外部集成、健壮性与安全、部署与 CI/CD。以通用教学案例串联各章。
- 13 章依次为：开发者的元技能、构筑代码质量的护城河、后端开发概览、HTTP 与 RESTful 架构、数据持久化、并发模型与性能工程、综合实战（文档查询的分层实现）、前端开发概况与工程化演进、Vue3 核心机制与状态设计、前后端通信与联调、与外部世界的集成、健壮性与安全底线、部署容器化与持续集成。
- 正文与实验解耦：正文只负责讲透原理与可运行示例，动手与评分完全由实验指导书承担。

## 3 章节结构模板（每节固定骨架）

每个正文小节按以下固定骨架展开，顺序不得改动：

1. **标题**：清晰的主题名（编号由 MyST 自动生成，渲染后形如“6.1 并发、并行与异步”；写作时只写主题，不手写编号）。小节标题**不要用“术语：一句话定义”的公式模板**（如“Node.js：前端的运行时与工具宿主”“组合式 API：按关注点组织代码”），这类标题读起来像 AI 在枚举概念。标题应抓住本节主线：一个具体短句、一个动作主张或一个名词性主题，而不是提问句，也不是给术语贴一句定义标签。
2. **承上导言（1 段）**：标题之后紧跟一段说明，点明本节在整章中的位置与目的，承上启下，不提前透露具体实现。
3. **核心概念（分节展开）**：每个概念用“定义 + 对比表格 + 代码示例”的结构。表格用于对比（并发 vs 并行、阻塞 vs 非阻塞、三种模型等），代码示例控制在 15-20 行以内。
4. **代码演示**：优先使用 `code-cell`，且每个 code-cell 只做一件事。不写预期输出注释。以声明式配置为主的小节（Dockerfile、Compose、CI 工作流等），示例可用对应语言的展示围栏承载，并在正文说明本地怎样校验；这类小节不强制 `code-cell`，也不为凑数硬加演示。
5. **本节小结（3-5 点）**：总结核心结论，不写金句，也不写口号式收尾。

## 4 写作风格规则

### 用词与语气

- 不用 emoji（AI 味太重）。
- 不用口语化表达（"咱们"、"大家"、"其实"等）。
- 不使用破折号“——”。
- 不用直角引号「」，正文引用或强调一律用弯双引号“”或不加引号。
- 不用感叹号堆砌。
- 小节标题不用“术语：一句话定义”的公式模板（见第 3 节“标题”规范）。
- 不用“第 A 章讲 X、第 B 章讲 Y、本章讲 Z”这类章节预告公式，也不用“缝合”“把两端接起来”一类比喻铺陈导言；承上启下直接说清本节要回答什么。
- 正文内如需类比保持克制，不用口语化比喻与网络用语（如“翻车”“玄学”“帮手”），不用“才是真正的交付”一类口号式判断。

### 对比与表格

- 优先用表格做对比，不要大段文字罗列。
- 表格列数控制在 3-5 列，列名清晰（如“维度 | threading | multiprocessing | asyncio”）。
- 表格后紧跟 1-2 句总结，不要"晾"在那里。

### 代码示例

- 每个 code-cell 只演示一个概念。
- 代码块前有 1-2 句说明"这段代码演示什么"。
- 代码块后有 1-2 句观测要点或结论。
- 避免写预期输出注释——code-cell 会实际运行。
- 多个输出用 `print()`，不用 Jupyter 的隐式输出。

## 5 章节间衔接规则

- 每节开头要“承上”，用 1-2 句话回顾前一节的结论，点明本节要解决什么问题。
- 节内小节之间也要自然过渡，不突兀堆叠概念。

## 6 章级骨架 index.md 契约

每章目录下必须包含 `index.md` 作为章首页，骨架固定如下，顺序与写法不得改动：

```markdown
# 章名

> **本章学习目标**
> - 目标 1
> - 目标 2
> - 目标 3

> **为什么需要掌握本章**
> 一段话讲清本章在真实工程中的位置与价值。

> **预计理论学时**：X学时
```

- 章组成：`index.md` + 若干 `<english_name>.md` 正文小节 + 章末 `summary_and_questions.md`。章内节数量以内容需要为准，不凑数也不遗漏。
- 章标题与节标题由 MyST 自动编号，写作时不手写编号前缀。

## 7 可运行代码与围栏规范

- 可执行代码的唯一围栏是 ````{code-cell} ipython3`。所有需要在构建时真实执行的 Python 代码必须置于此围栏内，保持完整可运行。
- Shell 命令、终端示意一律使用 ````bash` 围栏，仅作展示，不参与执行。
- 配置文件（`dockerfile`、`yaml`、`json`、`toml`、`nginx`）用对应语言的围栏展示，仅作展示，不参与执行；给出声明后用一两句说明本地怎么校验它。
- 不展示显而易见或重复的样板代码。能用省略或引用说清处不贴全量；贴出的代码必须是读者需要关注、理解或运行的关键部分。
- 每个 `{code-cell} ipython3` 块应自包含或与前文块形成可执行的递进链路，避免孤立、不可运行的片段。
- 不写预期输出注释；输出一律用 `print()` 显式打印。

示例：

````markdown
下面这段代码演示如何定义一个带类型标注的函数并调用：

```{code-cell} ipython3
def hello(name: str) -> str:
    return f"hello, {name}"

print(hello("world"))
```

`print` 显式输出调用结果，构建时由 code-cell 真实执行并渲染结果。

Shell 示意：

```bash
python demo.py
```
````

## 8 章末 summary_and_questions.md 契约

- 每章章末固定文件为 `summary_and_questions.md`，不得更名或拆分。
- 文件内必须包含两节，且仅含这两节：
  1. `## 本章小结`：用要点回顾本章核心概念与工程启示，不引入新概念。
  2. `## 思考题`：若干开放讨论题，鼓励课堂或论坛讨论，无答案、不设标准解、不做评分。
- 思考题编写规则：
  - 每个思考题问一个"为什么"或"什么情况下"。
  - 不止问概念，要问工程判断。
  - 题目之间有层次：从概念辨析 → 选型判断 → 工程权衡 → 综合设计。
  - 每题控制在 100-150 字，不超 200 字。
  - 不用"请列举"，用"请分析"、"请判断"、"请设计"。

## 9 严谨性与中立性

- 涉及技术选型、性能对比、安全取舍时，必须给出客观依据，如官方文档、基准数据、适用场景与代价分析，不偏袒任一技术栈。
- 有数据说数据，无数据说 trade-off。避免绝对化表述，明确前置条件与边界。

## 10 环境约定（Linux-only）

- 全书所有命令行、路径、环境相关示例均面向 **Linux**（以 Ubuntu / Debian 系为例），统一使用 `bash` 与 `/` 分隔符，不再提供多平台对照。
- 虚拟环境统一为 `.venv`，激活命令为 `source .venv/bin/activate`，解释器路径为 `.venv/bin/python`，代码中涉及路径一律用 `pathlib.Path` 与 `/` 书写。
- 不假设读者使用其他操作系统，关键操作仅给出 Linux 写法；如需强调可移植性，通过 Python 抽象（`pathlib` / `shutil` / `subprocess` 列表形式）说明，而非罗列多平台命令。

## 11 目录、命名与引用

- 正文小节文件命名：`<english_name>.md`（全英文小写下划线，不带编号前缀），如 `engineering_project_structure.md`、`fastapi_routing.md`。章末固定项为 `summary_and_questions.md`。
- 章与节的编号由 `myst.yml` 的 `numbering: { title: true, headings: true }` 统一管理；文件名与正文均不手写编号。
- 跨章引用一律使用相对链接（从引用文件所在目录出发），如 `[](../concurrency_perf/async_programming_core.md)`（兄弟章之间用 `../` 上跳一级），不使用绝对路径或硬编码 URL。
- 全书命令与路径统一为 Linux 语法。

## 12 明令禁止

以下内容不得出现在正文中。如需提及，仅可在本节"禁止清单"内作为负面示例出现，正文与小节不得以任何形式设立相关栏目：

- 禁止栏目：习题、延伸挑战、参考答案、判卷。
- 禁止时间表述：周 N、第 N 周 等以教学周为单位的进度表述。
- 禁止在正文中提供评分标准、判分脚本或标准答案。正文的思考题不设答案，不做判卷。
- 归口说明：上述禁止的习题与作业由实验指导书承担，实验指导书提供任务说明与验收要求，不提供起始代码或标准答案。

## 13 实验篇边界

- 练习与作业、评分由实验指导书承担，不在理论章中展开。
- 实验指导书包含 6 个按领域组织的实验；实验一、二另有数据生成脚本，其余实验由读者自行创建项目与代码。验收以演示与讨论为准。
- 理论章与实验章通过文字引导衔接，但不混排内容。

## 14 修改与迭代原则

- 每次只改一个明确的问题（如"改开头比喻"、"补充过渡段"、"调整表格"）。
- 不改上一轮已经确认通过的内容，除非用户明确要求。
- 修改后说明改动要点，便于用户确认。

- [ ] 至少 2 处示例演示（优先 code-cell，每个只做一件事，前置说明 + 后置观测；声明式配置类内容可用展示围栏，并说明本地校验方式）
- [ ] 本节小结（3-5 点，不写金句）
- [ ] 每节开头有“承上”过渡
- [ ] 没有 emoji
- [ ] 没有口语化表达
- [ ] 没有破折号“——”
- [ ] 没有预期输出注释
- [ ] 运行 `python scripts/check_style.py`：红线 0 处、频次规则不超标（见第 16 节）

## 16 反 AI 味负面模式清单（机器可校验）

本节是第 4 节风格规则的可执行化：文本读起来“AI 味重”，通常不是单句写得差，而是若干修辞模式被反复使用。以下规则由 `scripts/check_style.py` 扫描，第 15 节自检清单要求交稿前运行；退出码 0 为通过，1 为存在违规，与 `myst build --html --execute --strict` 同为门禁。

扫描口径：只统计正文。跳过 YAML frontmatter、代码围栏（含 `{code-cell}`、mermaid）、行内代码、HTML 注释与加粗斜体标记本身；`book/STYLE.md` 与 `node_modules/` 不参与扫描。

### 红线（0 容忍，出现即违规）

| 模式 | 正则 | 改法 |
|---|---|---|
| 破折号 | `——` | 改为逗号、冒号或拆成两句 |
| 直角引号 | `「」` | 用弯双引号“”或不加引号 |
| 感叹号 | `！` | 改为陈述句（代码围栏内的注释不计） |
| emoji | `☀-➿`、`U+1F000-U+1FAFF`、`U+2B00-U+2BFF` 等 | 删掉，用文字表述 |
| 口语化用词 | 咱们、大家、其实、说白了、翻车、玄学、人肉、帮手、闭门造车 | 换成书面表达 |

### 频次规则（按单个文件计数，超限即违规）

| 编号 | 模式 | 每文件上限 | 典型例子 |
|---|---|---|---|
| A | 对仗反转“不是……而是……” | 1 | “这不是性能竞赛，而是……”连续出现在多段 |
| B | 本质化收束“本质是 / 本质上是 / 本质在于” | 1 | 每段结尾都用“本质是”下定义 |
| C | 升华钩子“这正是……” | 1 | 段末反复“这正是……的钥匙/含义” |
| D | 数字排比标题 | 1 | “三种模型”“五种语言”“四个边界”式标题满篇（“第 N 步”步骤序列不计） |
| E | 拟人比喻 | 2 | “第 N 笔债”“旧账”“人走茶凉”“看门人”“逼出来”“登场”“敲门”等 |

上限的含义是“偶发可以，成串不行”：单次使用是正常修辞，同文件反复出现即构成可识别的模式。写作时若发现自己连续两段用同一句式收尾，第二段直接改写。

脚本用法：

```bash
python scripts/check_style.py            # 详细报告（文件、行号、命中原文）
python scripts/check_style.py --summary  # 只看超标文件汇总表
python scripts/check_style.py --only red # 只查红线
```

人眼仍需自查的部分（脚本无法判断）：段落长短是否均匀、每节是否都是“导言→概念→表格→小结”同一节拍、比喻整体密度、段末是否句句升华。这些见第 15 节清单。
