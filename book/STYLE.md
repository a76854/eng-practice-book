# 全书写作契约（STYLE.md）

本文档是《算法编程与工程实践》后续周 2–15 及里程碑 M1–M3 的写作契约。周 1（`week01_环境与项目骨架.md`）是风格锚，本文将锚点的规则固化为可引用的条约。

---

## 1. 章节骨架模板

每章文件 `book/weekNN_*.md` 必须按以下顺序组织，标题与锚点固定：

```markdown
---
jupytext:
  text_representation: ...
kernelspec:
  display_name: Python 3
  language: python
  name: python3
---

# 周N 标题

> 动机段（2–5 句话）：为什么学这一章、为什么现在学、与前后章的衔接。

## 学习目标
- 3–5 条可测量目标（动词用「能…」「会…」「能解释…」「能编写…」）

## 先修要求
- 列出需要的知识/工具/已完成章节，未完成的标「无」或「完成周 N」

## 正文
### N.1 … / N.2 … / …
（按需分小节，概念讲解与可运行代码交替出现）

### 改动并预测
≥3 个实验，每个实验固定三段式：
- **改什么**：一行或一段具体改动
- **预测**：运行前写下预期现象/输出/报错
- **解释**：为什么会这样（回扣正文概念）

## 习题
≥5 道，题干在正文列出；参考答案落在 `answers/weekNN/`（纯函数、可 pytest）

## 延伸挑战
开放式 1–3 题，鼓励探索，无标准答案

> 本章内容原创，概念对应 …。（原创声明句，见 §5）
```

里程碑章节（`week06_m1.md` / `week11_m2.md` / `week16_m3.md`）可将「正文」替换为「任务说明 / 提交结构 / 评分标准」，但仍保留动机、学习目标、先修、改动并预测（或等价的自测实验）、习题/延伸挑战、原创声明。

## 2. 代码约定

| 场景 | 写法 | 说明 |
|---|---|---|
| 可执行代码 | ````{code-cell} ipython3` | 唯一的可执行代码围栏；`jupyter-book build --execute` 会真实运行 |
| Shell 示意 | ` ```bash` | 仅示意，不被执行；安装命令、目录操作等用此 |
| Python 示意（不执行） | ` ```python` | 仅示意片段；若需执行必须改用 `{code-cell}` |
| 占位符 | `` {占位符}`` | 大括号包裹，如 `{API_KEY}`、`{项目根目录}` |
| 行文中的代码 | `` `code` `` | 单行内联代码 |

规则：

- 每章至少 1 个 `{code-cell} ipython3`，且在 `--execute` 下必须通过。
- Shell 命令中的路径、密钥、URL 若为示例，必须用 `{占位符}` 标注可替换部分。
- 代码注释与输出保持中文或中英对照，关键概念首次出现时标注英文原文。

## 3. 行文规则

1. **语言**：全书中文，专业术语首次出现时括注英文（如「虚拟环境（virtual environment）」）。
2. **语气**：面向大二/大三学生，直接、具体、可操作；少用抽象论述，多用「你」视角的步骤。
3. **每章必含**：动机段、3–5 条学习目标、先修要求、≥3 个「改动并预测」实验（每实验带预期与解释）、≥5 道习题（参考答案在 `answers/weekNN/`）、延伸挑战、文件尾原创声明。
4. **习题参考答案**：落在 `answers/weekNN/`，为 hermetic 纯函数题（不依赖网络/外部服务/真实文件系统），配 `test_*.py`，`pytest answers/weekNN/ -q` 必须全绿。
5. **文件尾原创声明**：每章末尾单句声明，见 §5。
6. **概念原创性**：正文中 `d2l` / `6.031` / `Crafting Interpreters` 仅以引用/链接/致谢出现，不逐字搬运原文。
7. **时效性**：不得引用过时事实（以 MeetingToText HEAD 的 `pyproject.toml` / `README.md` 为准，禁止将过时的启动方式或部署描述归于本项目现状）；
8. **锁文件**：不宣称「Python 锁文件是必需」。
9. **MyST 扩展**：可用 `colon_fence` / `dollarmath` / `linkify` / `substitution` / `tasklist`，见 `_config.yml` 的 `parse.myst_enable_extensions`。

---

## 4. 目录与引用

- 章节文件命名：`weekNN_*.md`（周号唯一锚，见 `book/_toc.yml`），`_toc.yml` 必须全命中，无 orphan。
- 章内小节用 `###` 起步（`#` 为章标题、`##` 为一级节）。
- 跨章引用用相对链接，如 `[周1 环境与项目骨架](week01_环境与项目骨架.md)`。
- 参考文献/延伸阅读单列小节或脚注，不混入正文段落。

## 5. 原创声明模板

每章文件末尾保留一句原创声明，模板：

> 本章内容原创，概念对应 MeetingToText 的 `{文件名或模块}`。

示例：

> 本章内容原创，概念对应 MeetingToText 的 pyproject.toml / README。

> 本章内容原创，算法图示参考 d2l 教学法结构，代码与表述均为原创。

> 本章内容原创，协作流程参考 6.031 课程设计，案例与习题均为原创。

要求：每章 `grep -c "原创" book/weekNN*.md` ≥1。
