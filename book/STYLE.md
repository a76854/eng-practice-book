# 全书写作契约（STYLE.md）

> 本文档是《算法编程与工程实践》全书写作的唯一权威契约。任何章节作者在开工前只需阅读本文档，无需额外访谈即可按约交付。后续章节迭代以本文为准，本文未规定之处再行补充。

## 1 角色与文风

- 角色定位：资深软件工程教材作者，兼具一线大厂后端工程经验。写作视角是“老师傅带新人”，既懂教材体系，也懂线上真实坑点。
- 语言风格：专业但不晦涩。概念必须讲透、术语必须准确，同时多用生活化类比帮助理解。避免堆砌黑话，必要时先给直觉再给定义。
- 受众假设：面向本科大学生，已有基础编程能力，但对工程化、协作、后端全链路不熟悉。所有关键概念循序渐进，不跳步，不预设“显然”。

## 2 全书结构与篇章分工

- 理论篇共 11 章（第 1 至 11 章），分属前四篇；第五篇为实验指导书，不承担理论授课。
- 编排逻辑：从开发者元技能、代码质量护城河，贯通后端全景、HTTP 与 RESTful、数据持久化、并发与性能，再到前端协作、外部集成、健壮性与安全、部署与 CI/CD。MeetingToText 作为贯穿演示项目串联各章。
- 理论章与实验章解耦：正文只负责讲透原理与可运行示例，动手与评分完全由第五篇承担。

## 3 章级骨架：index.md 契约

每章目录下必须包含 `index.md` 作为章首页，骨架固定如下，顺序与写法不得改动：

```markdown
# 第X章 章名

> **本章学习目标**
> - 目标 1
> - 目标 2
> - 目标 3

> **为什么需要掌握本章**
> 一段话讲清本章在真实工程中的位置与价值。

> **预计理论学时**：X学时
```

- 章组成：`index.md` + 若干 `<N.N>_<中文名>.md` 正文小节 + 章末 `summary_and_questions.md`。章内节数量以内容需要为准，不凑数也不遗漏。
- 章标题与节标题由 MyST 自动编号，写作时不手写编号前缀。

## 4 正文小节 .md 契约

- 正文小节文件承载核心教学内容，采取“正文讲解与可运行代码交替”的节奏。关键概念循序渐进，先动机后定义，先示例后抽象。
- 可运行代码是本书一等公民。正文中的可执行示例必须完整、可运行、可复现，读者复制即可得到相同结果。
- 代码须标注文件路径与运行预期输出。涉及多文件的示例，给出清晰的目录与文件名；单文件片段亦需说明应保存为何文件、如何运行、预期输出是什么。

## 5 可运行代码与围栏规范

- 可执行代码的唯一围栏是 ````{code-cell} ipython3`。所有需要在构建时真实执行的 Python 代码必须置于此围栏内，保持完整可运行。
- Shell 命令、终端示意一律使用 ````bash` 围栏，仅作展示，不参与执行。
- 不展示显而易见或重复的样板代码。能用省略或引用说清处不贴全量；贴出的代码必须是读者需要关注、理解或运行的关键部分。
- 每个 `{code-cell} ipython3` 块应自包含或与前文块形成可执行的递进链路，避免孤立、不可运行的片段。

示例：

````markdown
文件 `m2t/demo.py`：

```{code-cell} ipython3
def hello(name: str) -> str:
    return f"hello, {name}"

print(hello("world"))
# 预期输出: hello, world
```

Shell 示意：

```bash
python m2t/demo.py
```
````

## 6 章末 summary_and_questions.md 契约

- 每章章末固定文件为 `summary_and_questions.md`，不得更名或拆分。
- 文件内必须包含两节，且仅含这两节：
  1. `## 本章小结`：用要点回顾本章核心概念与工程启示，不引入新概念。
  2. `## 思考题`：若干开放讨论题，鼓励课堂或论坛讨论，无答案、不设标准解、不做评分。
- 思考题重在启发与辨析，不考察记忆，不设对错分。

## 7 严谨性与中立性

- 涉及技术选型、性能对比、安全取舍时，必须给出客观依据，如官方文档、基准数据、适用场景与代价分析，不偏袒任一技术栈。
- 有数据说数据，无数据说 trade-off。避免绝对化表述，明确前置条件与边界。

## 8 跨平台差异标注

- 所有命令行、路径、环境相关示例必须标注 Windows / macOS / Linux 差异，至少覆盖路径分隔符、激活虚拟环境命令等典型分歧点。
- 示例写法：`source .venv/bin/activate`（macOS / Linux）与 `.venv\Scripts\activate`（Windows）；路径示例同时说明 `/` 与 `\` 差异。
- 不假设读者操作系统，关键操作给出多平台对照或明确说明适用平台。

## 9 目录、命名与引用

- 正文小节文件命名：`<N.N>_<english_name>.md`（全英文小写下划线），如 `1.1_engineering_project_structure.md`、`4.3_fastapi_routing.md`。章末固定项为 `summary_and_questions.md`。
- 章与节的编号由 `myst.yml` 的 `numbering: { headings: true }` 统一管理，文件命名仅作排序与可读性。
- 跨章引用一律使用相对链接（从引用文件所在目录出发），如 `[](../chapter04_http_restful/4.1_http_protocol_essence.md)`，不使用绝对路径或硬编码 URL。
- 资源与样例置于 `book/samples/` 等约定目录，引用时保持相对路径一致。

## 10 明令禁止

以下内容不得出现在理论篇正文中。如需提及，仅可在本节“禁止清单”内作为负面示例出现，正文与小节不得以任何形式设立相关栏目：

- 禁止栏目：习题、延伸挑战、参考答案、判卷；以及“改动 并 预测”三段式互动栏目（此处以空格分隔以避免与历史写法连续命中，意指连续五字写法）。
- 禁止时间表述：周 N、第 N 周 等以教学周为单位的进度表述。
- 禁止在正文中提供评分标准、判分脚本或标准答案。正文的思考题不设答案，不做判卷。
- 归口说明：上述禁止的习题、作业与评分统一由第五篇实验指导书承担，实验形式为 README+starter，无答案、不做判卷。

## 11 实验篇边界

- 练习与作业、评分由第五篇实验指导书承担，不在理论章中展开。
- 实验形式为 `README + starter`，提供任务说明与起始代码，不提供答案，不做评分。验收以演示与讨论为准。
- 理论章与实验章通过文字引导衔接，但不混排内容。
- 补充：正文禁止的练习、作业与评分形态，统一在第五篇以 README+starter 承载，无答案、不做评分。

## 12 作者自检清单

提交章节前逐项确认：`index.md` 骨架完整且含学习目标、为什么需要掌握本章、预计理论学时；正文小节含可运行的 `{code-cell} ipython3` 且标注路径与预期输出；Shell 仅用 `bash` 围栏；章末为 `summary_and_questions.md` 且含本章小结与思考题；已标注 Windows / macOS / Linux 差异；跨章引用为相对链接；未出现第 10 节禁止内容。
