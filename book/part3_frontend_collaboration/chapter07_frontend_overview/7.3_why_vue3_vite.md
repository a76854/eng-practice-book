# 为何选择 Vue 3 + Vite

> 学完本节，你能回答：Vue 3 的组合式 API 解决了什么规模化痛点？Proxy 响应式与 Vue 2 的 `Object.defineProperty` 有何本质差异？Vite 为何在开发期比“先打包再服务”的传统链路更快？

## 选型不是“最潮”，是“最贴合约束”

承接 [7.2 框架三驾马车](7.2_framework_troika.md) 的客观对比，本课程为 MeetingToText 选择 **Vue 3 + Vite**，基于三条可复盘的约束判断——换一套约束，答案就该不同：

1. **受众是后端背景的学生**：需要“HTML 直觉友好、渐进增强、文档对中文友好”的框架，让后端开发者能以最小前端心智读懂目录与模板；Vue 的 SFC 模板贴近 HTML，渐进能力允许从“一个页面的一块列表”开始，而非一上来就理解 JSX 与闭包。
2. **项目是交互中等的后台系统**：任务列表、搜索过滤、音频播放、纪要编辑——以“状态 → 列表 → 表单”为主，复杂度在于“状态复用与组合”而非“超大规模企业级约束”；组合式 API 在这种规模下比选项式更易做逻辑复用与测试。
3. **工程链路追求“可解释的快”**：开发期希望“改一行、瞬时可见”，构建期希望“产物可审计、依赖可复现”。Vite 的“开发期不打包、按需转译 + 原生 ESM”与“生产期 Rollup 打包”恰好匹配该诉求。

> **中立提醒**：本节解释“为何在本课程选 Vue 3 + Vite”，不论证“Vue 优于 React/Angular”。若约束变为“团队已深度使用 React + Next.js”或“企业要求 Angular 全家桶规范”，结论应随之改变——选型判断的价值在于“可解释的 trade-off”，而非“站队”。

## 组合式 API：把“关注点”从“选项”中解放出来

Vue 2 的选项式 API（`data` / `methods` / `computed` / `watch` 分散在不同选项）适合中小组件，但当 MeetingToText 的“任务列表 + 搜索 + 轮询”逻辑 growing，同一关注点的代码会被拆到四个选项中，复用只能靠 `mixin`（命名冲突、来源不明）。

Vue 3 的组合式 API（`setup` + `ref`/`reactive`/`computed`/`watch` + 组合函数）把“同一关注点的状态与逻辑”收拢到同一函数中，并通过普通函数即可复用：

选项式（Vue 2 风格，仅示意）：

```javascript
// 选项式：关注点分散在不同选项，复用靠 mixin
export default {
  data() { return { keyword: '', tasks: [], timer: null } },
  computed: { filtered() { return this.tasks.filter(t => t.filename.includes(this.keyword)) } },
  methods: { async load() { this.tasks = (await fetch('/api/tasks').then(r => r.json())).tasks } },
  mounted() { this.load(); this.timer = setInterval(this.load, 3000) },
  beforeUnmount() { clearInterval(this.timer) }
}
```

组合式（Vue 3 风格，`script setup`）：

```javascript
// 组合式：同一关注点收拢，可抽为 useTasks() 复用
import { ref, computed, onMounted, onUnmounted } from 'vue'

export function useTasks() {
  const keyword = ref('')
  const tasks = ref([])
  async function load() {
    const data = await fetch('/mock.json').then(r => r.json())
    tasks.value = data.tasks
  }
  const filtered = computed(() => tasks.value.filter(t => (t.name || t.filename).includes(keyword.value)))
  let timer = null
  onMounted(() => { load(); timer = setInterval(load, 3000) })
  onUnmounted(() => clearInterval(timer))
  return { keyword, tasks, filtered, load }
}

// 组件中：const { keyword, filtered } = useTasks()
```

类比：选项式像“按工具分抽屉”（所有刀放一起、所有叉放一起），找“一顿饭所需的全套餐具”要开四个抽屉；组合式像“按套餐收纳”（一屉即一餐具套装），复用就是“再拿一套同样的收纳盒”。

## Proxy 响应式：从“劫持属性”到“代理对象”

Vue 2 用 `Object.defineProperty` 劫持“已知的属性”，新增属性需 `Vue.set`，数组需重写变异方法；Vue 3 用 `Proxy` 代理整个对象，天然支持新增/删除属性与数组索引，且依赖追踪更精确、开销更低（官方文档与 RFC 有详细对比与基准）：

```javascript
// 概念对照（示意，非真实 Vue 源码）
// Vue 2: 劫持单个属性
Object.defineProperty(obj, 'keyword', {
  get() { track(); return val },
  set(v) { val = v; trigger() }
})
// 新增属性无法自动劫持 → 需 Vue.set(obj, 'newProp', 1)

// Vue 3: 代理整个对象
const proxy = new Proxy(obj, {
  get(target, key) { track(target, key); return Reflect.get(target, key) },
  set(target, key, value) { const r = Reflect.set(target, key, value); trigger(target, key); return r }
})
// 新增/删除/数组索引均被代理，无需额外 API
```

对后端开发者的直觉翻译：Vue 3 的 `ref`/`reactive` 就像给对象套了一层“可观测代理”，读取时自动“订阅”，写入时自动“通知”——与后端的“观察者模式”或“发布-订阅”是同一思想在前端的具体实现。更多响应式细节将在 [第8章 响应式原理](../chapter08_vue3_core/8.1_reactivity_principles.md) 展开。

> **跨平台提示**：响应式原理与操作系统无关；本地验证时用 `pathlib.Path` 处理路径差异，虚拟环境激活为 `source .venv/bin/activate`（macOS / Linux）与 `.venv\Scripts\activate`（Windows）。

## Vite 为何在开发期更快

传统打包器（Webpack 等）的工作流是“先把所有模块打包成 bundle，再起 dev server”——项目越大，首次启动与热更新越慢。Vite 换了思路：

- **开发期不打包**：利用浏览器原生 ES Module（`type: module` + `import`），按需、按路由转译单个文件；依赖（`vue`、`vue-router` 等）用 esbuild 预构建（Go 编写，极快），源码用原生 ESM 直接服务。改一行，只转译一行。
- **生产期再打包**：用 Rollup 对 ESM 做 tree-shaking 与分包，产物依然是高度优化的静态资源。

```
传统：源码 → 全部打包成 bundle → dev server 响应（改一行 → 增量重打包 bundle）
Vite： 源码 → ESM 按需服务 + 依赖预构建（esbuild），改一行 → 只转译该文件
```

类比：传统是“开餐前把所有菜一次炒好再上桌”，客人改一道菜要重做整桌；Vite 是“点菜后单炒”，只做客人点的那一道，自然更快。对 MeetingToText 这类后台系统，开发期“改列表过滤逻辑 → 浏览器瞬时热更新”的体验差异，正来自这一架构选择。

下面这份内联 `package.json` 的脚本即体现该分工（见 [index 本章验证](index.md) 的 `json.loads` 解析）：

```javascript
// 示意：package.json（节选）
{
  "type": "module",
  "scripts": { "dev": "vite", "build": "vue-tsc --noEmit && vite build", "preview": "vite preview" },
  "dependencies": { "vue": "^3.5.13" },
  "devDependencies": { "vite": "^6.0.0", "@vitejs/plugin-vue": "^5.2.0" }
}
```

```bash
# 开发期（按需 ESM，不打包）与生产期（Rollup 打包）对照（示意）
npm run dev     # 或 pnpm dev → Vite dev server，改一行即热更新
npm run build   # 或 pnpm build → vue-tsc 类型检查 + vite build 产物到 dist/
# Windows / macOS / Linux 命令相同；若用 pnpm，见 7.4 的包管理器对比
```

## 可运行示例：Python 类比“组合式复用 + Proxy 响应式 + Vite 按需”

文件 `book/part3_frontend_collaboration/chapter07_frontend_overview/demo_vue3_vite.py`（用 Python 类比 Vue 3 的组合式复用与 Proxy 响应式，并用“按需转译 vs 全量打包”的计数器类比 Vite 的开发期优势，本地可复现，无网络）：

```{code-cell} ipython3
# 文件 book/part3_frontend_collaboration/chapter07_frontend_overview/demo_vue3_vite.py
from typing import Callable

# ---- 1) Proxy 响应式极简实现（类比 Vue 3 reactive/ref） ----
class Reactive:
    """极简 Proxy：拦截读写，自动追踪与触发（类比 Vue 3 Proxy）"""
    def __init__(self, initial: dict):
        object.__setattr__(self, "_data", dict(initial))
        object.__setattr__(self, "_subs", {})  # key -> [effect]

    def _track(self, key, effect: Callable):
        self._subs.setdefault(key, []).append(effect)

    def _trigger(self, key):
        for eff in self._subs.get(key, []):
            eff()

    def __getattr__(self, key):
        return self._data[key]

    def __setattr__(self, key, value):
        if key in ("_data", "_subs"):
            object.__setattr__(self, key, value)
        else:
            self._data[key] = value
            self._trigger(key)

    def effect(self, key: str, fn: Callable):
        """订阅某 key 的变化（类比 computed/watch 的依赖收集）"""
        self._track(key, fn)

# 模拟 MeetingToText 的搜索过滤：keyword 变化自动重算 filtered
state = Reactive({"keyword": "", "tasks": ["meeting.wav", "interview.mp3", "demo.wav"]})
renders: list[str] = []

def render_filtered():
    kw = state.keyword.lower()
    filtered = [t for t in state.tasks if kw in t.lower()]
    view = " | ".join(filtered) if filtered else "(空)"
    renders.append(view)

# 首次渲染 + 订阅 keyword 与 tasks
render_filtered()
state.effect("keyword", render_filtered)
state.effect("tasks", render_filtered)
print("初始:", renders[-1])

state.keyword = "meeting"  # 直接赋值，自动触发
print("keyword=meeting:", renders[-1])
assert renders[-1] == "meeting.wav"

state.keyword = "mp3"
print("keyword=mp3:", renders[-1])
assert renders[-1] == "interview.mp3"

# 新增属性也能被代理（对比 Vue 2 需 Vue.set）
state.new_field = "hello"
state.effect("new_field", lambda: renders.append(f"new_field={state.new_field}"))
state.new_field = "world"
print("新增属性:", renders[-1])
assert renders[-1] == "new_field=world"
print("Proxy 校验通过：新增/修改均自动触发")
print()

# ---- 2) 组合式复用：把“可复用逻辑”抽为函数（类比 useTasks） ----
print("=== 组合式复用 ===")

def use_keyword_filter(initial_tasks: list[str]):
    """组合函数：封装 keyword + filtered + load，类似 Vue 的 useTasks()"""
    local = Reactive({"keyword": "", "tasks": list(initial_tasks)})
    views: list[str] = []

    def compute():
        kw = local.keyword.lower()
        views.append([t for t in local.tasks if kw in t.lower()])

    compute()
    local.effect("keyword", compute)
    local.effect("tasks", compute)
    return local, views

s1, v1 = use_keyword_filter(["a.wav", "b.mp3"])
s2, v2 = use_keyword_filter(["x.wav", "y.mp3"])
s1.keyword = "a"
s2.keyword = "y"
print("实例1 filtered:", v1[-1])
print("实例2 filtered:", v2[-1])
assert v1[-1] == ["a.wav"]
assert v2[-1] == ["y.mp3"]
print("组合式复用通过：同一逻辑在两个实例中独立复用，无命名冲突")
print()

# ---- 3) Vite 按需 vs 传统全量打包（计数器类比） ----
print("=== Vite 按需 vs 传统全量 ===")
files = ["App.vue", "router.ts", "store.ts", "utils.ts", "a.vue", "b.vue", "c.vue"]

def traditional_build(changed: str) -> int:
    """传统：改一文件，重打包全部文件"""
    return len(files)

def vite_dev(changed: str) -> int:
    """Vite 开发期：改一文件，只转译该文件 + 依赖预构建已缓存"""
    return 1

for changed in ["App.vue", "store.ts"]:
    print(f"改 {changed}: 传统需处理 {traditional_build(changed)} 个文件, Vite 需处理 {vite_dev(changed)} 个文件")

assert vite_dev("App.vue") < traditional_build("App.vue")
print("构建对比通过：开发期按需显著少于全量")
print()
print("小结：组合式解决‘逻辑复用’，Proxy 解决‘依赖追踪’，Vite 解决‘开发期反馈速度’")
# 预期输出:
# 初始: meeting.wav | interview.mp3 | demo.wav
# keyword=meeting: meeting.wav
# keyword=mp3: interview.mp3
# 新增属性: new_field=world
# Proxy 校验通过：新增/修改均自动触发
# ...
# 组合式复用通过：同一逻辑在两个实例中独立复用，无命名冲突
# 改 App.vue: 传统需处理 7 个文件, Vite 需处理 1 个文件
# 构建对比通过：开发期按需显著少于全量
# 小结：...
```
