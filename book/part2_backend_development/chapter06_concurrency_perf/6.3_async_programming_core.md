# 异步编程核心

> 学完本节，你能回答：事件循环如何用单线程实现并发？`async`/`await`、协程、Task、Future 各自是什么、如何协作？为什么 `await` 是“让出”而非“阻塞”？MeetingToText 的“批量转写等待”为何适合用 `asyncio` 重叠？

## 为什么需要异步：从“一个个等”到“一起等”

想象你在餐厅同时点了三道菜：同步做法是“等第一道上桌吃完再点第二道”；异步做法是“三道一起下单，上哪道吃哪道”。后者的关键不是“做得更快”，而是**等待被重叠**——在等第一道菜的间隙，你可以先喝汤、回消息。

`asyncio` 就是 Python 的“餐厅叫号系统”：**单线程事件循环**（Event Loop）不断询问“谁的 I/O 好了”，就绪的任务就被唤醒执行，未就绪的继续等。整个过程只有一根线程在跑，通过**协作式让出**（`await`）实现并发。

## 核心概念：四件套

- **协程（Coroutine）**：用 `async def` 定义的函数，调用时不立即执行，而是返回一个协程对象。类比“菜谱”——写好了但还没下锅。
- **`await`**：让出点。`await asyncio.sleep(0.05)` 的含义是“我要等 50ms，这段时间你去做别的事，好了再叫我”。没有 `await` 的 `async def` 会一直占着循环（见 [6.4](6.4_fastapi_async_pitfalls.md) 的陷阱）。
- **Future**：一个“将来会填好的盒子”，代表某个异步结果的占位符。协程 `await` 的本质就是“等某个 Future 被填好”。
- **Task**：对协程的**调度包装**。`asyncio.create_task(coro())` 会把协程提交给事件循环立即排程，返回的 `Task` 是 `Future` 的子类，可被 `await`、`cancel`、`gather`。
- **事件循环（Event Loop）**：单线程的调度器，维护就绪队列与 I/O 多路复用。`asyncio.run(main())` 会创建新循环、运行 `main`、关闭循环。

> **执行模型**：`asyncio` 是**协作式**（cooperative）而非抢占式——任务必须主动 `await` 才会让出。若某协程做 100ms 的纯计算不 `await`，整个循环都会被卡住（这正是 [6.4](6.4_fastapi_async_pitfalls.md) 的“阻塞事件循环”陷阱）。

## 常用并发原语

| 原语 | 作用 | 类比 |
| --- | --- | --- |
| `await coro()` | 等单个协程完成 | 等一道菜上桌 |
| `asyncio.gather(*coros)` | 并发等多个协程，全部完成才返回 | 一次下三道菜，等齐 |
| `asyncio.wait_for(coro, timeout)` | 带超时的等待 | 等 30s 不上菜就催单 |
| `asyncio.create_task(coro)` | 立即排程，后台运行 | 先下单，稍后再取 |
| `asyncio.Queue` | 协程间安全队列 | 传菜窗口 |

> **跨平台提示**：`asyncio` 为标准库，Windows / macOS / Linux 均可用；`asyncio.run` 需 Python 3.7+，本书要求 3.12，已满足。路径与环境激活差异同 [6.1](6.1_concurrency_parallel_async.md)。

## 可运行示例一：事件循环、Task、Future 与 `gather` 的协作

文件 `book/part2_backend_development/chapter06_concurrency_perf/demo_asyncio_core.py`（演示协程、Task、Future、gather、Queue 的协作，输出排序保证确定）：

```{code-cell} ipython3
# 文件 book/part2_backend_development/chapter06_concurrency_perf/demo_asyncio_core.py
import asyncio
import time

async def fetch_segment(seg_id: int, delay: float = 0.05) -> str:
    """模拟获取一段转写结果：等待 delay 后返回（I/O 密集）。"""
    await asyncio.sleep(delay)
    return f"seg-{seg_id}"

async def task_with_future():
    """演示 Future：手动创建 Future，在后台任务中填值，主协程 await 它。"""
    loop = asyncio.get_running_loop()
    fut: asyncio.Future[str] = loop.create_future()

    async def _fill():
        await asyncio.sleep(0.03)
        if not fut.done():
            fut.set_result("future-result")

    # 后台填 Future
    asyncio.create_task(_fill())
    result = await fut
    print("future result:", result)
    assert result == "future-result"
    return result

async def queue_demo():
    """演示 asyncio.Queue：生产者-消费者协作。"""
    q: asyncio.Queue[int] = asyncio.Queue()

    async def producer():
        for i in range(3):
            await asyncio.sleep(0.01)
            await q.put(i)
        await q.put(-1)  # 结束哨兵

    async def consumer(out: list[int]):
        while True:
            v = await q.get()
            if v == -1:
                q.task_done()
                break
            out.append(v)
            q.task_done()

    out: list[int] = []
    await asyncio.gather(producer(), consumer(out))
    print("queue out:", sorted(out))
    assert sorted(out) == [0, 1, 2]
    return out

async def main():
    t0 = time.perf_counter()

    # 1) gather 并发：3 个 50ms 任务约 50ms 完成
    results = await asyncio.gather(
        fetch_segment(0), fetch_segment(1), fetch_segment(2)
    )
    t_gather = time.perf_counter() - t0
    print("gather results:", sorted(results))
    print(f"gather elapsed: {t_gather:.3f}s")
    assert sorted(results) == ["seg-0", "seg-1", "seg-2"]
    assert t_gather < 0.12

    # 2) create_task 后台排程：任务在后台跑，主协程可先做别的事
    t1 = asyncio.create_task(fetch_segment(10, 0.04))
    t2 = asyncio.create_task(fetch_segment(11, 0.04))
    # 主协程做一点别的
    await asyncio.sleep(0.01)
    print("tasks created, doing other work...")
    r1, r2 = await asyncio.gather(t1, t2)
    print("task results:", sorted([r1, r2]))
    assert sorted([r1, r2]) == ["seg-10", "seg-11"]

    # 3) Future 协作
    await task_with_future()

    # 4) Queue 协作
    await queue_demo()

    # 5) wait_for 超时：0.02s 的超时等 0.05s 的任务，应触发 TimeoutError
    try:
        await asyncio.wait_for(fetch_segment(99, 0.05), timeout=0.02)
        assert False, "should timeout"
    except asyncio.TimeoutError:
        print("wait_for timeout as expected")

    # 6) 串行 vs 并发耗时对照（同 50ms 任务，串行约 150ms，并发约 50ms）
    t0 = time.perf_counter()
    for i in range(3):
        await fetch_segment(i)
    t_serial = time.perf_counter() - t0

    t0 = time.perf_counter()
    await asyncio.gather(fetch_segment(0), fetch_segment(1), fetch_segment(2))
    t_conc = time.perf_counter() - t0

    print(f"serial {t_serial:.3f}s vs concurrent {t_conc:.3f}s")
    assert t_conc < t_serial
    print("asyncio 核心对照通过")

await main()
# 预期输出:
# gather results: ['seg-0', 'seg-1', 'seg-2']
# gather elapsed: 0.05x s
# tasks created, doing other work...
# task results: ['seg-10', 'seg-11']
# future result: future-result
# queue out: [0, 1, 2]
# wait_for timeout as expected
# serial 0.15x s vs concurrent 0.05x s
# asyncio 核心对照通过
```

## 可运行示例二：为何 `await` 是“让出”而非“阻塞”

文件 `book/part2_backend_development/chapter06_concurrency_perf/demo_asyncio_yield.py`（对比“在协程中用 `time.sleep` 阻塞循环”与“用 `await asyncio.sleep` 让出”的差异）：

```{code-cell} ipython3
# 文件 book/part2_backend_development/chapter06_concurrency_perf/demo_asyncio_yield.py
import asyncio
import time

async def good_task(name: str):
    print(f"{name} start")
    await asyncio.sleep(0.03)  # 让出，事件循环可去跑别的任务
    print(f"{name} done")
    return name

async def bad_task_blocking(name: str):
    # 反例：用 time.sleep 阻塞整个事件循环（协作式调度的陷阱，详见 6.4）
    print(f"{name} start (blocking)")
    time.sleep(0.03)  # 阻塞，不会让出；演示用，实际应避免
    print(f"{name} done (blocking)")
    return name

async def run_good():
    t0 = time.perf_counter()
    results = await asyncio.gather(good_task("A"), good_task("B"), good_task("C"))
    elapsed = time.perf_counter() - t0
    print("good gather:", sorted(results), f"elapsed {elapsed:.3f}s")
    # 3 个 30ms 任务并发约 30ms
    assert sorted(results) == ["A", "B", "C"]
    assert elapsed < 0.10
    return elapsed

async def run_bad():
    t0 = time.perf_counter()
    # 阻塞版本虽也用 gather，但每个任务内的 time.sleep 会卡住循环，无法真正重叠
    results = await asyncio.gather(
        bad_task_blocking("A"), bad_task_blocking("B"), bad_task_blocking("C")
    )
    elapsed = time.perf_counter() - t0
    print("bad gather:", sorted(results), f"elapsed {elapsed:.3f}s")
    assert sorted(results) == ["A", "B", "C"]
    # 阻塞版本耗时接近串行（执行顺序虽由事件循环调度，但 sleep 期间循环被卡）
    return elapsed

print("--- good: await asyncio.sleep (让出) ---")
t_good = await run_good()
print("--- bad: time.sleep in async (阻塞) ---")
t_bad = await run_bad()
print(f"让出 {t_good:.3f}s vs 阻塞 {t_bad:.3f}s（阻塞通常更慢或至少不更快）")
print("让出语义验证通过：await 才会让控制权回到事件循环")
# 预期输出:
# --- good: await asyncio.sleep (让出) ---
# A start ... B start ... C start ... A done ... B done ... C done
# good gather: ['A', 'B', 'C'] elapsed 0.03x s
# --- bad: time.sleep in async (阻塞) ---
# A start (blocking) ... A done (blocking) ... B start ... B done ... C start ... C done
# bad gather: ['A', 'B', 'C'] elapsed 0.09x s
# 让出 ... vs 阻塞 ...
```
