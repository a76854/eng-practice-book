# 本章小结

- **并发与并行是两回事**。并发是任务的组织方式（多个任务如何共享计算资源），并行是硬件的执行方式（多个任务是否真正同时运行）。单核可以实现并发，但无法实现并行。理解这一区别，是选择正确并发模型的起点。

- **阻塞/非阻塞与同步/异步是正交的两组概念**。阻塞/非阻塞描述调用方的状态（等不等），同步/异步描述任务间的关系（怎么通知）。不能将它们混为一谈。四象限框架——同步阻塞、同步非阻塞、异步阻塞、异步非阻塞——提供了分析并发模型的完整视角。

- **Python 三种并发模型各有明确的适用边界**：`threading` 适合 I/O 密集型任务（并发量适中），`multiprocessing` 适合 CPU 密集型任务（利用多核绕过 GIL），`asyncio` 适合高并发 I/O 场景（极低切换开销支撑海量连接）。选型的关键是先定位瓶颈类型。

- **GIL 是 CPython 内存管理机制的产物**，它保护引用计数不被多线程竞争破坏。对于 I/O 密集型任务，GIL 在等待期间被释放，多线程有效；对于 CPU 密集型任务，GIL 成为硬瓶颈，多线程无法利用多核。GIL 不是设计缺陷，而是经过权衡的工程决策，短期内不会被移除。

- **asyncio 的协作式并发模型**依赖事件循环驱动所有协程运行，`async`/`await` 提供主动让出的语法基础，Task 是协程的调度单元，Future 是结果的占位容器。协作式调度的代价是：任何一个协程不遵守约定（调用阻塞代码），整个事件循环都会被卡住。

- **FastAPI 异步陷阱的本质**是 `async def` 路由在事件循环中执行，阻塞操作会卡住整个服务；而 `def` 路由在线程池中执行，阻塞只影响当前线程。选择 `async def` 还是 `def`，取决于路由中的操作是否支持异步等待。

- **性能优化的唯一正路是先度量再优化**。`timeit` 提供小片段的精确计时，`cProfile` 定位全程序的函数级热点，`EXPLAIN` 分析数据库慢查询的执行计划，`line_profiler` 在热点函数内部逐行定位瓶颈。四者配合，构成从宏观到微观的完整度量体系。

# 思考题

1. **并发模型的选型判断**：你要开发一个文件处理服务，用户上传一个 ZIP 包，服务需要解压、逐个文件进行格式转换、将转换结果打包后返回。解压和打包涉及磁盘 I/O，格式转换是 CPU 密集型计算。你会如何为这个服务设计并发模型？是否需要混合使用多进程和多线程？请画出请求处理的流程，并说明每部分为什么选择某种并发方式。

2. **GIL 的边界**：你有一段 CPU 密集型计算代码，在多线程环境下完全没有加速效果。同事建议“换成多进程就好了”。但多进程带来了额外的内存开销和数据序列化成本。请分析：在什么条件下多进程的收益能覆盖它的成本？数据量、核心数、计算复杂度三个维度如何影响决策？如果不使用多进程，还有哪些方式可以让 CPU 密集型代码在 Python 中跑得更快？

3. **协作式调度的脆弱性**：在 FastAPI 应用中，你在 `async def` 路由中不小心调用了 `time.sleep(2)`，生产环境发现服务在高峰期响应变慢。请解释：为什么一个 2 秒的 `time.sleep()` 会让整个服务的延迟都变高？如果你在路由中使用了同步的 `requests.get()`，影响是否相同？如果改用 `httpx.AsyncClient`，问题为什么能够解决？从事件循环的调度机制角度分析。

4. **Task 与 Future 的职责划分**：`asyncio.create_task()` 返回的是一个 Task 对象，Task 是 Future 的子类。请分析这种继承关系的设计意图：为什么 Task 需要既是“可执行单元”又是“结果容器”？在 asyncio 的实现中，如果 Task 不继承 Future，而是维护一个独立的 Future 属性来保存结果，会有什么问题？

5. **性能剖析与直觉的冲突**：某个 Web 服务响应变慢，你凭经验认为瓶颈在数据库查询，于是在索引和查询上花了三天时间优化，但效果不明显。如果用 `cProfile` 剖析后实际发现，大部分时间花在模板渲染（字符串拼接）上。这个反直觉的场景说明了什么？请结合“先度量再优化”的原则，讨论性能优化中如何平衡经验和数据，以及如何避免优化偏见（只优化自己熟悉的领域）。

6. **从概念到工程的迁移**：你接手了一个使用多线程 + 同步数据库驱动的老项目，并发量接近 1000 请求/秒，出现响应延迟抖动。你决定迁移到 asyncio + 异步数据库驱动。请列出迁移过程中需要面对的挑战：现有的同步库如何迁移？共享内存状态如何管理？多线程下的锁机制在 asyncio 中如何处理？为什么 asyncio 中不需要锁，但又引入了新的并发安全问题（`await` 点安全）？
