# 并发、并行与异步

> 学完本节，你能回答：并发与并行有何本质差异？异步与非阻塞是否是同一回事？I/O 密集与 CPU 密集任务为何要选不同的并发模型？MeetingToText 的批量音频处理为何适合用线程/协程重叠 I/O，而不适合用多线程加速纯计算？

## 为什么需要辨析：同一个“同时做”有三种实现

想象食堂的三个窗口：

- **并发（Concurrency）**：一个服务员在三个窗口间来回跑，同一时间只服务一人，但通过快速切换让三人都感觉“在被服务”。对应单核上多任务交替执行，核心是**结构**——如何交错任务以提高资源利用率。
- **并行（Parallelism）**：三个服务员各守一窗口，同一时刻真的有三人被服务。对应多核上多任务真正同时执行，核心是**执行**——是否在物理上同时发生。
- **异步（Asynchronous）**：你点完餐拿到取餐号，不用站在窗口等，做好了叫号。对应“发起请求后不等结果，先做别的事，结果就绪再处理”，核心是**调用方式**——是否阻塞等待结果。

三者的关系常被一句话概括：并发是“处理多个任务的能力”，并行是并发的一个子集（需要多核），异步是实现并发的一种**手段**。与之正交的还有两对概念：

- **同步 vs 异步**：关注**调用方**。同步是“调用后等结果返回再往下走”；异步是“调用后先返回，结果稍后通过回调/Future/await 取得”。
- **阻塞 vs 非阻塞**：关注**等待方式**。阻塞是“等待期间线程被挂起、不能做别的事”；非阻塞是“等待期间线程可去做别的事（轮询或被通知）”。

> **直觉校准**：异步不等于非阻塞，但二者常组合出现。`asyncio` 的 `await` 是“异步 + 非阻塞”的协作式等待：当前协程让出控制权，事件循环去驱动别的就绪任务。

## I/O 密集 vs CPU 密集：选型第一性原理

- **I/O 密集**（网络请求、文件读写、数据库查询、调用 `m2t/asr.py` 的远程 ASR）：瓶颈在**等待**，CPU 大部分时间空闲。适合用**线程**或**协程**重叠等待时间——一个任务等 I/O 时让另一个任务用 CPU。
- **CPU 密集**（音频重采样的大规模数值计算、文本后处理中的正则大规模替换）：瓶颈在**计算**。Python 中多线程受 GIL 限制难以并行加速 CPU 计算，适合用**进程**（`multiprocessing`）或把计算下沉到 C 扩展/NumPy 等释放 GIL 的库。

> **与 `m2t` 的呼应**：`m2t/audio.py` 的 `load_audio` 是文件 I/O 密集（适合并发重叠），而 `resample_audio` 若走 `librosa` 则是 CPU 密集；`m2t/asr.py` 的 `transcribe` 若走网络则为 I/O 密集。与第 3 章的分层思想一致——先识别瓶颈类型，再选模型，而非“默认多线程”。

## 三种并发工具的定位

| 工具 | 模型 | 适用 | 成本 |
| --- | --- | --- | --- |
| `threading` | 内核线程，抢占式调度 | I/O 密集、需共享内存 | 线程创建与切换开销、需处理竞态 |
| `concurrent.futures` | 线程/进程池的高层封装 | 批量任务、需 `Future` 统一接口 | 池化可控，接口一致 |
| `asyncio` | 单线程事件循环，协作式调度 | 高并发 I/O、长连接、网关 | 单线程内无竞态，但阻塞调用会拖垮循环 |

> **跨平台提示**：`threading` / `concurrent.futures` / `asyncio` 均为标准库，Windows / macOS / Linux 行为一致；涉及文件路径时用 `pathlib.Path` 适配分隔符（`/` vs `\`），虚拟环境激活为 `source .venv/bin/activate`（macOS / Linux）与 `.venv\Scripts\activate`（Windows）。

## 可运行示例一：用 `threading` 与 `concurrent.futures` 对照“并发重叠 I/O”

文件 `book/part2_backend_development/chapter06_concurrency_perf/demo_concurrency_threading.py`（模拟 I/O 等待 50ms 的批量任务，对比串行、裸线程与线程池，均用排序保证输出确定）：

```{code-cell} ipython3
# 文件 book/part2_backend_development/chapter06_concurrency_perf/demo_concurrency_threading.py
import time
import threading
import concurrent.futures

def io_task(task_id: int, delay: float = 0.05) -> str:
    """模拟 I/O 任务：等待 delay 秒后返回结果（代表文件/网络等待）。"""
    time.sleep(delay)
    return f"task-{task_id}"

# 1) 串行执行：3 个任务各 50ms，约 150ms
t0 = time.perf_counter()
serial_results = [io_task(i) for i in range(3)]
t_serial = time.perf_counter() - t0
print("serial results:", sorted(serial_results))
print(f"serial elapsed: {t_serial:.3f}s")
assert sorted(serial_results) == ["task-0", "task-1", "task-2"]
# 串行耗时约 0.15s，允许 0.13-0.25s 的调度抖动
assert 0.12 < t_serial < 0.35

# 2) 裸 threading：3 线程并发，约 50ms 完成（等待重叠）
results_mt = []
threads = []

def _worker(tid: int):
    r = io_task(tid)
    results_mt.append(r)

t0 = time.perf_counter()
for i in range(3):
    th = threading.Thread(target=_worker, args=(i,))
    threads.append(th)
    th.start()
for th in threads:
    th.join()
t_thread = time.perf_counter() - t0
print("threading results:", sorted(results_mt))
print(f"threading elapsed: {t_thread:.3f}s")
assert sorted(results_mt) == ["task-0", "task-1", "task-2"]
# 并发后应显著快于串行
assert t_thread < t_serial

# 3) concurrent.futures 线程池：更简洁的批量接口，同样重叠等待
t0 = time.perf_counter()
with concurrent.futures.ThreadPoolExecutor(max_workers=3) as ex:
    futs = [ex.submit(io_task, i) for i in range(3)]
    pool_results = sorted([f.result() for f in concurrent.futures.as_completed(futs)])
t_pool = time.perf_counter() - t0
print("pool results:", pool_results)
print(f"pool elapsed: {t_pool:.3f}s")
assert pool_results == ["task-0", "task-1", "task-2"]
assert t_pool < t_serial

# 4) 进程池对照（I/O 密集场景下进程池也能重叠等待，但进程开销更大，教学演示用 2 worker）
with concurrent.futures.ProcessPoolExecutor(max_workers=2) as ex:
    futs = [ex.submit(io_task, i) for i in range(3)]
    proc_results = sorted([f.result() for f in concurrent.futures.as_completed(futs)])
print("process pool results:", proc_results)
assert proc_results == ["task-0", "task-1", "task-2"]

print("并发对照通过：串行 <线程/线程池/进程池> 在 I/O 等待上均有重叠收益")
# 预期输出:
# serial results: ['task-0', 'task-1', 'task-2']
# serial elapsed: 0.15x s
# threading results: ['task-0', 'task-1', 'task-2']
# threading elapsed: 0.05x s
# pool results: ['task-0', 'task-1', 'task-2']
# pool elapsed: 0.05x s
# process pool results: ['task-0', 'task-1', 'task-2']
# 并发对照通过：...
```

```bash
# 本地验证（macOS / Linux）
.venv/bin/python -c "import threading, concurrent.futures; print('concurrency ok')"
# Windows 需用
.venv\Scripts\python.exe -c "import threading, concurrent.futures; print('concurrency ok')"
```

## 可运行示例二：用 `asyncio` 对照“协程重叠 I/O”

文件 `book/part2_backend_development/chapter06_concurrency_perf/demo_concurrency_asyncio.py`（同等 50ms I/O 任务，用 `asyncio.gather` 并发，单线程内协作式调度）：

```{code-cell} ipython3
# 文件 book/part2_backend_development/chapter06_concurrency_perf/demo_concurrency_asyncio.py
import asyncio
import time

async def async_io_task(task_id: int, delay: float = 0.05) -> str:
    await asyncio.sleep(delay)
    return f"task-{task_id}"

async def _run_async_demo():
    # 1) 串行 await：3 个 50ms 任务约 150ms
    t0 = time.perf_counter()
    s0 = await async_io_task(0)
    s1 = await async_io_task(1)
    s2 = await async_io_task(2)
    t_serial = time.perf_counter() - t0
    serial = sorted([s0, s1, s2])
    print("async serial:", serial, f"elapsed {t_serial:.3f}s")
    assert serial == ["task-0", "task-1", "task-2"]
    assert 0.12 < t_serial < 0.35

    # 2) 并发 gather：3 任务约 50ms 完成（单线程内重叠等待）
    t0 = time.perf_counter()
    results = await asyncio.gather(
        async_io_task(0), async_io_task(1), async_io_task(2)
    )
    t_conc = time.perf_counter() - t0
    conc = sorted(results)
    print("async concurrent:", conc, f"elapsed {t_conc:.3f}s")
    assert conc == ["task-0", "task-1", "task-2"]
    assert t_conc < t_serial
    # 返回供外层打印
    return t_serial, t_conc

t_serial, t_conc = await _run_async_demo()
print(f"asyncio 对照通过：串行 {t_serial:.3f}s > 并发 {t_conc:.3f}s")
# 预期输出:
# async serial: ['task-0', 'task-1', 'task-2'] elapsed 0.15x s
# async concurrent: ['task-0', 'task-1', 'task-2'] elapsed 0.05x s
# asyncio 对照通过：串行 ... > 并发 ...
```

```bash
# 本地验证事件循环可用（macOS / Linux）
.venv/bin/python -c "import asyncio; asyncio.run(asyncio.sleep(0)); print('asyncio ok')"
# Windows 需用
.venv\Scripts\python.exe -c "import asyncio; asyncio.run(asyncio.sleep(0)); print('asyncio ok')"
```
