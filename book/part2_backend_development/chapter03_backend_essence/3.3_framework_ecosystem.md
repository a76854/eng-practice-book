# 框架生态谱系

> 学完本节，你能回答：为什么 Python 会同时存在 Django、Flask、FastAPI 三类框架？它们的定位差异是什么？在什么约束下应选哪一类？

## 谱系不是“谁替代谁”，而是“谁适合哪段”

框架的演进与语言选型一样，受约束驱动。若把后端框架比作交通工具：

- **Django** 像“高铁”——轨道、车站、调度一体化，适合“站点密集、规则统一”的长线。
- **Flask** 像“自行车”——极轻、极灵活，适合“短距离、自定义路线”的探索。
- **FastAPI** 像“电动车”——在轻量与性能间取平衡，异步与类型驱动让“中长距离通勤”更省力。

三者不是线性替代，而是**在“约束—能力”坐标系中的不同落点**。

### 全栈 Django：约定优于配置

- **定位**： batteries-included。ORM、管理后台、表单、认证、迁移一体化，开箱即得完整站点。
- **依据**：官方文档与社区案例显示，Django 在内容型站点与管理后台密集型项目中交付快、规范统一；但“约定”也意味着定制成本，偏离约定需额外封装。
- **适用**：团队小、交付快、后台重、规范强的场景；课程大作业若以 CRUD 与管理页为主，Django 是稳妥选择。
- **代价**：学习曲线与隐式约定、异步支持后发、深度定制时需理解其内部约定。

### 微架构 Flask：小核心 + 扩展

- **定位**： micro。核心仅路由与上下文，ORM、表单、认证均由扩展按需拼装。
- **依据**：Flask 官方强调“保持核心简单”，扩展生态丰富但也分散；小项目中灵活、透明，但大项目需自行约定结构，否则易随扩展拼装而碎片化。
- **适用**：原型、微服务、小工具、对“可看清每一层”有教学诉求的场景。
- **代价**：约定需自建，选型与胶合成本由团队承担；异步与类型推导非原生。

### 高性能 FastAPI：类型与异步原生

- **定位**： modern。基于 Starlette（异步）与 Pydantic（类型校验），类型驱动、自动文档、异步原生。
- **依据**：官方基准与社区压测在 I/O 密集型场景中常以 FastAPI 为 Python 侧代表；但“高性能”需结合 workload 解读，真实业务中数据库与外部调用往往是瓶颈，框架差异需在端到端链路中验证。
- **适用**：AI 集成、I/O 密集、需要自动 OpenAPI 文档与强类型校验的服务；本课程 MeetingToText 的主栈。
- **代价**：生态相对年轻，部分 Django 开箱能力需自组；对异步心智与类型标注有要求。

> **中立性说明**：谱系无优劣，只有 trade-off。Django 的“全栈”在规范场景是优势，在定制场景是约束；Flask 的“微”在小团队是灵活，在大团队是规范成本；FastAPI 的“现代”在 I/O 密集与类型驱动中是增益，在重度后台与存量约束中未必最优。选型应以约束清单为准，而非“新就是好”。

## 谱系一览

| 维度 | Django | Flask | FastAPI |
|---|---|---|---|
| 哲学 | 全栈、约定 | 微核、扩展 | 现代、类型+异步 |
| 适合规模 | 中大、规范强 | 小中、灵活 | 中大、I/O 密集 |
| 学习曲线 | 中高（约定多） | 低（核心小） | 中（需类型与异步） |
| 文档与校验 | 手写或第三方 | 手写或第三方 | Pydantic 自动、OpenAPI 原生 |
| 异步 | 后补 | 有限 | 原生 |

## 可运行示例：FastAPI 最小应用（谱系中的一极）

示例（用 FastAPI 演示谱系中“现代”一极的最小形态，Flask/Django 形态以注释对照，无需安装他框架）：

```{code-cell} ipython3
from fastapi import FastAPI
from fastapi.testclient import TestClient

# FastAPI 最小应用：与 Flask 的 @app.route、Django 的 path() 在路由思想上同源
app = FastAPI(title="Framework Spectrum Demo", version="0.1.0")

@app.get("/")
def root():
    return {"framework": "FastAPI", "spectrum": "modern"}

@app.get("/health")
def health():
    return {"status": "ok"}

@app.get("/echo/{name}")
def echo(name: str):
    return {"echo": name}

# 对照（注释形态，不执行）：
# Flask:  @app.route("/echo/<name>")  def echo(name): return {"echo": name}
# Django: path("echo/<str:name>/", views.echo)

client = TestClient(app)

r1 = client.get("/")
print("GET /:", r1.json())
assert r1.json()["framework"] == "FastAPI"

r2 = client.get("/health")
print("GET /health:", r2.json())
assert r2.json()["status"] == "ok"

r3 = client.get("/echo/m2t")
print("GET /echo/m2t:", r3.json())
assert r3.json() == {"echo": "m2t"}

# 验证 OpenAPI 自动生成（FastAPI 特有，Django/Flask 需额外插件）
schema = app.openapi()
print("openapi paths:", sorted(schema["paths"].keys()))
assert "/" in schema["paths"]
assert "/health" in schema["paths"]

print("谱系演示通过：同一路由思想，三框架表述不同，约束决定选型")
# 预期输出:
# GET /: {'framework': 'FastAPI', 'spectrum': 'modern'}
# GET /health: {'status': 'ok'}
# GET /echo/m2t: {'echo': 'm2t'}
# openapi paths: ['/', '/echo/{name}', '/health']
# 谱系演示通过：同一路由思想，三框架表述不同，约束决定选型
```
