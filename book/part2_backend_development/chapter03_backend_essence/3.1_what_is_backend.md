# 后端是什么：为什么前后端分离

> 学完本节，你能回答：① 用“前端—后端—存储”一句话定位后端在哪里？② 为什么要前后端分离，而不是让后端直接拼 HTML？③ 后端的四条职责边界如何分工？④ 一条“接收请求 → 返回 JSON”的最小链路如何在本地用 `TestClient` 验证？

## 一句话定位后端：前端—后端—存储

现代 Web 系统最简分层是**前端—后端—存储**三层：前端负责呈现与交互（浏览器 / App），存储负责持久化（数据库 / 对象存储），而**后端夹在中间，负责接收前端请求、执行业务规则、读写存储、再把结果以结构化数据返回给前端**。一句话定位后端：**后端是面向前端提供可编程数据接口、面向存储维护一致性与安全的服务层**。

这一定位决定了后端的输入输出形态：输入是 HTTP 请求，输出是结构化响应（通常 JSON），中间是规则与状态。前后端分离正是为了让这一输入输出契约足够稳定与可测试：前端—后端—存储三层各司其职，前端可独立演进交互，后端可独立演进业务与存储，而二者通过契约（API）对齐，而非共享模板或数据库表。

## 为什么前后端分离

### 两种形态对比：模板直出 vs JSON API

| 维度 | 后端模板直出（SSR / 模板渲染） | 前后端分离（JSON API） |
|------|-------------------------------|------------------------|
| 渲染地点 | 后端拼好 HTML，直出给浏览器 | 后端只返 JSON，前端在浏览器中渲染 |
| 契约 | HTML 即契约，改文案即改接口 | JSON Schema 即契约，结构稳定 |
| 多端复用 | Web 专用，App 需另起接口 | 一套 API 供 Web / App / 开放平台复用 |
| 团队协作 | 前后端耦合在同一代码仓与发布流 | 前后端通过 OpenAPI 并行开发、独立部署 |
| 测试 | 需解析 HTML 断言 | 直接对 JSON 与状态码断言，易自动化 |

模板直出并非“错误”，在内容站、后台管理等以文档为中心的场景仍有优势；但在需要多端复用、频繁交互、团队并行的产品中，**前后端分离**让前后端通过 JSON 契约解耦，换来更高的演进自由度。

### URL 与职责如何分：`/api` 前缀

前后端分离后，URL 空间也要分离，避免职责混淆：

- **页面路由**由前端路由接管，如 `/tasks`、`/tasks/123` 是前端页面的地址，返回的是单页应用的 HTML 壳。
- **数据接口**由后端接管，统一以 `/api` 为前缀，如 `/api/tasks`、`GET /api/tasks/{id}`，返回 JSON。

约定 `/api` 前缀的好处是**边界清晰**：网关、代理、鉴权中间件可对 `/api/*` 统一施策（如鉴权、限流、审计），而静态资源与页面路由走另一条链路；前后端也可独立部署到不同域名或 CDN 后，通过反向代理将 `/api/*` 转发到后端服务。

一句话小结：**前后端分离 = 渲染分离 + 契约分离 + 部署分离**，而 `/api` 前缀是这一分离在 URL 层面的显式标记。

## 后端的边界：四条职责线

即便做了前后端分离，后端内部仍需守好四条边界，职责不混、变更不耦合。理想流向是 `HTTP 契约 → 校验 → 业务编排 → 持久化 → 响应`，安全检查散落在入口、边界与落库前。

- **API 设计**：对外契约。做什么（资源与动作）、怎么叫（路径与方法）、传什么（请求/响应形状）、错了怎么说（状态码与错误体）。契约一旦发布就是承诺，改动成本高，故需先设计后实现。
- **业务逻辑**：领域规则。中性 Task 领域中“创建任务 → 校验去重 → 落库 → 返回”的编排、状态机流转、去重与幂等，都属于业务层。业务层不该知道 HTTP 细节，只关心“给定输入，产出什么”。
- **数据流转**：持久化与传输。从请求体到领域对象、从领域对象到数据库行、从数据库到响应体的映射，以及事务边界与一致性。`m2t.store.TaskStore` 就是数据流转的最简形态。
- **安全防护**：守门。认证（你是谁）、授权（你能做什么）、校验（输入是否合法）、限流与审计。安全不是末尾的补丁，而是贯穿每一层的检查点。

四者合起来即后端的**边界**：对外守契约，对内守规则，对下守数据，对全链路守安全。前后端分离让这四条线更易独立测试——改校验不碰存储，换数据库不改路由。

> **环境约定**：本书面向 Linux，本节示例在所有平台行为一致；若涉及文件路径，统一用 `pathlib.Path` 处理路径。

## 可运行示例：接收请求 → 返回 JSON 的最小编排

下面用单文件演示“接收请求 → 返回 JSON”的最小编排，复用教学包的 `TaskStore` 作为存储边界，用 `TestClient` 在本地验证，无需真实网络。中性 Task 领域，仅演示边界分层，不绑定具体业务产品。

```{code-cell} ipython3
import tempfile, pathlib
from typing import Annotated

from fastapi import FastAPI, Header, HTTPException, Depends
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field
from m2t.store import TaskStore

# --- 数据流转层：复用教学包的 TaskStore（持久化边界） ---
tmpdir = tempfile.TemporaryDirectory()
db_path = pathlib.Path(tmpdir.name) / "boundary.db"
store = TaskStore(db_path)

# --- 业务逻辑层：纯函数/类，不依赖 FastAPI ---
class TaskService:
    def __init__(self, store: TaskStore):
        self.store = store

    def create_task(self, task_id: str, filename: str) -> dict:
        # 业务规则：task_id 与 filename 必为非空；重复 id 视为冲突
        if not task_id.strip() or not filename.strip():
            raise ValueError("task_id and filename must be non-empty")
        if self.store.get(task_id) is not None:
            raise ValueError(f"task {task_id} already exists")
        self.store.create(task_id, filename, full_text="")
        row = self.store.get(task_id)
        assert row is not None
        return row

service = TaskService(store)

# --- API 契约层：Pydantic 定义输入/输出形状 ---
class CreateTaskIn(BaseModel):
    task_id: str = Field(min_length=1, description="任务 ID")
    filename: str = Field(min_length=1, description="原始文件名")

class CreateTaskOut(BaseModel):
    id: str
    filename: str
    status: str

# --- 安全防护层：极简 API Key 校验（演示边界，不做真实鉴权） ---
def verify_api_key(x_api_key: Annotated[str | None, Header()] = None):
    # 教学演示：若携带则必须为 demo-secret，否则放行（便于对比“有/无防护”的差异）
    if x_api_key is not None and x_api_key != "demo-secret":
        raise HTTPException(status_code=401, detail="invalid api key")
    return x_api_key

app = FastAPI(title="Task API")

@app.post("/api/tasks", response_model=CreateTaskOut, dependencies=[])
def create_task(payload: CreateTaskIn, api_key: str | None = Depends(verify_api_key)):
    try:
        row = service.create_task(payload.task_id, payload.filename)
    except ValueError as e:
        msg = str(e)
        if "already exists" in msg:
            raise HTTPException(status_code=409, detail=msg)
        raise HTTPException(status_code=422, detail=msg)
    return CreateTaskOut(id=row["id"], filename=row["filename"], status=row["status"])

@app.get("/api/tasks/{task_id}", response_model=CreateTaskOut)
def get_task(task_id: str):
    row = store.get(task_id)
    if row is None:
        raise HTTPException(status_code=404, detail="task not found")
    return CreateTaskOut(id=row["id"], filename=row["filename"], status=row["status"])

# --- 本地验证：用 TestClient 演示“契约 → 业务 → 持久化 → 防护”的分层效果 ---
# 接收请求 → 返回 JSON 的闭环在本地完成验证
client = TestClient(app)

# 1) 正常创建：接收 JSON 请求，返回 JSON 响应
r1 = client.post("/api/tasks", json={"task_id": "t1", "filename": "demo.wav"})
print("create t1:", r1.status_code, r1.json())
assert r1.status_code == 200
assert r1.json()["id"] == "t1"

# 2) 重复创建 → 409（业务层冲突转化为 HTTP 语义）
r2 = client.post("/api/tasks", json={"task_id": "t1", "filename": "demo.wav"})
print("duplicate:", r2.status_code, r2.json()["detail"])
assert r2.status_code == 409

# 3) 非法输入 → 422（Pydantic 契约层拦截，未进入业务层）
r3 = client.post("/api/tasks", json={"task_id": "", "filename": "x.wav"})
print("empty id:", r3.status_code)
assert r3.status_code == 422

# 4) 安全层：错误 api key → 401
r4 = client.post("/api/tasks", json={"task_id": "t2", "filename": "a.wav"}, headers={"x-api-key": "bad"})
print("bad key:", r4.status_code, r4.json()["detail"])
assert r4.status_code == 401

# 5) 正确 api key 放行
r5 = client.post("/api/tasks", json={"task_id": "t2", "filename": "a.wav"}, headers={"x-api-key": "demo-secret"})
print("good key:", r5.status_code, r5.json())
assert r5.status_code == 200

# 6) 查询：GET 返回 JSON
r6 = client.get("/api/tasks/t2")
print("get t2:", r6.json())
assert r6.json()["filename"] == "a.wav"

tmpdir.cleanup()
print("边界校验通过：契约/业务/持久化/防护各司其职，前后端通过 /api JSON 契约协作")
# 预期输出:
# create t1: 200 {'id': 't1', ...}
# duplicate: 409 task t1 already exists
# empty id: 422
# bad key: 401 invalid api key
# good key: 200 {'id': 't2', ...}
# get t2: {'id': 't2', ...}
# 边界校验通过：...
```
