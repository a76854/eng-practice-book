项目刚开始时，直接调用 `sqlite3.execute()` 往往最快。随着连接池、异步访问、复杂关系和跨数据库需求出现，团队可能逐步引入驱动层或 ORM。真正危险的不是选错一个工具，而是在没有理解它替你做了什么时，把抽象当成魔法。

## 所有访问都写在业务函数里：缺了什么

**1. SQL 与用户输入混在一起**

字符串拼接让输入有机会改变 SQL 结构，而不再只是一个值。

```python
cur.execute(f"SELECT * FROM tasks WHERE id = '{user_input}'")
```

**2. 连接和事务没有统一边界**

某个函数忘记提交，另一个函数异常后没有回滚，再有一个函数长期占着连接。错误看似随机，根因却是每段业务都在自行管理数据库生命周期。

```text
OperationalError: database is locked
```

**3. 抽象层级与问题规模不匹配**

简单的单表查询若套上复杂 ORM，理解生成 SQL 的成本可能高于手写 SQL；关联众多的领域模型若全靠字符串 SQL，又会把映射和重复查询散落到各处。

这些问题并非原生 SQL 或 ORM 单独造成，而是因为团队没有明确：**值如何绑定、事务在哪里结束、哪一层负责把数据库结果翻译成业务对象**。

### 从“会发 SQL”到“管理访问边界”

上述问题——注入、事务漂移、抽象错配——可以用一个统一原则处理：**始终分离 SQL 与值，并按实际复杂度选择刚好够用的访问层**。

## 三种访问层级：谁替你管理什么

| 境界 | 代表 | 抽象 | 适合场景 |
|------|------|------|----------|
| 原生 `sqlite3` | 标准库 `sqlite3` | 直接发 SQL，手写占位符 `?` | 教学、小工具、本地持久化（如 `m2t/store.py`） |
| 驱动层 `asyncpg` | PostgreSQL 异步驱动 | 仍写 SQL，但连接/协议/异步由驱动管 | 高并发后端，直连 PostgreSQL |
| ORM 层 `SQLAlchemy 2.0` | ORM + Core | 用 Python 对象/表达式描述查询，生成 SQL | 复杂模型、迁移、跨库可移植 |

`m2t/store.py` 选择原生 `sqlite3`，是因为它只有少量表和明确查询，保留可见 SQL 比引入对象映射更有教学价值。若服务改用 PostgreSQL 并需要异步连接池，`asyncpg` 才开始解决真实问题；若模型与关联继续增加，SQLAlchemy 的映射和会话管理才可能抵消其学习成本。

## 共同底线：参数化查询

```python
# 危险：字符串拼接，攻击者可注入 " OR 1=1 --
cur.execute(f"SELECT * FROM tasks WHERE id = '{user_input}'")

# 安全：占位符，驱动负责转义与类型处理
cur.execute("SELECT * FROM tasks WHERE id = ?", (user_input,))
```

参数化的核心不是“给引号做转义”，而是把 SQL 结构和值分开发给驱动，由驱动按类型绑定参数。占位符风格由驱动决定：`sqlite3` 常用 `?`，`asyncpg` 使用 `$1 / $2`，SQLAlchemy 可使用命名绑定或表达式对象；不要在不同驱动之间照搬占位符。

## 驱动层：保留 SQL，引入异步连接管理

## ORM 层：用对象与表达式描述持久化

`SQLAlchemy 2.0` 提供两层：`Core`（表达式语言，仍近 SQL）与 `ORM`（对象映射）。适合模型多、关联多、需迁移工具 `Alembic` 协同的项目。

```python
# 示意：SQLAlchemy 2.0 ORM（不在本书 .venv 中执行，仅示意）
# pip install sqlalchemy  # 生产环境按需安装，本书不强制
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column  # type: ignore
from sqlalchemy import String, Text, select  # type: ignore

class Base(DeclarativeBase):
    pass

class Task(Base):
    __tablename__ = "tasks"
    id: Mapped[str] = mapped_column(String, primary_key=True)
    filename: Mapped[str] = mapped_column(String, nullable=False)
    status: Mapped[str] = mapped_column(String, default="pending")
    full_text: Mapped[str] = mapped_column(Text, default="")

# 查询：用 Python 表达式生成 SQL
# stmt = select(Task).where(Task.status == "completed").order_by(Task.id)
# result = session.execute(stmt).scalars().all()

# 插入：对象即行
# task = Task(id="t1", filename="a.wav")
# session.add(task)
# session.commit()

# 注意：ORM 的 N+1、隐式加载、Session 生命周期是常见坑点，需显式 selectinload / joinedload 控制
```

> **何时选 ORM**：表多、关联多、需要声明式模型与迁移联动时；若查询以复杂聚合与窗口函数为主，`Core` 或原生 SQL 可能更直接。

## 可运行示例：原生 `sqlite3` 的正确姿势

示例（仅用标准库 `sqlite3`，演示参数化、事务与 `Row` 映射，无网络）：

```{code-cell} ipython3
import sqlite3

# 内存库用于演示参数化、事务与 Row 工厂；内存库不会真正进入 WAL 模式
conn = sqlite3.connect(":memory:")
conn.row_factory = sqlite3.Row
conn.execute("PRAGMA busy_timeout=5000")
conn.executescript("""
CREATE TABLE tasks (
    id TEXT PRIMARY KEY,
    filename TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'pending',
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    full_text TEXT DEFAULT ''
);
CREATE INDEX idx_tasks_created_at ON tasks(created_at DESC);
""")
conn.commit()

def create_task(task_id: str, filename: str, status: str = "pending") -> None:
    # 参数化：? 占位符，值与 SQL 分离，防注入
    with conn:
        conn.execute(
            "INSERT INTO tasks (id, filename, status) VALUES (?, ?, ?)",
            (task_id, filename, status),
        )

def get_task(task_id: str) -> dict | None:
    # Row -> dict：让调用方无需关心 DB 行对象细节（类似 ORM 的雏形）
    row = conn.execute("SELECT * FROM tasks WHERE id = ?", (task_id,)).fetchone()
    return dict(row) if row else None

def list_by_status(status: str, limit: int = 10) -> list[dict]:
    cur = conn.execute(
        "SELECT * FROM tasks WHERE status = ? ORDER BY created_at DESC LIMIT ?",
        (status, limit),
    )
    return [dict(r) for r in cur.fetchall()]

# 1) 写入与读取
create_task("t1", "meeting.wav", "completed")
create_task("t2", "demo.wav")
print("get t1:", get_task("t1"))

# 2) 参数化防注入演示：恶意输入被当作值而非 SQL
evil = "t1' OR '1'='1"
row = conn.execute("SELECT * FROM tasks WHERE id = ?", (evil,)).fetchone()
print("evil lookup:", row)  # None，说明未被注入
assert row is None

# 3) 事务：with conn: 块内自动 COMMIT，异常自动 ROLLBACK
try:
    with conn:
        conn.execute("INSERT INTO tasks (id, filename) VALUES (?, ?)", ("t3", "c.wav"))
        # 重复主键触发回滚，t3 不会残留
        conn.execute("INSERT INTO tasks (id, filename) VALUES (?, ?)", ("t1", "dup.wav"))
except sqlite3.IntegrityError as e:
    print("txn rolled back:", e)

print("after failed txn, t3 exists:", get_task("t3") is not None)
assert get_task("t3") is None

# 4) 批量操作：executemany
conn.executemany(
    "INSERT INTO tasks (id, filename, status) VALUES (?, ?, ?)",
    [("t3", "c.wav", "pending"), ("t4", "d.wav", "completed")],
)
conn.commit()
print("list completed:", [r["id"] for r in list_by_status("completed")])
assert len(list_by_status("completed")) == 2

# 5) 连接生命周期：Connection 上下文只管事务，不负责 close
# 用 contextlib.closing 显式关闭文件数据库连接
import tempfile, pathlib
from contextlib import closing
tmp = tempfile.TemporaryDirectory()
db_path = pathlib.Path(tmp.name) / "tier_demo.db"
with closing(sqlite3.connect(db_path)) as c:
    with c:  # 正常退出提交，异常退出回滚
        c.execute("CREATE TABLE kv (k TEXT PRIMARY KEY, v TEXT)")
        c.execute("INSERT INTO kv VALUES (?, ?)", ("hello", "world"))
with closing(sqlite3.connect(db_path)) as c:
    print("kv:", c.execute("SELECT v FROM kv WHERE k=?", ("hello",)).fetchone()[0])
tmp.cleanup()

conn.close()
print("三境界校验通过：原生 sqlite3 参数化/事务/批量均按预期")
# 预期输出:
# get t1: {'id': 't1', 'filename': 'meeting.wav', ...}
# evil lookup: None
# txn rolled back: UNIQUE constraint failed: tasks.id
# after failed txn, t3 exists: False
# list completed: ['t4', 't1'] 或按 created_at 排序的 2 条
# kv: world
# 三境界校验通过：原生 sqlite3 参数化/事务/批量均按预期
```

逐层回看：`sqlite3` 让 SQL、参数和事务边界完全可见；`asyncpg` 仍保留 SQL，但加入 PostgreSQL 协议、异步和连接池；SQLAlchemy 再把表、关系和查询表达成 Python 对象。层级上升意味着更多机制由工具接管，也意味着团队需要理解连接池、会话、延迟加载和生成 SQL。

回到旅行的比喻：自己查词典适合路线简单且希望完全掌控细节，专业翻译适合仍由你决定内容但需要更高效沟通，旅行团适合行程复杂且标准化程度高。选择数据库访问方式也一样：从最小工具开始，只有当新抽象明确消除了一类重复成本时，才让它进入默认技术栈。
