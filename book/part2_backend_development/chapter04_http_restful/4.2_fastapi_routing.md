# FastAPI 路由

学完本节，你能回答：

- 上一节的方法、状态码、资源三条准则，在 FastAPI 里分别由什么承载？
- 路径参数、查询参数、请求体三者在 HTTP 语义上的分工是什么？
- FastAPI 如何用类型标注自动完成校验，让校验失败统一以 422 暴露？
- Depends 依赖注入如何让分页与参数校验可复用？

> FastAPI 是一台把 HTTP 信封格式"印"进代码里的机器。你声明类型与约束，它自动完成校验、生成文档、返回正确的状态码，替你把上一节的那些规范扛在肩上。

上一节讲了三条准则：方法是动词，状态码是责任归属，资源是名词。这一节看它们在 FastAPI 里怎么落地。FastAPI 的做法是用 Python 类型标注声明契约，框架在边界自动校验、自动给状态码，让你专注于写清楚"这个接口要什么、回什么"。

## 三条准则在 FastAPI 里的落点

| 上一节的准则 | FastAPI 里的落点 | 例子 |
|---|---|---|
| 方法（动词） | 路由装饰器 | @app.get / @app.post / @app.put / @app.delete |
| 状态码 | status_code 参数 | 创建用 201，删除用 204 |
| 资源（名词） | 路径结构 | /tasks 表示集合，/tasks/{id} 表示单个 |

FastAPI 的路由装饰器天然把 HTTP 方法映射成 Python 函数，路径里写资源、方法上写动作、status_code 写责任归属，三条准则一次到位。

## 三类参数的分工

把 HTTP 请求比作一份快递单，三类参数各有分工：

| 参数类型 | HTTP 位置 | 语义 | 用法 |
|---|---|---|---|
| 路径参数 | URL 路径，如 /tasks/{id} | 资源的身份，必填且唯一 | 定位要操作的资源 |
| 查询参数 | URL 问号后，如 ?limit=20 | 资源的筛选、分页、排序 | 修饰集合 |
| 请求体参数 | Body | 创建或更新的完整载荷 | 承载业务数据 |

分工混了契约就模糊：把分页塞进 Body 无法被缓存与收藏，把资源 ID 放进 Query 则丢了可寻址性。FastAPI 用函数签名声明这三类参数：路径参数从路径提取，查询参数从问号后提取，请求体由 Pydantic 模型承载。

## 方法与状态码落地

下面这段代码用内存字典模拟存储，走完一个资源的创建、查询、替换、删除，每个环节都由 HTTP 方法与状态码表达语义。

```{code-cell} ipython3
from fastapi import FastAPI, HTTPException, Response, status
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field

class TaskIn(BaseModel):
    task_id: str = Field(min_length=1, max_length=64, description="任务 ID")
    filename: str = Field(min_length=1, description="文件名")

class TaskOut(BaseModel):
    id: str
    filename: str
    status: str

db: dict[str, str] = {}

app = FastAPI(title="HTTP and RESTful Demo")

@app.post("/tasks", response_model=TaskOut, status_code=status.HTTP_201_CREATED)
def create_task(payload: TaskIn, response: Response):
    if payload.task_id in db:
        raise HTTPException(status_code=409, detail=f"task {payload.task_id} already exists")
    db[payload.task_id] = payload.filename
    response.headers["Location"] = f"/tasks/{payload.task_id}"
    return TaskOut(id=payload.task_id, filename=payload.filename, status="pending")

@app.get("/tasks/{task_id}", response_model=TaskOut)
def get_task(task_id: str):
    if task_id not in db:
        raise HTTPException(status_code=404, detail="task not found")
    return TaskOut(id=task_id, filename=db[task_id], status="pending")

@app.put("/tasks/{task_id}", response_model=TaskOut)
def put_task(task_id: str, payload: TaskIn):
    db[task_id] = payload.filename
    return TaskOut(id=task_id, filename=payload.filename, status="pending")

@app.delete("/tasks/{task_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_task(task_id: str):
    db.pop(task_id, None)
    return Response(status_code=status.HTTP_204_NO_CONTENT)

client = TestClient(app)

r1 = client.post("/tasks", json={"task_id": "t1", "filename": "demo.wav"})
print("POST /tasks:", r1.status_code, r1.headers.get("location"))
assert r1.status_code == 201
assert r1.headers["location"] == "/tasks/t1"

r2 = client.post("/tasks", json={"task_id": "t1", "filename": "dup.wav"})
print("POST duplicate:", r2.status_code)
assert r2.status_code == 409

r3 = client.get("/tasks/t1")
print("GET /tasks/t1:", r3.status_code, r3.json()["filename"])
assert r3.status_code == 200

r4 = client.put("/tasks/t1", json={"task_id": "t1", "filename": "v2.wav"})
r5 = client.put("/tasks/t1", json={"task_id": "t1", "filename": "v2.wav"})
print("PUT twice:", r4.json()["filename"], r5.json()["filename"])
assert r4.json()["filename"] == "v2.wav"
assert r5.json()["filename"] == "v2.wav"

r6 = client.delete("/tasks/t1")
r7 = client.delete("/tasks/t1")
print("DELETE twice:", r6.status_code, r7.status_code)
assert r6.status_code == 204
assert r7.status_code == 204

r8 = client.get("/tasks/t1")
print("GET after delete:", r8.status_code)
assert r8.status_code == 404
```

观测要点：创建返回 201 并带上 Location，重复创建返回 409 而非覆盖，PUT 与 DELETE 连续执行两次结果一致，删除后再查返回 404。上一节的"方法、状态码、幂等"在这里变成了一段可直接运行、可直接断言的代码。

## 三类参数与校验：声明约束而非手写判断

第二段代码演示路径参数、查询参数、请求体三类参数如何分工，以及 Pydantic 如何在请求进入业务之前就拦住非法输入。

```{code-cell} ipython3
from typing import Annotated
from fastapi import FastAPI, HTTPException, Query, Path, Depends
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field

class TaskIn(BaseModel):
    task_id: str = Field(min_length=1, max_length=64, description="任务 ID")
    filename: str = Field(min_length=1, description="文件名")
    priority: int = Field(default=0, ge=0, le=10, description="优先级 0-10")

class Pagination(BaseModel):
    limit: int = Field(default=20, ge=1, le=100)
    offset: int = Field(default=0, ge=0)

def paginate(
    limit: Annotated[int, Query(ge=1, le=100, description="每页数量")] = 20,
    offset: Annotated[int, Query(ge=0, description="偏移量")] = 0,
) -> Pagination:
    return Pagination(limit=limit, offset=offset)

db: dict[str, dict] = {}
app = FastAPI(title="Parameter Demo")

@app.post("/tasks", status_code=201)
def create(payload: TaskIn):
    db[payload.task_id] = {"filename": payload.filename, "priority": payload.priority}
    return db[payload.task_id]

@app.get("/tasks/{task_id}")
def get_one(task_id: Annotated[str, Path(min_length=1, description="任务 ID")]):
    if task_id not in db:
        raise HTTPException(status_code=404, detail="not found")
    return db[task_id]

@app.get("/tasks")
def list_tasks(p: Annotated[Pagination, Depends(paginate)]):
    items = list(db.values())
    return items[p.offset : p.offset + p.limit]

client = TestClient(app)

r1 = client.post("/tasks", json={"task_id": "a1", "filename": "x.wav", "priority": 5})
print("create a1:", r1.status_code, r1.json())
assert r1.status_code == 201

r2 = client.post("/tasks", json={"task_id": "a2", "filename": "x.wav", "priority": 99})
print("priority overflow:", r2.status_code)
assert r2.status_code == 422

r3 = client.post("/tasks", json={"task_id": "", "filename": "x.wav"})
print("empty id:", r3.status_code)
assert r3.status_code == 422

r4 = client.get("/tasks/a1")
print("get a1:", r4.json())
assert r4.status_code == 200

for i in range(5):
    client.post("/tasks", json={"task_id": f"b{i}", "filename": f"f{i}.wav", "priority": 1})

r5 = client.get("/tasks?limit=2&offset=1")
print("paginated:", len(r5.json()))
assert len(r5.json()) == 2

r6 = client.get("/tasks?limit=999")
print("limit overflow:", r6.status_code)
assert r6.status_code == 422
```

观测要点：路径参数来自 URL，查询参数来自问号后，请求体由 Pydantic 承载。优先级超限、空 ID、分页超限都在进入业务之前被 422 拦截，路由代码里没有一句手写的 if 判断。

## 本节小结

- 方法对应装饰器、状态码对应 status_code、资源对应路径，上一节的三条准则在 FastAPI 里各有明确落点。
- 路径参数定位资源、查询参数修饰集合、请求体承载载荷，三者分工写在函数签名里。
- 类型标注加 Field 约束让校验在边界自动发生，以 422 暴露，路由里不写手工判断。
- Depends 让分页等可复用逻辑从路由中抽离，保持路由薄而可测。

> 声明契约，而不是手写防线，框架自会在边界替你站岗。
