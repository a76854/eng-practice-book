# RESTful 成熟度模型

> 学完本节，你能回答：为什么“把所有操作都 POST 到 `/api/action`”难以演进？Richardson 的四个阶梯各自解决了什么问题、又引入了什么代价？MeetingToText 的 API 处在哪一级，是否有必要再往上走？

## 从 RPC 到 REST：不是“风格”，而是“约束的叠加”

把后端 API 设计比作快递单的写法演进：最初只写“寄件”二字（一个入口处理所有事），接着按物品分类写“文件 / 包裹”（资源初现），再按动作细分“寄 / 查 / 退”（HTTP 动词），最后在单子上印“下一步可做什么”的指引（Hypermedia）。每一级都让协作更自描述，但也增加设计与实现成本。

Leonard Richardson 的成熟度模型（Richardson Maturity Model, RMM）把这一演进切为四级：

| 级别 | 名称 | 核心约束 | MeetingToText 对照 |
|------|------|----------|---------------------|
| Level 0 | POX（Plain Old XML/JSON） | 单一入口 + 单一方法（多为 POST） | `POST /api/action {op: "createTask"}`（反面教材） |
| Level 1 | 资源 | 按资源拆分 URL | `POST /tasks` / `POST /transcribe` / `POST /export`（已满足） |
| Level 2 | HTTP 动词 + 状态码 | 用方法与状态码表达语义 | `GET /tasks/{id}` `DELETE /tasks/{id}` `201 / 404 / 409`（本书推荐的实践水位） |
| Level 3 | Hypermedia（HATEOAS） | 响应中携带下一步可执行的链接/动作 | `{"id":"t1","links":{"self":"/tasks/t1","transcribe":"/tasks/t1/transcribe"}}`（按需选用） |

> **中立性说明**：Level 3 并非“更高级就更好”。Hypermedia 在需要“客户端自发现、可演进”的开放 API（如支付、云资源编排）中价值显著，但在前后端紧密协作、由 OpenAPI 契约驱动的 MeetingToText 中，Level 2 已能覆盖绝大多数需求，强行引入 Hypermedia 会增加前端解析成本与文档复杂度。

## 四级的代价与收益

- **Level 0 → 1**：收益是“资源可寻址”，代价是需梳理领域名词（Task / Transcript / Export），避免动词堆砌。
- **Level 1 → 2**：收益是“语义可被基础设施理解”——缓存对 `GET` 生效、重试对 `PUT/DELETE` 安全、网关可按状态码限流；代价是团队需统一状态码与幂等约定。
- **Level 2 → 3**：收益是“可演进性与自描述”，客户端无需硬编码 URL，通过 `links` 发现能力；代价是前后端均需理解并消费 Hypermedia，调试与测试成本上升，且在强契约（OpenAPI + 代码生成）的闭环中边际收益递减。

本书与 MeetingToText 选择 **Level 2 为默认水位**，Hypermedia 仅在“需向第三方暴露可发现 API”时按需引入。这一判断的依据是**协作模式**：前后端同团队、由 `openapi.json` 生成类型与客户端时，URL 的“可发现性”已由契约生成器解决，无需再在运行时通过 `links` 发现。

## URL 风格对照：同一业务的四种写法

以“创建任务、查询任务、触发转写、导出纪要”为例，同一业务在四级下的 URL 风格差异直观可见（路径与方法对照）：

- **Level 0**：`POST /api` + `{"action":"createTask","filename":"a.wav"}` / `{"action":"getTask","id":"t1"}` —— 所有操作挤在单一端点，靠 Body 区分。
- **Level 1**：`POST /tasks` / `GET /tasks/t1` / `POST /tasks/t1/transcribe` / `POST /tasks/t1/export` —— 资源出现，但方法与状态码仍可能混用（如全用 `200`）。
- **Level 2**：`POST /tasks → 201 + Location` / `GET /tasks/{id} → 200/404` / `POST /tasks/{id}/transcribe → 202 Accepted` / `DELETE /tasks/{id} → 204` —— 方法与状态码各自归位。
- **Level 3**：在 Level 2 响应体中追加 `links` / `actions`，客户端据此决定下一步可做什么，而非硬编码 URL 模板。

> **环境约定**：本书面向 Linux，URL 设计与平台无关；若涉及文件路径（如导出文件的本地落盘），统一用 `pathlib.Path` 处理路径。

## 可运行示例：同一业务的成熟度对照（TestClient 本地验证）

文件 `book/part2_backend_development/chapter04_http_restful/demo_maturity.py`（对照 Level 0/1/2 的路由风格，无网络）：

```{code-cell} ipython3
import tempfile, pathlib
from fastapi import FastAPI, HTTPException, Response, status
from fastapi.testclient import TestClient
from pydantic import BaseModel, Field
from m2t.store import TaskStore

tmpdir = tempfile.TemporaryDirectory()
db_path = pathlib.Path(tmpdir.name) / "maturity.db"
store = TaskStore(db_path)

class TaskCreateIn(BaseModel):
    task_id: str = Field(min_length=1)
    filename: str = Field(min_length=1)

# --- Level 0：单一入口，靠 Body 的 action 区分（反面教材，仅作对照） ---
app_l0 = FastAPI(title="Level 0 - RPC")
class RpcIn(BaseModel):
    action: str
    task_id: str | None = None
    filename: str | None = None

@app_l0.post("/api")
def rpc_dispatch(payload: RpcIn):
    if payload.action == "createTask":
        if not payload.task_id or not payload.filename:
            raise HTTPException(status_code=400, detail="missing fields")
        if store.get(payload.task_id) is not None:
            raise HTTPException(status_code=409, detail="already exists")
        store.create(payload.task_id, payload.filename)
        return {"ok": True, "id": payload.task_id}
    elif payload.action == "getTask":
        if not payload.task_id:
            raise HTTPException(status_code=400, detail="missing task_id")
        row = store.get(payload.task_id)
        if row is None:
            raise HTTPException(status_code=404, detail="not found")
        return {"ok": True, "task": row}
    else:
        raise HTTPException(status_code=400, detail=f"unknown action {payload.action}")

# --- Level 1：按资源拆分 URL，但状态码与方法仍可更精细 ---
app_l1 = FastAPI(title="Level 1 - Resources")
@app_l1.post("/tasks")
def l1_create(payload: TaskCreateIn):
    if store.get(payload.task_id) is not None:
        raise HTTPException(status_code=400, detail="already exists")  # 仍用 400，语义可更精确
    store.create(payload.task_id, payload.filename)
    return {"id": payload.task_id, "status": "pending"}

@app_l1.post("/tasks/{task_id}/transcribe")
def l1_transcribe(task_id: str):
    # 演示“资源 + 动作”风格：资源已拆分，但状态码未区分 201/202/204
    if store.get(task_id) is None:
        raise HTTPException(status_code=404, detail="not found")
    return {"id": task_id, "transcribed": True}

# --- Level 2：资源 + HTTP 动词 + 状态码（本书推荐水位） ---
app_l2 = FastAPI(title="Level 2 - HTTP Verbs + Status Codes")
class TaskOut(BaseModel):
    id: str
    filename: str
    status: str

@app_l2.post("/tasks", response_model=TaskOut, status_code=status.HTTP_201_CREATED)
def l2_create(payload: TaskCreateIn, response: Response):
    if store.get(payload.task_id) is not None:
        raise HTTPException(status_code=409, detail="already exists")
    store.create(payload.task_id, payload.filename)
    row = store.get(payload.task_id)
    assert row is not None
    response.headers["Location"] = f"/tasks/{payload.task_id}"
    return TaskOut(id=row["id"], filename=row["filename"], status=row["status"])

@app_l2.get("/tasks/{task_id}", response_model=TaskOut)
def l2_get(task_id: str):
    row = store.get(task_id)
    if row is None:
        raise HTTPException(status_code=404, detail="not found")
    return TaskOut(id=row["id"], filename=row["filename"], status=row["status"])

@app_l2.delete("/tasks/{task_id}", status_code=status.HTTP_204_NO_CONTENT)
def l2_delete(task_id: str):
    row = store.get(task_id)
    if row is None:
        return Response(status_code=status.HTTP_204_NO_CONTENT)
    store.delete(task_id)
    return Response(status_code=status.HTTP_204_NO_CONTENT)

# Level 3 演示：Level 2 的 GET 响应中追加 links（可选，不强制）
@app_l2.get("/tasks/{task_id}/hyper", response_model=dict)
def l2_hyper(task_id: str):
    row = store.get(task_id)
    if row is None:
        raise HTTPException(status_code=404, detail="not found")
    return {
        "id": row["id"],
        "filename": row["filename"],
        "status": row["status"],
        "links": {
            "self": f"/tasks/{task_id}",
            "transcribe": f"/tasks/{task_id}/transcribe",
            "export": f"/tasks/{task_id}/export",
        },
    }

# --- 本地验证：对照三级的 URL 风格与语义差异 ---
# 清理后重新建库，保证各组测试隔离
import os
# 用新库演示 Level 0 vs Level 2 的对照
c0 = TestClient(app_l0)
r0 = c0.post("/api", json={"action": "createTask", "task_id": "m0", "filename": "a.wav"})
print("L0 create:", r0.status_code, r0.json())
assert r0.status_code == 200  # Level 0 往往全返回 200，语义靠 Body 判断
r0b = c0.post("/api", json={"action": "getTask", "task_id": "m0"})
print("L0 get:", r0b.json()["task"]["id"])
assert r0b.json()["task"]["id"] == "m0"
r0c = c0.post("/api", json={"action": "unknownAction"})
print("L0 unknown:", r0c.status_code)
assert r0c.status_code == 400

c1 = TestClient(app_l1)
r1 = c1.post("/tasks", json={"task_id": "m1", "filename": "b.wav"})
print("L1 create:", r1.status_code, r1.json())
assert r1.status_code == 200
r1b = c1.post("/tasks/m1/transcribe")
print("L1 transcribe:", r1b.json())
assert r1b.json()["transcribed"] is True

c2 = TestClient(app_l2)
r2 = c2.post("/tasks", json={"task_id": "m2", "filename": "c.wav"})
print("L2 create:", r2.status_code, r2.headers.get("location"))
assert r2.status_code == 201
assert r2.headers["location"] == "/tasks/m2"
r2b = c2.get("/tasks/m2")
print("L2 get:", r2b.json())
assert r2b.json()["id"] == "m2"
r2c = c2.get("/tasks/m2/hyper")
print("L3 hyper links:", r2c.json()["links"])
assert "self" in r2c.json()["links"]
# Level 2 的冲突语义更精确：409 而非 400
r2d = c2.post("/tasks", json={"task_id": "m2", "filename": "c.wav"})
print("L2 duplicate:", r2d.status_code)
assert r2d.status_code == 409
# DELETE 幂等：204
r2e = c2.delete("/tasks/m2")
print("L2 delete:", r2e.status_code)
assert r2e.status_code == 204

tmpdir.cleanup()
print("成熟度对照校验通过：Level 0→1→2→3 的语义与代价可见")
# 预期输出:
# L0 create: 200 {'ok': True, ...}
# L0 get: m0
# L0 unknown: 400
# L1 create: 200 {'id': 'm1', ...}
# L1 transcribe: {'id': 'm1', ...}
# L2 create: 201 /tasks/m2
# L2 get: {'id': 'm2', ...}
# L3 hyper links: {'self': ...}
# L2 duplicate: 409
# L2 delete: 204
# 成熟度对照校验通过：Level 0→1→2→3 的语义与代价可见
```
