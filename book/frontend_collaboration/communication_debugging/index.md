# 前后端通信与联调

> **本章学习目标**
> - 能够说清一次 HTTP 请求从浏览器发出、到后端返回的完整链路，以及前后端各自在链路上的职责
> - 能够用 `fetch` 与 `axios` 发出请求，并说清 axios 相对 fetch 多做了什么、选型依据是什么
> - 能够用 `loading` / `error` / `data` 三元组管理异步状态，并说清"竞态请求覆盖"的来源与规避
> - 能够用 OpenAPI、统一信封与字段命名约定把前后端契约落地，并说清契约演进的向后兼容做法
> - 能够解释 CORS 的同源策略原理，并用后端配置或开发期代理解决本地联调的跨域问题
> - 能够按"请求发出去了吗、状态码对吗、响应形状对吗、渲染对吗"四步定位联调问题，并用浏览器 Network 面板取证
> - 能够以后端视角读懂一次联调链路：请求头、状态码、响应体、渲染结果，完成跨端问题定位

> **为什么需要掌握本章**
> 前端能画页面了，后端能开接口了，但"连上"才是真正的交付。联调，是前后端第一次真正"对话"的地方：前端说"我按契约发了请求，你回的形状怎么不对"，后端说"我这边日志 200 了，你那边怎么没渲染"。这一章讲的就是怎么把这两端缝起来：请求怎么发、结果怎么等、契约怎么对齐、跨域怎么破、出错了怎么定位。学会了，"联调翻车"就从玄学变成了按图索骥的排查。

> **预计理论学时**：3学时

本章以文档查询应用前后端打通为贯穿例子：前端搜索框输入关键词 `GET /api/search?q=...`，后端返回文档列表，前端渲染。动手练习交给实验指导书。章内结构如下：
