# Vue3 机制与状态

**本章学习目标**
> - 能够说清 Vue 3 的核心特性（单文件组件、声明式渲染、响应式、组件化）与组合式 API 的组织方式，以及为什么需要 Vite 构建
> - 能够用插值、`v-bind`、`v-on`、`v-if`、`v-for`、`v-model` 读懂模板如何把数据接到界面，并说清 `v-model` 的双向绑定本质
> - 能够用 `ref`、`computed`、`watch` 说清"数据变了，视图为什么自动变"，并在三者之间选对用法
> - 能够用 Props 向下、Emits 向上刻画组件间通信，并在组件挂载时（`onMounted`）拉取后端数据
> - 能够用路由表、登录守卫与懒加载三件事，理解前端多页面应用的页面切换与鉴权
> - 能够用 Pinia 的 State、Getter、Action 三层模型，说清跨组件共享状态归谁管、怎么变
> - 能够以后端视角读懂 Vue 组件的源码、路由配置与状态目录，完成前后端联调定位
> - 能够用 Vitest 与 `@vue/test-utils` 测组件的渲染输出与交互事件，理解组件测试与后端接口测试的同一套思路

> **为什么需要掌握本章**
> 前端概况一章回答了前端从哪来、框架怎么选、工程怎么搭，那些是前端的版图。可版图之外，真正能协作交付的，是能读懂前端那几行最核心的代码。站在后端视角，Vue 3 有五个必懂的概念，恰好都能对应到你熟悉的东西：模板是"数据到界面的取值规则"，响应式是前端的"发布订阅"，组件是"带契约的函数"，路由是"路径到处理器的映射"，状态库是"单例服务"。读懂这五样，联调时那句"数据明明返回了为何视图不动""父子组件到底谁改状态""刷新后为何回到首页"才有处可查。本章把每一块都讲到"够用"为止，不往深处钻。

> **预计理论学时**：3学时

本章讲 Vue 的语法与机制，不依赖可运行环境：代码一律以围栏展示，动手练习交给实验指导书。章内结构如下：

- [Vue 3 与 Vite](why_vue3_vite.md) —— 认识 Vue 3 的核心特性与组合式 API，以及为什么需要 Vite

- [数据如何驱动视图](reactivity_principles.md) —— `ref`、`computed`、`watch` 如何让数据变化自动反映到界面
- [把界面拆成组件](component_design.md) —— Props 向下、Emits 向上，以及挂载时拉取数据
- [多页面与登录守卫](routing_management.md) —— 路由表、登录守卫与懒加载三件事
- [跨组件共享的状态](cross_component_state_pinia.md) —— State、Getter、Action 三层与后端状态的边界
- [组件测试](component_testing.md) —— Vitest 与 `@vue/test-utils` 测渲染与交互，替代手动点页面
